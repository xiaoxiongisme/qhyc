# V2 样本外崩塌排查（2026-11-01）

> 关联：[离场规则候选_SL1_TR6_验证门控.md](./离场规则候选_SL1_TR6_验证门控.md) 第 6.1 节。
> 排查脚本：`scripts/investigate_v2_oos.py`（core / --cmp src / --cmp reest）。

## 1. 问题

生产 walk-forward 基线（`FusionConfig` 默认 `SL2.0/TR2.0/BE0.5`，`walkforward.py`
`train_days=720 / test_days=60 / step_days=60 / reestimate=False`）在 28 窗 × 50 品种上：

| 指标 | 基线 |
|---|---:|
| IS 净（点） | +32,709.8 |
| **OOS 净（点）** | **−330,406.2** |
| **decay = OOS/IS** | **−10.1011** |

即「样本内盈利、样本外崩塌」。需要定位：**是设定 / 数据问题，还是策略真失效？**

> ⚠ **口径澄清（重要）**：上表是 `validate_exit_candidate.py` 的 28 窗基线（区间不含早期 2015–2019 的 IS 巨负窗口）。本次排查 `core` 取 akshare 全量区间
> （2015-01-05~2026-10-31）复现，得到 **59 窗**，IS 净因此转为 **−682,571.7**（详见 §5.1）。
> 两次**方向一致（都亏）**，但量级/窗口数不同，**不能把 28 窗的 IS=+32,709 当作「样本内盈利」的可靠结论**——
> 那是窗口截断造成的假象。真正的全量形态是「样本内也系统性亏损」。

## 2. 核心矛盾（为何怀疑「设定问题」）

此前**分析工作区**（`E:/抖音分析/.../analysis/`）用另一套数据管线得到的是**正 OOS**：

- `v2_final.json`：OOS meanR **+0.2344%**、27,316 笔、12/12 年为正、59 品种全正。
- `tb_grid_results.json`：同口径全量网格（59 品种）。

而**生产引擎**（`fusion_backtest.py` + `walkforward.py`，回测固定 `src=bar_60m`）
在同一策略上得到**负 OOS**。两套结论直接矛盾。

⚠ 关键时间线：生产回测数据源在 **2026-10-31** 才从 `hourly_bar(src=akshare)`
改为 `l1_mkt.bar_60m`（见 `fusion_backtest.py` 第 90–94 行注释），时间正好卡在本轮分析窗口。
旧的 `hourly_bar(akshare)` 历史段被 `agg_1m` 主键占位导致覆盖空洞；新的 `bar_60m`
虽规范化，但其历史覆盖与合约映射尚未被独立验证。**本次 `--cmp src` 已证明两主连源都崩
（详见 §5.2），故「V2 失效」并非「某一源空洞」所致**；但两源都经过同一套**主连拼接 / 复权**
逻辑，而分析工作区用**真实合约**（绕过主连）反而盈利，因此根因更可能是主连复权系统性偏差，
而非策略本身。该判断已于 **§7 用「真实合约回测路径」做决定性验证，结果推翻 H4**——
去掉复权后 SN 反而更亏，且同一下调序列「日线盈利 / 60m 崩塌」，崩塌根因在 60m 粒度而非复权。

## 3. 假设

| 假设 | 内容 | 判别信号 |
|---|---|---|
| H1 数据源人为衰减（设定问题） | `bar_60m` 历史覆盖 / 合约映射有缺陷，引入假亏损 | `--cmp src` 中仅 `bar_60m` 崩、`hourly_bar` 不崩 |
| H2 参数衰减（设定问题） | 固定参数在后期行情失效 | `--cmp reest` 中逐窗重估可救回 OOS |
| H3 策略真失效 | 边本身不存在或被结构性破坏 | 两对照都不救、且崩塌广泛（多品种 / 多窗） |
| H4 个别品种数据问题 | 少数品种贡献大部分 OOS 亏损 | core 逐品种高度集中（最亏 5 品种占比高） |
| H5 成本口径（已排除） | 真实费率只影响绝对量级，IS/OOS 同口径施加，不可能造成 IS/OOS 不对称 | —— 不单列对照 |

## 4. 方法论

脚本 `scripts/investigate_v2_oos.py` 复用 `run_walk_forward` / `fusion_params_from_config`，三类诊断：

1. **core（默认）**：单遍基线 WF → 逐窗表（test 区间 / n_oos / IS / OOS / decay）+ 逐品种
   OOS 表（最亏在前）+ 集中度（最亏 5 品种占比、OOS<0 窗占比、OOS<0 品种数）。
2. **--cmp src**：`src=bar_60m` vs `src=hourly_bar(akshare)` 整体 OOS 净 / decay 对照。
3. **--cmp reest**：`reestimate=False` vs `True`（重估网格 `[{}, {sl_atr:1.5}, {sl_atr:2.5}]`）
   整体 OOS 净 / decay 对照。

运行（在能连 DB 的 qhyc 容器）：
```bash
docker exec -d qhyc-api sh -c "cd /app && python3 -u scripts/investigate_v2_oos.py \
  --out /tmp/oos_core.json > /tmp/oos_core.log 2>&1; echo EXIT=\$? >> /tmp/oos_core.log"
docker exec -d qhyc-api sh -c "cd /app && python3 -u scripts/investigate_v2_oos.py \
  --cmp src --max-symbols 25 --out /tmp/oos_src.json >> /tmp/oos_src.log 2>&1"
docker exec -d qhyc-api sh -c "cd /app && python3 -u scripts/investigate_v2_oos.py \
  --cmp reest --max-symbols 15 --out /tmp/oos_reest.json >> /tmp/oos_reest.log 2>&1"
```

### 5.2 --cmp src —— 数据源敏感性　25 品种（main_contracts 前 25，恰为亏损集中段），2015-01-05~2026-10-31

| 源 | OOS 净（点） | IS 净（点） | decay | 窗数 |
|---|---:|---:|---:|---:|
| bar_60m | −562,169.4 | −3,863,673.3 | 0.1455 | 58 |
| akshare | −503,036.4 | −2,790,084.1 | 0.1803 | 59 |

- **两源都崩**，且 bar_60m 反而略糟（OOS/IS 都更负）→ **H1（仅某一源人为衰减）被否定**。
- 两源都经过同一套**主连拼接 / 复权**逻辑；而分析工作区用**真实合约**绕过主连反而盈利 → 根因更可能是**主连复权系统性偏差**，而非「某源数据空洞」。
- 注：25 品种口径（取 main_contracts 前 25，恰为 SN/NI/CU… 等亏损集中品种）使量级比 core 全 50 品种更负，仅用于**同源对照**，不与 §5.1 绝对值直接比。

### 5.3 --cmp reest —— 参数重估敏感性　**2026-11-01 已跑（全 50 品种，bar_60m，58 窗）**

| 模式 | OOS 净（点） | IS 净（点） | decay | 窗数 |
|---|---:|---:|---:|---:|
| reestimate=False（生产基线） | **−562,169.4** | −3,863,673.3 | 0.1455 | 58 |
| reestimate=True（网格 `[{}, {sl_atr:1.5}, {sl_atr:2.5}]`） | **−613,717.6** | −3,078,964.1 | 0.1993 | 58 |

- **逐窗重估（reestimate=True）没有救回 OOS，反而略差**（−562k → −614k）；decay 仍远低于 0.5 及格线
  （0.15 → 0.20）。reestimate 只扰动 `sl_atr`，无法改变「边本身弱于成本」的结构。
- 两模式 IS 均为**巨负（−300万~−386万）**，即样本内就已系统性亏损——不是"固定参数在后期漂移"，
  而是策略在所有训练窗都亏。
- **结论：H2（参数衰减 → 逐窗重估可救）被否定。** 崩塌不是"重估一下参数就能修复"的设定问题。
- 注：此结果取代了 §6.3 原"暂缓未跑"的判断；原暂缓理由（IS 巨负→重估无用）方向正确，本次实测坐实。
  此前 `--cmp reest` 因 `run_walk_forward` 内部 `_data_range` 只认 `HourlyBar`、不认 `bar_60m`
  （`start=None` 取不到区间返回全 0），已修复为显式传 `bar_60m` 区间（见 `investigate_v2_oos.py`）。

## 6. 结论与下一步

### 6.1 假设判定

| 假设 | 判定 | 依据 |
|---|---|---|
| H1 单一数据源人为衰减 | ❌ **否定** | §5.2：bar_60m 与 akshare 两主连源**都崩** |
| H2 参数衰减 / 粒度错配 | ✅ **升级为主因候选** | §7：同一下调序列在**日线盈利/持平、60m 崩塌**，差异仅在粒度→60m 参数化失效，非数据 |
| H3 策略真失效（60m 层面） | ✅ **成立**（推翻 H4 后成为主因） | §7：真实合约日线不救 SN/NI；同一下调序列日线≈持平 vs 60m 崩塌 |
| **H4 主连复权 bug 导致崩塌** | ❌ **否定（关键反转）** | §7：去掉复权（真实合约日线 B）后 SN 反而**多亏 52.7 万**；同一下调序列日线盈利→复权不是亏损源 |
| H5 成本口径 | ✅ 已排除 | 成本 IS/OOS 同口径施加，不造成不对称 |

### 6.2 当前最可信的判断（2026-11-01 决定性验证后**反转**）

> ⚠ **结论反转**：原先「高度疑似主连复权偏差（H4）」的判定被 **§7 决定性验证推翻**。
> 证据方向是反的——**去掉复权（真实合约）后 SN 反而亏得更多**，且**同一下调序列在日线≈持平/盈利、
> 在 60m 崩塌**，说明崩塌的差异来自**粒度 / 60m 参数化**，而非数据源 / 复权。

**崩塌是「策略在 60m 粒度的真失效（含参数/粒度错配，H2/H3）」，不是「主连复权设定问题（H4）」。**
三条决定性证据（详见 §7）：

1. **SN/NI（占 OOS 亏损 ~78%）在真实合约日线下并未转盈，反而更差**：SN 主连复权 A=+377,220 元（盈利）
   vs 真实合约 B=−150,315 元（亏损），**Δ(B−A)=−527,536 元**。若 H4（复权制造亏损）成立，去掉复权应救回 SN；
   实测相反。NI 两口径接近（A +46,918 / B +35,883），亦无拯救。
2. **同一下调序列，日线 vs 60m 天壤之别**：bar_60m 经重采样到日线后，SN/NI 子集 walk-forward OOS=**+430,926 元（盈利）**，
   而原 60m 同序列生产回测 OOS=**−330,406 元（崩塌）**（§1）。二者价格来源完全相同，**唯一差异是 bar 粒度**
   （60m 的 `ema_k=140`≈6 天 vs 日线的 140 天）——故崩塌的不同iator 是粒度/参数化，不是复权。
3. **复权本身是必要的、且有益的**：probe 实测 bar_60m 在每次换月处相对真实主力合约价呈数千~上万点的
   **阶梯（累计 cum_offset 已把换月跳空抹平）**；若复权缺失（B=裸拼接），序列在换月处出现真实跳空，
   反而引入虚假信号/止损。B 在全量 50 品种日线 WF OOS=−223,969，劣于 A 的 ≈−1,452（持平）。
   即「复权」不仅不是亏损因，反而是让序列可用的前提。

> 补充：原先支撑 H4 的「分析工作区用真实合约反而盈利」属于**非同口径对照**（不同策略 / 不同粒度 /
> 不同管线），不能作为「主连复权有 bug」的证据；§7 的 A vs B 才是同策略同粒度的决定性对照。

### 6.3 下一步（按优先级，**已据 §7 重排**）

1. **H4（修主连复权数据）正式下撤**：不要再投入时间去「修复 SN/NI 的 cum_offset」并期待 V2 转盈——
   决定性验证已证明复权不是亏损源。
2. **转向 60m 策略/参数层（H2/H3）**：核心矛盾是「同一下调序列日线能盈利、60m 崩塌」。
   直接抓手：`ema_k=140` 在 60m 仅≈6 天（趋势门控过短、信号过密），应优先在 60m 重估趋势/入场
   参数（或确认 V2 的边本质是**日线尺度**现象）。可补跑 `--cmp reest`（`reestimate=True`）看 60m 逐窗
   重估能否救回 OOS。
3. **离场候选 `SL1.0/TR6.0` 维持不晋升**（与关联文档一致）——崩塌根因在上游的策略/粒度层，
   离场参数之争是次要矛盾。
4. **（可选，非必需）proper 真实合约回测**：若仍想彻底排除复权，需做「逐具体合约交易、换月平仓
   并实现价差为真实成本」的多合约回测；但鉴于 §7 的日线 vs 60m 独立论证已决定性，此项可暂缓。

## 7. 决定性验证：真实合约回测路径（推翻 H4）　2026-11-01

> 脚本：`scripts/verify_real_contract_oos.py`（研究分支 `cb/v2-oos-investigation`，未碰 `main`/`cb/dev`）。
> 思路：用**同一套**信号层 `_generate_states` + 组合层 `_simulate_trades`、同一 walk-forward 窗口
> （720/60/60），**只替换输入日线价格序列**，隔离单一变量「数据源 / 主连复权」：
> - **A（主连复权·对照）** = `l1_mkt.bar_60m`(SN888…) 重采样**日线**——生产回测真用的序列，携带累计复权。
> - **B（真实合约·实验）** = `public.contract_daily` 经 `public.main_contract_map` 逐日取「当日主力真实合约」
>   日线 OHLC 拼接（**绕过 cum_offset**，裸拼接，换月处有真实跳空）。

**关键数据约束（probe 实测）**：生产容器 DB **没有** `fut_kline`（真实合约 60m），只有 `contract_daily`
（真实合约**日线**，SN 起 2021-01-18）。故本验证只能在**日线粒度、2021+**进行；60m 真实合约直测不可行。

**判定标准（用户原话）**：真实合约下 SN/NI 若转盈 → 实锤复权 bug；仍亏 → 指向策略真失效。

### 7.1 SN/NI 结果（2021-01-01~2026-12-31，金额元，全量单跑）

| 品种 | A 主连复权 | B 真实合约 | Δ(B−A) | A_wf OOS | B_wf OOS |
|---|---:|---:|---:|---:|---:|
| SN888 | **+377,220**（胜 38.5%） | **−150,315**（胜 28.4%） | **−527,536** | −51,661 | −159,367 |
| NI888 | +46,918（胜 35.3%） | +35,883（胜 34.4%） | −11,036 | −54,267 | −20,258 |

→ **SN 在真实合约下不仅没转盈，反而多亏 52.7 万**。H4 的判别信号（"去掉复权→救回"）**反向成立**，H4 否定。

### 7.2 全量 50 品种（同窗 2021+，日线 WF 720/60/60）

| 口径 | 窗数 | OOS 净 | IS 净 | decay |
|---|---:|---:|---:|---:|
| A 主连复权 | 24 | **−1,452（≈持平）** | +1,966,060 | −0.0007 |
| B 真实合约 | 24 | **−223,969（亏损）** | −1,461,758 | 0.1532 |

→ 全量口径下 A（复权）仍**显著优于** B（真实合约）：去掉复权后 OOS 由持平转为 −22.4 万。
再次印证"复权不是亏损源，去掉反而更糟"。

### 7.3 日线 vs 60m 的独立性论证（不依赖 B，最关键）

**严格同口径（SN/NI 两品种、同一 `bar_60m` 价格序列）：**

| 序列 | 粒度 | walk-forward OOS |
|---|---|---:|
| SN/NI 的 `bar_60m` 下调序列 | **日线**（重采样） | **+430,926 元（盈利，§7.1 A_full）** |
| SN/NI 的 `bar_60m` 下调序列 | **60m**（生产回测） | **−375,164 元（崩塌，§5.1：SN −192,799 + NI −182,365）** |

二者价格来源**完全相同**（同一 `bar_60m`，仅重采样到日线），唯一差异是 bar 粒度
（60m 的 `ema_k=140`≈6 天 vs 日线的 140 天）。若崩塌源于复权（H4），则日线也应崩（同一下调序列）；
实测日线**盈利** → **崩塌的不同iator 是 60m 粒度下的策略/参数行为，不是数据源/复权**。
全 50 品种的日线 A 同样≈持平（WF OOS −1,452，§7.2），而 60m 全 50 品种崩 −330,406（§1），方向一致。

### 7.4 局限与诚实声明

1. **粒度错配**：因服务器无 60m 真实合约数据，决定性对照只能在日线做；60m 真实合约直测不可行。
   但 §7.3 的"同序列日线 vs 60m"论证不依赖真实合约，已单独决定性。
2. **B 含换月跳空污染**：B 是裸拼接，换月处价格跳空会制造虚假 P&L/信号，可能**夸大** B 的亏损；
   故 B 的**绝对量级不可直接读**，但其**方向（不救 SN、且劣于 A）**与 §7.3 互为印证。
3. **proper 真实合约回测**（逐合约、换月平仓实现价差）可进一步消除 B 的污染，但非定论所必需。

   OOS 净 R 全部为负、同号通过=NO。即 **V2 的边在近期样本外无论用哪个时间尺度都消失**——
   不是"60m 粒度错配、挪到日线就好"，而是**边本身在近期 regime 不存在 / 被结构性破坏（H3 的硬化版）**。

   OOS 窗后，日线同样 decay（daily_60 IS +0.026 → OOS −0.026）。
2. **60m 比日线更糟的根因是成本，不是信号逻辑**：60m 的 OOS 成本R ≈ **0.057**，日线 ≈ **0.021**——

   **普遍小于成本**。所以策略是**成本负向（gross alpha < transaction cost）**，60m 因频次高而被放大，
   但日线也救不回（日线毛 R 同样被 0.021 成本吞噬）。
3. **ema_k 在 60m 从 20 扫到 1120（≈3 天~≈1.7 年）都不救**：HTF 趋势门控周期不是瓶颈——
   瓶颈是"每笔交易的毛 alpha 抵不过成本"。

### 8.4 最终结论（硬化）

| 假设 | 最终判定 |
|---|---|
| H1 单一数据源人为衰减 | ❌ 否定（§5.2 两源都崩） |
| **H2 参数衰减 / 粒度错配（挪日线或重估可救）** | ❌ **否定（实测）**：reest 不救（§5.3）；日线 OOS 同样负（§8.2） |
| **H3 策略真失效（跨尺度、成本主导）** | ✅ **成立（硬化）**：§8.2 全尺度 OOS 负、gross<cost |
| H4 主连复权 bug | ❌ 否定（§7） |
| H5 成本口径 | ✅ 已排除（成本 IS/OOS 同口径） |

**一句话**：V2 融合策略在近期样本外（2024-2026）**无论日线还是 60m、无论 ema_k 取多少，都显著为负（t≈−2.7），
根因是每笔毛 alpha 小于交易成本**——这是策略本身的真失效，不是数据/复权 bug（H4 否）、也不是参数重估或挪粒度能救（H2 否）。
SN/NI 的"集中亏损"在 WF 口径下部分属实（NI 单品种占 60%），但更底层的结论是**边在近期 regime 消失了**。

### 8.5 下一步（重写）

1. **H4/H2 两条"设定问题"线全部下撤**：不要再投入"修主连复权"或"挪日线/重估参数"来期待 V2 转盈——决定性验证已证伪。
2. **转向策略 alpha 本身的再研究**：问题的本质是"毛 alpha < 成本"。方向应是：
   (a) 重新审视入场质量 / 信号逻辑（当前胜率仅 ~28%、毛 R 微正）；(b) 评估降低换手（更长持有、更少假信号）
   以压低成本 R；(c) 考虑 V2 是否是"已衰减的 old-school 趋势/均值回归 alpha"，需 new idea 而非调参。
3. **离场候选 `SL1.0/TR6.0` 维持不晋升**——崩塌根因在 alpha 层，离场参数之争是次要矛盾。
4. **部署侧隐患（高优先）**：SN/NI/AP 在连续回测下"一次入场永不平仓"。若 V2 上实盘连续运行，
   必须确认 walk-forward/在线引擎在跨合约换月或长期持仓下有强制平仓/再入场机制，否则会重演"持 11 年"。
5. **（可选）proper 真实合约回测**：逐合约、换月平仓实现价差，彻底排除复权变量；鉴于 §7/§8 已决定性，此项可暂缓。
