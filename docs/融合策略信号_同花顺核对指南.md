# 融合策略信号 —— 在同花顺期货通里怎么核对（以 PTA 为例）

> 生成日期：2026-09-14　适用：qhyc 融合策略 15 分钟信号扫描（`TA888` 等 50 品种主力连续）

## 一、结论先说

| 问题 | 答案 |
|---|---|
| 看哪个序列？ | **PTA主连**（主力连续） |
| 看哪个周期？ | **60 分钟**（不是日线！） |
| 引擎用的是哪条数据？ | `TA888` = 新浪主力连续 `TA0`（不复权拼接），当前拼接的是 **TA701** |
| 为什么我在图上"看不到"信号？ | ① 周期不对（日线）；② 同花顺不会显示我们策略的信号，只有你自己画线才能对照；③ 部分信号非常临界 |

## 二、四条序列的区别（别选错）

| 同花顺里的名称 | 含义 | 是否等于引擎的 TA888 |
|---|---|---|
| **PTA主连** | 主力连续：把各时期"持仓量最大的合约"首尾拼接，换月处会**跳空** | ✅ **就是它** |
| PTA连续 | 最近月／交割月合约的连续（连一、连二…），价格是**近月合约** | ❌ 不是同一条线 |
| PTA指数 | 全部挂牌合约按持仓量/成交量**加权**平均，永不跳空 | ❌ 不是同一条线 |
| PTA主力合约（如 TA701） | 当前单一主力合约，可真实交易 | ⚠️ 未换月时与主连当前段重合；换月后会与主连分叉 |

**实证依据**：`daily_bar` 中 `TA888` 在 2026-09-04 的 OHLC = 5996 / 6006 / 5884 / 5922、持仓 1,064,566，
与 `contract_daily` 中 `TA701` 的当日数据**完全一致** → `TA888` 就是"当前主力合约的拼接"。
（TA 的主力月为 1/5/9；9 月合约进入交割月后，主力已轮到 **TA701**。）

## 三、引擎在图上画的是哪两条线

全部基于 **60 分钟收盘价**：

| 用途 | 参数 | 代码实现 | 同花顺公式写法 |
|---|---|---|---|
| 方向层（锁多/锁空） | `ema_k = 140` | `ewm(span=140, adjust=False).mean()` | `EMA(CLOSE,140)` |
| 入场线（回踩/上穿） | `ma_n = 20` | `ewm(span=20, adjust=False).mean()` | `EMA(CLOSE,20)` |

⚠️ **重要**：代码里变量名叫 `ma20`，但实现是 `ewm`——**是指数均线 EMA20，不是普通 MA20**。
如果你在图上画的是 `MA(CLOSE,20)`（简单均线），线会不一样，回踩/上穿的位置自然对不上。

方向层还用了"**前一根**的方向"做门控（`htf_dir = 上一根的 sign(收盘 − EMA140)`），
即：上一根 60 分钟 K 收盘在 EMA140 上方 → 只允许做多；下方 → 只允许做空。这样对齐已收盘 K 线，无前视。

## 四、案例：PTA 2026-09-04 的"买"（开多）

**那根 K 线**：9/4 的 60 分钟 K，`O=5900　H=5950　L=5890　C=5946`，
当期 `EMA20 = 5945.8`、`EMA140 = 5789`。

四个条件全部满足（入场模式 `both_nm` 的"MA20 回踩重启"分支）：

1. **方向门控**：前一根收盘 5898 > EMA140(5786.7) → 只做多 ✅
2. **回踩**：最低 5890 ≤ EMA20(5945.8)，即盘中一度下破均线 ✅
3. **重启（上穿）**：收盘 5946 > EMA20(5945.8)，且前一根收盘 5898 < 前一根 EMA20 ✅
4. **阳线且收在上半部**：C > O，且 5946 ≥ (5950+5890)/2 = 5920 ✅

> ⚠️ **这个信号极度临界**：5946 只比 EMA20 高 **0.2 点**（约 0.003%）。
> 不同软件的主连拼接合约/换月日只要差一点，EMA20 就可能算成"没站上"，信号就不出现。
> 所以即使你完全按"主连 + 60 分钟"看，也可能找不出这根"买"——它不是一眼可见的形态，而是刀锋上的信号。
> 这不是你在图上操作错了。

## 六、想在图上一眼看到买卖点（可选）

在期货通里新建指标 → **「指标属性 → 类型」选「主图」**（⚠️ 不要用副图：`DRAWICON` 是按价格坐标画的，
副图坐标轴里 `LOW * 0.998` 落在范围外，箭头会看不见）→ 把下面这段贴进去：

```
FSDIR := IF(CLOSE > EMA(CLOSE, 140), 1, 0 - 1);
FSHTF := REF(FSDIR, 1);
FSE20 := EMA(CLOSE, 20);
FSUP := CLOSE > FSE20 AND REF(CLOSE, 1) < REF(FSE20, 1);
FSDN := CLOSE < FSE20 AND REF(CLOSE, 1) > REF(FSE20, 1);
FSTL := LOW <= FSE20;
FSTS := HIGH >= FSE20;
FSBL := CLOSE > OPEN AND CLOSE >= (HIGH + LOW) / 2;
FSBR := CLOSE < OPEN AND CLOSE <= (HIGH + LOW) / 2;
FSKL := CLOSE > REF(HHV(HIGH, 10), 1) AND CLOSE > OPEN;
FSKS := CLOSE < REF(LLV(LOW, 10), 1) AND CLOSE < OPEN;
FSKB := FSKL AND REF(FSKL, 1) = 0;
FSSK := FSKS AND REF(FSKS, 1) = 0;
FSLON := FSHTF >= 0 AND ((FSUP AND FSTL AND FSBL) OR FSKB);
FSSHT := FSHTF <= 0 AND ((FSDN AND FSTS AND FSBR) OR FSSK);
DRAWICON(FSLON, LOW * 0.998, 1);
DRAWICON(FSSHT, HIGH * 1.002, 2);
```

### 变量对照

| 变量 | 含义 |
|---|---|
| `FSDIR` | 本根方向 = `sign(收盘 − EMA140)`（`IF` 给 1 / -1） |
| `FSHTF` | **前一根**的方向，用于门控（无前视） |
| `FSE20` | 入场线 EMA20 |
| `FSUP` / `FSDN` | 收盘上穿 / 下穿 EMA20（与上一根比较） |
| `FSTL` / `FSTS` | 最低 ≤ EMA20（回踩）/ 最高 ≥ EMA20（反抽） |
| `FSBL` / `FSBR` | 阳线且收上半区 / 阴线且收下半区 |
| `FSKL` / `FSKS` | 收盘突破前 10 根最高 / 跌破前 10 根最低 |
| `FSKB` / `FSSK` | 上面两条的**首次触发**（去掉连续重复，避免单边行情糊一串箭头） |
| `FSLON` / `FSSHT` | 最终的开多 / 开空条件 |

### 两处必须知道的差异（别拿箭头数当交易次数）

1. **这只是入场箭头**：不含引擎的离场（2×ATR 初始 / 2×ATR 吊灯 / 0.5×ATR 保本，close-only），
   也不含引擎的 `cooldown_bars = 3` 冷却。所以箭头会比引擎实际开仓**略多**，尤其突破分支。
2. **`DRAWICON` 第 3 个参数是图标序号**，各版本图标表不同；不显示就换别的数字，
   或改用文字：`DRAWTEXT(FSLON, LOW * 0.998, '买');`

### 为什么变量都叫 `FS...`（编译报错备忘）

第一版用的是 `DIR / HTF / M20 / CROSSUP / TL / TS / BKL ...` 这类短名，同花顺报：

```
错误行数: 3    错误语句: M20 := EMA(CLOSE, 20);
详细原因: [语法错误]CROSSUP 参数名称不能与系统函数及关键字一致
```

- 真因：`CROSSUP` 与同花顺**内置函数 / 关键字撞名**（函数库很大，短英文缩写极易踩）。
- **报错行号不可信**：显示第 3 行，实际真凶是**第 4 行**（同花顺常把错误记在真凶的上一行）。
- 修法：所有中间变量**统一加前缀**（这里用 `FS`），一次根治，不必逐个试错。
- 同时补上了**运算符两侧空格**（`LOW * 0.998`，而不是 `LOW*0.998`）：`*` 不带空格最容易被
  词法器粘连成一个整体，报"函数未定义"。
- 纯 ASCII 版公式另存为：`docs/RHX_融合策略指标公式.txt`（打开→全选→复制，最不容易带脏字符）。

## 七、两个环境说明（避免误判）

1. **日志里的 `+00:00` 是假象**：`hourly_bar.trade_datetime` 是带时区字段，库里存的是**北京墙钟**值，
   但数据库会话时区是 UTC，回读时会显示成 `14:15+00:00`。**它代表的就是北京时间 14:15**，不是 UTC。
   调度器 `now = datetime.now()`（容器 `TZ=Asia/Shanghai`）与它相减是正确的。
2. **非交易时段不会被刷屏**：最新 K 线距当前超过 90 分钟就跳过（日盘收后到夜盘开盘之间不会推送）。

## 八、推送口径回顾

- 每 15 分钟扫描一次，**只在持仓状态变化时**推送：开多 / 开空 / 平多 / 平空（含反手）。
- 首次上线只发一条"融合策略已启动"，**不会补推历史持仓**——所以 9/4 那笔"买"你收不到，
  它在上线之前就已发生（当前 PTA 仍持有这单）。

## 附：推送口径（2026-09-14）

核对指南解决的是「**同花顺主图 / 引擎 / 推送**三方口径一致」，推送侧的完整规范见
工作区文档 `融合策略推送与执行规范_20260914.md`，要点：

- 推送为**事件驱动**（`fusion.heartbeat=false`）：只在持仓状态变化时推，持仓无变化不打扰；
  实测每交易日约 **5 条**（中位 6、最多 8），比原「每15分钟播报」的 63 条/日降 **92%**；
- 推送**时段窗口** `push_windows`：09:00-12:00 / 13:30-15:30 / 21:00-23:30，
  窗口外整轮冻结（23:00 后不做，夜盘品种的凌晨信号不再打扰）；节假日无行情自然静默；
- 每条**开仓信号**附该品种的 ⛔止损位 / 🎯保本触发价：
  止损 = 入场 ∓ 2×ATR（初始）与吊灯 2×ATR **取对持仓更紧者**，触发保本后上移到入场价；
  保本触发 = 入场 ± 0.5×ATR；
- 止盈不给固定目标，按后续离场信号走；
- 引擎改为**只用已收盘小时K**（`fusion.closed_bars_only=true`）——修复了原先读取未收盘K
  导致「同一小时内信号自己变」的重绘问题，同时与回测口径对齐。

推送频率与触发形态的完整依据（含实测频率表、窗口边界校验、以及"只推信号"带来的
止损不刷新盲区）见工作区文档 `推送频率调整_仅推信号_20260914.md`。
