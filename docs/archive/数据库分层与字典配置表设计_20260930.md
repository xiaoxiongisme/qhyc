## 1. 总体架构：L0 / L1 / L2 + 字典 + 配置一体化

```
┌──────────────────────────────────────────────────────────────┐
│  配置管理层（数据库控制，非代码）                                │
│  cfg_feature_switch  功能开关（替代 env/常量）                  │
│  cfg_basic_indicator 基本面/仓单指标字典                         │
│  factor_registry     因子注册/启用/删除（既有）                  │
│  data_layer_catalog  L0/L1/L2 分层血缘治理                      │
└──────────────────────────────────────────────────────────────┘
        │ 驱动 / 治理
┌──────────────────────────────────────────────────────────────┐
│  字典层（唯一权威，上层只认 variety_code + contract_code）       │
│  dim_exchange → dim_variety → dim_contract                      │
│  dim_symbol（既有）+ v_symbol_canonical（既有）                  │
└──────────────────────────────────────────────────────────────┘
        │ 解析命名空间（888/8888/KQ.m@ 由这里完成）
┌──────────────┐   存储过程    ┌──────────────┐   存储过程    ┌──────────────┐
│  L0 原始采集  │ ─sp_build_l1→ │  L1 归一化棒  │ ─sp_build_l2→ │  L2 复权offset │
│ 只入库/备份   │              │  只增改       │              │  只追加       │
│ fut_kline/    │              │ bar_5/15/30/  │              │ roll_segment  │
│ daily/hourly │              │ 60m           │              │ (cum_offset)  │
│ 基本面原始表  │              │ summary       │              │               │
└──────────────┘              └──────────────┘              └──────────────┘
```

### 1.1 L0 界定（本次拍板：1 分钟缺失且无法补充）

- **L0 = 直接采集的各周期原始棒（5/15/30/60m/daily 来自 天勤/akshare）+ 基本面原始表**（仓单/库存/基差/会员持仓/宏观/逐合约日线）。
  - 这些表**只入库保存、定期备份、不删除**（`data_layer_catalog.mutable_policy='write_once_backup'`）。
- `minute_bar`（1 分钟）保留为 L0 类但当前为空（预留）；`sp_build_l1_from_minute` 已就绪，未来 1 分钟补回即可重建各周期 L1 棒。
- 此界定与《数据层复权架构裁定_20260930》一致，仅把原「L0=minute_bar」上移为「L0=直接采集棒」——因 1 分钟已不可得（用户 2026-09-30 明确）。

### 1.2 L1 / L2 由存储过程产生，只增改/只追加

- **L1** `bar_5m/15m/30m/60m` + `member_position_rank_summary`：`mutable_policy='add_modify_only'`，由 `sp_build_l1_*` 经 `dim_symbol` 归一化 888/8888 写入（UPSERT）。
- **L2** `roll_segment`：`mutable_policy='append_only'`，由 `sp_build_l2_roll_segment` 从 L1 双门检测换月、只 INSERT 新段（历史段永不改）。`cum_offset` 锚定最早段=0，符合裁定「后复权只追加、历史永不重算」。

## 2. 新增/调整表清单

### 2.1 字典表（007）

| 表 | 主键 | 来源回填 | 说明 |
|---|---|---|---|
| `dim_exchange` | exchange_code | 静态种子（6 所） | 交易所字典 |
| `dim_variety` | variety_code | `futures_symbol`(73) + `dim_symbol` | 品种字典（tick/multiplier/main_symbol） |
| `dim_contract` | contract_code | `contract_code_map` + `contract_daily`(日期) + `main_contract_map`(is_main) | **合约配置表**：上市/交割起止、是否主力、所属主连 |
| `v_variety_contracts` | 视图 | — | 品种→合约族概览 |

**合约配置表 `dim_contract` 关键列**：`delivery_year/month`、`list_date/first_trade_date/last_trade_date`、`main_symbol`（如 CU888）、`is_main`（当前主力快照）、`is_active`。满足用户「每个合约的起止时间、合约是否主连」。

### 2.2 配置表（008）

| 表 | 作用 | 关键列 |
|---|---|---|
| `cfg_feature_switch` | **数据库控制的功能开关**（替代 env/代码常量） | switch_key(PK)/enabled/value/switch_group |
| `cfg_basic_indicator` | 基本面/仓单指标字典 | indicator_code(PK)/src_table/frequency/unit/layer |
| `data_layer_catalog` | L0/L1/L2 分层治理（固化血缘） | table_name(PK)/layer/source_layer/derived_by/mutable_policy |

**`cfg_feature_switch` 种子（与现状 env 实际生效值对齐，避免迁移即行为突变）**：
`factor_v1v6_enabled=true`、`factor_ic_monitor_enabled=true`、`data_selfcheck_enabled=false`、`portfolio_brake_enabled=false`、`cloud_sync_enabled=true`、`rebuild_fut_kline_enabled=false`、`l1_canonical_enabled=true`、`l2_roll_enabled=true`、`minute_bar_adj_enabled=false`（废弃路径保留审计）、`briefing_signal_enabled=true`、`prediction_enabled=true`。

> 运维启停一项功能只需 `UPDATE cfg_feature_switch SET enabled=... WHERE switch_key=...`，**不必改代码/改 env/重启冷路径**。代码侧已通过 `app/core/feature_switch.py` 读取，且带 60s TTL 缓存与「表缺失回退 default」的容错。

### 2.3 存储过程（009）

| 过程 | 作用 | 策略 |
|---|---|---|
| `l1_table_of(freq)` | freq→bar 表映射辅助 | 纯函数 |
| `sp_build_l1_from_minute(p_freq)` | 1m→Xm 聚合（未来 1 分钟补回用） | 当前 1m 空→安全 no-op |
| `sp_normalize_l1_symbols()` | 审计 bar_* 非规范符号 | 只读报告 |
| `sp_refresh_dim_contract_dates()` | contract_daily→dim_contract 日期 | 只增改 |
| `sp_build_l2_roll_segment(p_freq)` | L1→L2 换月 offset（双门检测） | **append-only，fail-loud 守卫** |

## 5. 散落裸引用的整改计划（不一次性盲改）

`scripts/lint_direct_table_refs.py` 扫描结果：**`app/` 网关外裸引用 234 处 / 34 文件**（含网关自身 `app/data/*`、采集器 `app/ingest/*`、ORM `app/models/*` 等合法引用；严格按现状梳理口径的「业务代码直连行情表」约 71 处 / 8 文件：scheduler/fusion_signal/anomalies/calendar/health/ingest 等）。

**整改原则（无本地 DB，避免不可验证的风险）**：
1. 网关 `app/data/*`、`db/*`、`migrations/*`、ORM `app/models/*`、采集器 `app/ingest/*`（写方）**保留裸写**（它们本就是写入/定义侧）。
2. 业务读方（API 路由、策略信号、特征、预测）逐步改为 `barstore.load(symbol, freq, caliber)`，symbol 只传品种码/合约码。
3. 每次改一个文件、跑 `pytest` + 单品种取数对拍后再合入；不在本环境批量改写 71 处。

- **缺口**：5/15/30/60m 与日线在 2026-01-01~09-30 区间缺失（1m 不可补，按用户指令跳过）。

- **验收**：行数 + 水位两端逐位核对（沿用 §现状梳理_07 的 `_cmp_local_cloud.py` 方法）。

## 7. 迁移执行与回滚（沿用本地→git→云端）

```bash
# 应用（幂等，可重复跑）：两端同构执行
python scripts/db_apply_migrations.py        # 自动按 001..009 顺序、登记 schema_migrations
psql ... -f migrations/007_dim_tables.sql
psql ... -f migrations/008_cfg_tables.sql
psql ... -f migrations/009_l0_l1_l2_stored_procs.sql

# L2 复权刷新（务必先 A/B 对拍 build_roll_segments.py）
CALL sp_build_l2_roll_segment('min15');
CALL sp_build_l2_roll_segment('min30');
CALL sp_build_l2_roll_segment('min60');
CALL sp_build_l2_roll_segment('min5');
```

**回滚**：本批均为**加法**（建表/建过程/插种子/加视图），无 DROP 表/列；如需撤销按 `007→009` 反向 `DROP` 对应对象即可。开关类改动一行 `UPDATE` 还原。`sp_build_l2_roll_segment` 若对拍不通过，用 `DELETE FROM roll_segment WHERE freq=? AND seg_start > 已知正确末段` 安全回退（append-only 天然可裁）。

⚠ **验证前置**：本环境无本地 DB 可连（沙箱无 psql、无 timescaledb 可达），迁移只在**语法/DDL 层面**经过设计核对；**逻辑需在云端 dry-run**：`sp_build_l2_roll_segment` 必须经 `scripts/build_roll_segments.py` 双门结果 A/B 对拍通过后再退役 Python。
