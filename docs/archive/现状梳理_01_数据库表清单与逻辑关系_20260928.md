## 0. 先看结论（4 条）

1. **40 张业务表 + 5 个业务视图**，全部落在 `public` schema，其中 **7 张是 TimescaleDB 超表**。
2. **零业务外键**：`pg_constraint` 里只有 `_timescaledb_*` 内部约束，**业务表之间没有任何 FK**。所有"关联"都是应用层靠列名约定（`symbol` / `trade_date` / `run_id` / `eval_date`）拼出来的 —— 这是后面所有"join 不上 / 对不齐"类问题的根因。
3. **同一个逻辑对象存在多份物理存储**（行情尤其严重）：同一段 FG 行情同时存在于 `fut_kline` / `bar_15m` / `daily_bar` / `hourly_bar` / `main_continuous`，口径与 symbol 命名空间各不相同。
4. **云地数据量级差异巨大**，且差异方向不一致（详见 §5）：分钟线只在云端；`fut_kline` 的 min15/30/60 `continuous` 本地几乎为空。

```
                        ┌──────────────┐
                        │futures_symbol│ 品种主表(73)
                        └──────┬───────┘
                               │ product / symbol
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
   ┌────▼─────┐          ┌─────▼──────┐         ┌─────▼──────┐
   │ daily_bar│          │ hourly_bar │         │main_contin.│
   │ (akshare)│          │ (akshare)  │         │(csv_smooth)│
   └────┬─────┘          └─────┬──────┘         └─────┬──────┘
        │                      │                      │
        │  ← 三套"日线/小时线"并存，口径不同 →          │
        │                      │                      │
   ┌────▼──────────────────────▼──────────────────────▼─────┐
   │                    预测 / 回测 / 特征层                  │
   │  prediction_result   backtest_result ←run_id→           │
   │  sector_index        backtest_detail ←eval_date→daily_bar│
   │  transmission_weights  model_weights                    │
   └─────────────────────────────────────────────────────────┘

  ┌──────────────── 行情权威源（回测/对账基准）────────────────┐
  │  fut_kline (freq × kind)  ←天勤 天勤                     │
  │     contract ──┐                                          │
  │     continuous ├── 同一品种同一时段的三份，symbol 命名空间  │
  │     cont_adj ──┘  不一致（888 vs KQ.m@）                  │
  └──────────────────────────┬───────────────────────────────┘
                             │ 分钟源（仅云端）
              minute_bar → minute_bar_adj → bar_5m/15m/30m/60m

  ┌──────── 基本面（symbol = 合约标准码，与行情 888 是两套码）────────┐
  │ member_position_rank → member_position_rank_summary              │
  │ spot_basis / warehouse_receipt / inventory / roll_yield          │
  │        ↓ _lagged 视图（防前视）                                   │
  └────────────────────────┬─────────────────────────────────────────┘
                           │ contract_code_map（跨源代码桥梁）
                           ▼
                    factor_value ← factor_registry
```

**四条关键关联键**（全部是应用层约定）：

| 关联键                             | 连接的表                                                                                        | 风险                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `symbol`（主连 888 / `FG888`）      | `daily_bar`、`hourly_bar`、`bar_5/15/30/60m`、`fut_kline(min15+,continuous)`、`fusion_position` | `fut_kline` 的 daily/hourly cont_adj 用 `KQ.m@CZCE.FG`，与 888 **跨周期 join 不上**（已实测） |
| `trade_date` / `trade_datetime` | 几乎所有时序表                                                                                     | 时区/日界不统一（夜盘归属）                                                                  |
| `run_id`                        | `backtest_result` ↔ `backtest_detail`                                                       | 跨 run 重复计数曾致审计偏差                                                                |
| `eval_date`                     | `backtest_detail` ↔ `daily_bar`                                                             | 口径错位（ret_close vs close）曾致 reversal 0.5000 bug                                  |
