# 数据层复权架构裁定（2026-09-30）

> 背景：用户提出「未复权底表 → 复权回测」「主力/其他合约出信号」「1 分钟采集积累 → 聚合 → 复权」  
> 三条诉求，并判断「复权结果已保存，就不必重算」。本文件用本地实测数据逐条裁定。

---

## 0. 一句话结论

**不冲突，但必须分层，且「存了就不用重算」这个判断对前复权不成立、对后复权成立。**  
建议把复权层从「存复权结果」改为「存换月事件 offset」，前复权/后复权在回测上数学等价  
（实测逐 bar 差分差异 = 0），但后者只需追加、历史永不重算——这正好满足  
「1 分钟采集积累、底表可删」的减容目标。

---

## 1. 五个问题的裁定

### Q1：未复权底表 vs 复权回测，冲突吗？

不冲突，是**上下游**关系：未复权是输入，复权是派生。系统已用 `kind` 物理分离  
（`continuous` / `cont_adj` / `contract`），不存在覆盖。

但有一条**真冲突**：`app/data/caliber.py` 写明 PRD 铁律  
`DEFAULT_CALIBER = "continuous"`，且两个在产策略 `fusion_v34`(hourly)、  
`magic_axis`(15m) 都声明 `caliber="continuous"`。  
**回测改吃 `cont_adj` = 改 PRD 铁律，必须先改 PRD，不能偷偷切。**

### Q2：主力/其他合约出信号，与复权回测冲突吗？

**不冲突，但不能用同一个价格域。**

- **判定层**（信号）：复权序列。实测不一致率仅 0.20%~1.90%（10 品种中位约 0.7%），  
  且其中 **92%（721 个中的 663 个）集中在换月 ±30 根内**——即复权改掉的正是  
  换月造成的假穿越，不是扭曲正常行情。
- **执行层**（下单）：**不经过复权层**。复权价是数学构造、不可成交，  
  必须映射到真实合约。系统已有现成映射：`main_contract_map.main_symbol`、  
  `futures_symbol.main_symbol` / `is_main`、`v_symbol_canonical.contract_symbol`，  
  且 `fut_kline(kind='contract')` 已有 **619 万行**逐合约数据。

**为什么只差 1%？** 因为「价格 vs 同序列派生量（MA/ATR/通道）」这类判断在  
**整体平移下不变**——价格和 MA 同步平移，穿越点不变；  
ATR 是差分/点数，段内差分完全相同。  
**会变的是绝对价位判断**（`price <= 3400`、保证金、涨跌停、tick 取整）。

> 推论：只要策略用**距离 / ATR 倍数 / 收益率**口径，复权与未复权天然兼容；  
> 一旦出现硬编码价位或按价格百分比计算，就必须显式处理。

### Q3：1 分钟采集 → 聚合 → 复权 → 回测，可行吗？

**可行，且复权根本不需要 1 分钟。**

`scripts/adjust_bars.py` 只读 `bar_15m/30m/60m` 的 888 + 8888，**从不读 `minute_bar`**。  
本地实测：`minute_bar` 已清零（0 行），而 `bar_15m` 888 / 8888 各约 443 万行，  
复权链路照常工作。

| 层                    | 时间局部性                                         | 能否删底表  |
| -------------------- | --------------------------------------------- | ------ |
| 聚合（1m → 15m/30m/60m） | **时间局部**（只重算最近 days_back 天，桶对齐 DELETE+INSERT） | ✅ 可删   |
| 前复权                  | **全局依赖**（见 Q4）                                | ❌ 删了就废 |
| 后复权 / offset         | **只追加**                                       | ✅ 可删   |

### Q4：「保存了数据，就不需重算」——**前半句对，后半句错**

存储只省「读原始」的时间，省不掉「重算」。前复权**锚定最新段**，而「最新」每天都在变。

实测（本地 bar_15m，10 个品种，方法：对比「含最后一次换月」与「截断到最后一次换月前」  
两种情形下同一根历史 bar 的复权值）：

| 品种    | 换月数 | 最后一次换月     | 跳空点数    | 历史 bar 复权值改变量 | 是否等于跳空点数 |
| ----- | --- | ---------- | ------- | ------------- | -------- |
| AG888 | 15  | 2023-07-04 | +36.0   | +36.0         | 是        |
| AU888 | 12  | 2025-08-29 | +3.6    | +3.6          | 是        |
| PB888 | 35  | 2024-07-19 | −470.0  | −470.0        | 是        |
| AL888 | 29  | 2025-06-19 | −160.0  | −160.0        | 是        |
| CU888 | 6   | 2023-11-21 | −220.0  | −220.0        | 是        |
| ZN888 | 22  | 2024-12-17 | −320.0  | −320.0        | 是        |
| NI888 | 13  | 2023-05-19 | −4330.0 | −4330.0       | 是        |
| SN888 | 21  | 2022-10-18 | −3550.0 | −3550.0       | 是        |
| SC888 | 30  | 2025-07-14 | −12.4   | −12.4         | 是        |
| JM888 | 29  | 2025-12-05 | +77.5   | +77.5         | 是        |

**10/10 全部命中**：每新增一次换月，**全历史每根 bar 的复权值统一平移该跳空点数**。

> 这正是之前减容方案的雷：删掉 2015–2025 的 `minute_bar` 后，  
> `adjust_minute.py` 遇换月触发 `full=True` → 读全历史 → 只能写回 2026 →  
> 历史复权被清空，且 `assert_source_not_regressed` 只比 `max(ts)` 尾部，**拦不住**。

### Q5：那就没有办法了吗？——有：改存「换月事件 offset」

实测前复权 vs 后复权（同 10 品种）：

| 品种    | 逐 bar 差分最大差异 | 价格差（常数 K） | K 是否恒定 |
| ----- | ------------ | --------- | ------ |
| AG888 | 0.000000000  | +1083.0   | 是      |
| AU888 | 0.000000000  | +38.4     | 是      |
| PB888 | 0.000000000  | −6195.0   | 是      |
| AL888 | 0.000000000  | −2575.0   | 是      |
| CU888 | 0.000000000  | −1860.0   | 是      |
| ZN888 | 0.000000000  | −6125.0   | 是      |
| NI888 | 0.000000000  | −14880.0  | 是      |
| SN888 | 0.000000000  | −4760.0   | 是      |
| SC888 | 0.000000000  | −21.5     | 是      |
| JM888 | 0.000000000  | −1115.5   | 是      |

**前复权序列 = 后复权序列 + 常数 K**（K = 该品种全部换月累计，std < 1e-6），  
逐 bar 差分**浮点级完全一致**。

**结论：回测用后复权与前复权数学等价，但后复权只追加、历史永不改变。**

## 2. 为什么非做不可：不做复权的失真量级

未复权 888 序列在换月 bar 上的 close-to-close 收益 = 换月跳空，  
这是一笔**不存在的盈亏**。实测（同 10 品种）：

| 品种 | 换月数 | |跳空|中位 | |跳空| / ATR14 中位 | |跳空| / 价格 | 最大跳空 | 年换月次数 |  
|---|---|---|---|---|---|--- | --- | --- | --- | --- | --- | --- |  
| AG888 | 15 | 64.0 | 5.23 | 1.77% | 137.0 | 1.3 |  
| AU888 | 12 | 3.4 | 6.11 | 1.05% | 4.7 | 1.0 |  
| PB888 | 35 | 180.0 | 4.21 | 1.22% | 485.0 | 3.0 |  
| AL888 | 29 | 130.0 | 3.55 | 0.87% | 320.0 | 2.5 |  
| CU888 | 6 | 420.0 | 3.14 | 0.64% | 480.0 | 0.5 |  
| ZN888 | 22 | 267.5 | 3.75 | 1.26% | 540.0 | 1.9 |  
| NI888 | 13 | 1640.0 | 4.57 | 2.05% | 8140.0 | 1.1 |  
| SN888 | 21 | 1990.0 | 4.13 | 1.29% | 6560.0 | 1.8 |  
| SC888 | 30 | 8.8 | 4.90 | 1.77% | 28.3 | 3.5 |  
| JM888 | 29 | 88.0 | 6.94 | 5.67% | 353.0 | 2.5 |

**换月跳空中位 = 3.1 ~ 6.9 个 ATR14（中位约 4.6）。**  
而期货策略单笔止盈通常在 2~3 个 ATR 量级——  
**一次换月的假盈亏，比一笔真实交易的盈亏还大。**

叠加：84 品种 × 平均 2 次/年换月 ≈ **每年约 170 次换月事件**。  
现有在产回测（fusion / magic 均吃 `continuous`）**每次换月都会记一笔假盈亏**，  
这部分误差目前是**未被计量**的。

## 3. 建议架构

```
L0  minute_bar          1 分钟未复权原始        → 滚动窗口 30~60 天（或按品种保留）
L1  bar_5/15/30/60m      未复权 888 + 8888      → 长期保留（443 万行×2，是复权唯一输入）
L2  roll_events          (symbol, ts, delta)    → 约 2.8k 行，几 KB，只追加
    或 per-segment offset 表（每个合约段一个常数）
L3  main_contract_map    888 → 真实合约          → 已存在，执行层用
```

回测取数：`adj = raw + offset(ts)`（as-of join），或预生成后复权物化表。  
**不再生成 `minute_bar_adj`（7.03GB）**。

### 附带收益

- 省 7.03GB（`minute_bar_adj`）+ 免去 4~5 小时全量重算窗口。
- 拆掉「删历史底表 → 复权静默清空」这颗雷。
- 商品期货前复权**存在历史价格被推成负值**的风险（NI 累计 −14880，  
  若品种价格量级小于累计贴水，历史价转负 → 任何百分比计算爆炸）；  
  offset 方案天然规避。

### 落地顺序（沿用 本地 → git → 云端）

1. 建 `roll_events` 表 + 回填脚本（从现有 `bar_15m` 双门检测产出）。
2. 回测引擎加 `caliber` 参数，支持 `cont_adj_off`（即时 offset 复权），  
   **先在 fusion / magic 上做 A/B 对拍**，确认收益差 = 换月累计。
3. 对拍通过后，关 Path B（`fut_kline_rebuild.enabled=false`），退役 `minute_bar_adj`。
4. 最后才动 `minute_bar` 清理，且清理前加守卫：目标区间在 `bar_*` 已存在且非空。

1. **PRD 铁律是否改**：`DEFAULT_CALIBER` 由 `continuous` 改为复权口径？  
   （不改也能落地——回测层显式传 `caliber` 即可，但需承认现有回测含换月假盈亏。）

## 5. 实测口径与局限

- 数据源：本地 `qhyc-timescaledb`，`bar_15m` 886 万行、84 品种、2015-01-05 ~ 2026-09-29。
- 样本：按数据量取前 10 品种（AG/AU/PB/AL/CU/ZN/NI/SN/SC/JM），  
  **偏有色/贵金属，黑色与化工未覆盖**；另一轮另测 IF888、TA888 结论一致  
  （IF 跳空/ATR=2.84、TA=5.40，K 恒定，历史改变量=跳空点数）。
- 换月检测：复用 `scripts/adjust_bars.py` 双门（振幅门 + 指数连比率门 0.40）。  
  **漏检会低估**换月影响，故 Q2 结论是下界。
- 验证脚本：`scripts/_diag_adj_roll.py`、`scripts/_diag_adj_roll2.py`（只读，不写库）。
