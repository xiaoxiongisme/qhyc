# 详细设计（期货数据 / 因子 / 回测系统）

> 生成时间：2026-09-27
> 范围：行情采集、基本面采集、因子计算、调度、模型回测、本地↔云端同步的整体设计。
> 配套文档：`数据库设计.md`（表/字段/数据量）。

---

## 1. 系统定位

面向期货量化研究的一体化数据平台：采集四所（SHFE/CZCE/DCE/GFEX）行情与基本面数据，计算横截面/时序因子，支撑 wb 等研究员的策略回测。当前已实现**日线/小时线/15 分钟级行情（bar_15m 全品种，已随部署完整上云）/仓单/会员持仓**的采集与存储；**因子落库**已完成初版（`compute_factor_value.py` 落 `factor_value`，2,116,977 行，待接调度）。

---

## 2. 总体架构

Docker 编排（同构双环境）：

| 容器 | 镜像 | 职责 |
|---|---|---|
| `timescaledb` | TimescaleDB 2.17 / PG16 | 统一时序库（库 `futures`） |
| `api` | Python 服务 | 查询/推送接口 |
| `scheduler` | `app.scheduler` (APScheduler) | 单进程 `BlockingScheduler`，所有定时采集 |
| `pipeline`（M8） | 决策链路 | WB 信号档与推送 |

- **本地**：`docker-compose.yml`，`timescaledb` 映射 `5432` → 宿主可直连（localhost:5432）。
- **云端**：`docker-compose.cloud.yml`，同构镜像但 `listen_addresses=localhost` 且不映射 5432，**仅容器内网 `timescaledb` 主机名可达**。「服务器入库」= 云端重新部署同构容器并跑同一套 SQL/seed/采集脚本，无独立 ETL。

## 3. 数据采集层

### 3.1 行情（fut_kline）
- 来源：天勤 天勤（`fetch_fdf.py`），频点 `daily/hourly/min15`。
- 写入统一超表 `fut_kline(freq, kind, symbol, trade_datetime)`。
- 现状：daily/hourly 齐全；`fut_kline.min15` 仅 FG（一次性人工抓取），但**合成的 `bar_15m` 含全品种 168 合约（2026-09-27 实测云端=本地）**。

### 3.2 仓单日报（warehouse_receipt）
- 脚本 `collect_warehouse_receipt.py`，按交易所分路：
  - SHFE：先试 `dailydata/{date}dailystock.dat`（≤2025-11-17），404 回退解析 HTML 报表。
  - CZCE：`.xls`(≤2025-11-01) / `.xlsx`，openpyxl + xlrd 统一读取。
  - DCE/GFEX：Scrapling 浏览器会话，**按日即时 upsert + 跳过已存在日期（断点续跑）**，单日异常隔离。
- 当前 720,967 行，四所均至 2026-09-24。

### 3.3 会员持仓排名（member_position_rank(_summary)）
- `collect_member_rank_summary.py`：读交易所官方逐会员明细 → 聚合 top5/10/15/20 写入 summary（24 列）。

### 3.4 基本面（inventory / spot_basis / roll_yield）
- 对应 `collect_*.py`；`inventory`/`spot_basis` 已有数据，`roll_yield` 暂空。
- 定时任务中 `inventory_weekly` / `spot_basis_daily` 默认 `enabled=False`，需手动或配置开启。

## 4. 行情数据分层与处理

```
天勤 1分钟  ──▶  minute_bar  ──(time_bucket)──▶  bar_5m / bar_15m / bar_30m / bar_60m
                                                     │
daily contract ──▶ contract_daily        │
天勤 daily   ──▶ daily_bar  ──▶ main_contract_map ──▶ main_continuous (复权主连)
fut_kline(daily/hourly/min15) ──▶ adjust_cont_adj (复权主连重算)
```

- **实测现状（2026-09-27）**：`minute_bar` 实际 114,305,280 行、`bar_5m` 24,086,684 行、`bar_15m` 8,845,980 行（168 合约），且**云端与本地逐位一致**（行数、逐 symbol 行数+sum(volume)+max(ts) 全同）。`bar_15m` 止于 2025-12-31（合成链路未持续跑）；`bar_*` 虽不在 `db/init`，但部署时通过一次性迁移（PRD §14.2）已完整同步至云端。

## 5. 因子层（落库初版已完成）

- **元数据表** `factor_registry`：因子定义、数据源、权重、版本（当前空，未 seed）。
- **因子值表** `factor_value(factor_id, trade_date, symbol, raw_value, z_value, available_at, version, created_at)`：已写入逻辑。
- **计算脚本** `scripts/compute_factor_value.py`：
  - A 组（日内价量，来自 `bar_15m`，168 合约全品种，2015-2025）复用 `factor_ic_scan.build_factors`；
  - B 组（横截面基本面，来自 `spot_basis`/`member_position_rank_summary`/`inventory`/`warehouse_receipt`/`roll_yield`），按交易日横截面 z 标准化；含 `cross_rank_z`（B 组等权均值）。
  - 落库：本地 `factor_value` 已写入 **2,116,977 行**（`version=1.0`）；同步云端见 `scripts/sync_factor_value_server.py`（SSH 隧道 15432，单事务 TRUNCATE+COPY，幂等）。
- **结论**：因子已从「离线分析产物（文件）」进入数据库；`factor_ic_scan.py`/`factor_pairs_ic.py` 的 IC 分析仍产出 CSV/MD。待办：seed `factor_registry`、接入调度、持续增量。

## 6. 调度层（APScheduler，`app/scheduler.py`）

| 作业 | 触发 | 内容 |
|---|---|---|
| `ingest_*` | 08/12/16 点 | 日线等采集 |
| `lstm_weekly_retrain` | 周六 06:00 | LSTM 周训 |
| `transmission_weekly_recalc` | 周六 06:30 | 传导权重 |
| `backtest_weekly` | 周六 07:00 | M4 周回测 |
| `weights_monthly_update` | 每月 1 日 06:30 | 权重月更 |
| `fusion_scan` | 每 :05/:35 | 小时线融合信号 |
| `adjust_cont_adj` | 02:30 | 复权主连重算 |
| `rank_position` | 17:30 | 会员持仓排名 |
| `hourly_collect` | 每小时 :00 | `hourly_bar` |
| `minute_and_bars` | 每 :30 | `minute_bar` + 合成 `bar_*` |
| `fut_kline_incremental` | 01:40 | `fut_kline` 增量，**freqs=[daily,hourly]** |

> **缺口**：**无因子计算作业**；`fut_kline_incremental` 不含 `min15`；`minute_and_bars` 依赖 `minute_bar`（空）→ `bar_15m` 不更新。

## 7. 模型与回测层

- `prediction_result`：每日方向/概率/收益区间预测。
- `backtest_result` / `backtest_detail`：M4 回测汇总与逐日明细（400k+ 行）。
- `anomaly_ticket`：行情源差异质检。
- wb 的回测环境为独立 **DolphinDB**（`imports/FG/`，端口 8848），当前仅含 FG 数据——这来自其本地 CSV（`E:\QH\SX\qi_signal_FG_min15.csv`），非云端库；**云端 Postgres 的 `bar_15m` 已含全品种 15 分钟**。

## 8. 部署与同步设计

- 本地 ↔ 云端为**同构容器**；同步方式 = 代码 `git push` → 云端 `git pull` → `docker compose -f docker-compose.cloud.yml build && up -d`。
- 采集脚本通过 `PGHOST` 环境变量切换：`localhost`（本地）/`timescaledb`（云端容器内）。
- **隐患**：`warehouse_receipt` / `roll_yield` / `member_position_rank_summary` / `factor_*` / `minute_bar` / `bar_*` 由脚本运行时建表（`ensure_fundamental_schema.py` + `fetch_contract_1min.py --ensure-schema`），**若只跑 `db/init` 这些表不会存在**。需在云端初始化流程显式调用。
