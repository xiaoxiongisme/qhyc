# 合约代码统一规范（v1.0 · 2026-09-20）

> 适用范围：qhyc 全库**合约级**表（`member_position_rank` / `contract_daily` /
> `main_contract_map` / `daily_bar` / `spot_basis` 近远月 / 代码对照表）。
> 唯一换算入口：`app.core.symbol_code`；唯一登记表：`contract_code_map`。

---

## 1. 标准码

**标准码 = 品种码（大写）+ 交割年月（YYMM，两位年 + 两位月）**

```
AP2701   苹果 2027-01 交割
CU2611   沪铜 2026-11 交割
SI2611   工业硅 2026-11 交割
```

这是库内**唯一的合约书写法**。任何采集器在入库前必须调用 `SC.to_std()` 归一。

## 2. 各源原生写法（为什么必须归一）

| 交易所 | 官方原生 | 月份位数 | 原生大小写 | 标准码 |
|---|---|---|---|---|
| CZCE（郑商所） | `AP701` | **3 位**（个位年） | 大写 | `AP2701` |
| SHFE（上期所） | `cu2611` | 4 位 | **小写** | `CU2611` |
| DCE（大商所） | `a2601` | 4 位 | **小写** | `A2601` |
| GFEX（广期所） | `si2611` | 4 位 | **小写** | `SI2611` |
| CFFEX（中金所） | `IF2609` | 4 位 | 大写 | `IF2609` |
| INE（上期能源） | `sc2611` | 4 位 | **小写** | `SC2611` |
| 新浪 akshare | `AP2701` | 4 位 | 大写 | 同标准码 |
| 天勤 tqsdk | `CZCE.AP701` | 郑商 3 位 / 其余 4 位 | 郑商大、其余小 | `AP2701` |

### 已经发生的实际后果（本节规范要防的正是这些）

| 后果 | 具体表现 |
|---|---|
| 跨源 / 跨所 join 全部对不上 | 同一合约官方记 `AP701`、新浪记 `AP2701`，按 symbol 关联取不到对方 |
| 因子序列被拆成两条稀疏序列 | 按 symbol 聚合的会员持仓因子被切成两半，前 5 净持仓求和失真 |
| 品种级行污染合约级因子 | 郑商所官方接口一次返回「品种级 + 合约级」两层，品种级量级远大于单合约 |
| 错标交易所 | 新浪通道曾对 DCE 返回别的交易所品种，393 行错标 |

## 3. 命名空间（不参与合约码归一）

| 形态 | 含义 | 处置 |
|---|---|---|
| `FG888` | 本项目主力连续（合成）码 | 原样保留（`to_std` 直接返回） |
| `KQ.m@CZCE.FG` | 天勤主连码 | 原样保留（`m` **大小写敏感，绝不能整体 upper**） |
| `IDX:黑色` | 板块指数合成码 | 原样保留 |
| `CZCE.AP701` | 天勤具体合约码 | 仅登记进 `tqsdk_symbol`，**物理值不改** |

## 4. API（`app.core.symbol_code`）

```python
from app.core import symbol_code as SC

SC.to_std("AP701", "CZCE")              # -> "AP2701"      任意写法 → 标准码
SC.to_std("FG601", "CZCE", ref_date=d)  # -> 按 d 补年（3 位码十年循环，必须带日期）
SC.to_native("AP2701", "CZCE")          # -> "AP701"       标准码 → 官方原生
SC.to_native("CU2611", "SHFE")          # -> "cu2611"
SC.to_sina("AP2701", "CZCE")            # -> "AP2701"      标准码 → 新浪写法
SC.to_tqsdk("AP2701", "CZCE")           # -> "CZCE.AP701"  标准码 → 天勤订阅码
SC.delivery_ym("AP2701")                # -> (2027, 1)
SC.product_of("CZCE.AP610")             # -> "AP"
SC.is_continuous("FG888")               # -> True
```

## 5. 代码表 `contract_code_map`

DDL：`db/init/14_contract_code.sql`；ORM：`app.models.ContractCodeMap`。
主键 `(exchange, std_symbol, version)`。

| 字段 | 含义 |
|---|---|
| `exchange` / `std_symbol` | 交易所 + 标准码（联合主键） |
| `official_symbol` | 交易所官方原生写法（`AP701` / `cu2611`） |
| `sina_symbol` | 新浪源写法（`AP2701`） |
| `tqsdk_symbol` | 天勤订阅码（`CZCE.AP701`） |
| `observed_native` / `sources` | 库内实际观察到的原生写法 / 来源表清单（审计用） |
| `first_seen` / `last_seen` | 该合约在库内数据中的出现日期范围 |
| `product` / `deliv_year` / `deliv_month` / `name` | 品种、交割年月、品种名 |

## 6. 运维命令

```bash
# 重建代码表（全量刷新，会删掉不在新 payload 里的旧行）
python -m app.ingest.contract_code build

# 归一：默认 dry-run，只打印将改写的行
python -m app.ingest.contract_code normalize
python -m app.ingest.contract_code normalize --apply      # 执行（自动 CSV 备份 + PK 冲突预检）
python -m app.ingest.contract_code verify                 # 自检

# 历史回填（收尾自动刷新代码表）
python -m app.ingest.backfill_rank --start 2023-01-01 --end 2026-08-31 \
    --exchanges CZCE --rebuild-map

# 只跑某几张表
python -m app.ingest.contract_code build --tables member_position_rank,spot_basis
```

HTTP：

```
GET /symbols/contracts?exchange=CZCE&product=AP&limit=500   列出代码表
GET /symbols/contracts/resolve?code=AP701                   任意写法 → 四种写法
GET /positions/latest?symbol=AP701                          查询侧也容错（3 位码可命中）
```

## 7. 四条铁律

1. **送天勤前必须转回原生码。** 天勤按郑商所 3 位码订阅（`CZCE.AP701`），
   送标准码 `AP2701` 会订阅失败。`fut_kline.symbol` 保留天勤原生码**不做物理改写**。
2. **3 位码补年必须带该行的交易日。** `to_std` 的 `ref_date` 默认今天；
   郑商所 3 位码的「年」只有个位、**十年一循环**——库里 `daily_bar` 的 `FG601`
   同时装着 2016-01 与 2026-01 两个真实合约，必须**按逐行交易日**生成日期段补年。
3. **改采集器后必须重启容器。** `./app:/app/app:ro` 只读挂载，Python 不热重载：
   `docker restart qhyc-api qhyc-scheduler`。
4. **新数据入库后要重建代码表。** 代码表是从库内实际出现过的 symbol 反推的，
   回填 / 新增品种不会自动登记（用 `--rebuild-map` 收尾）。

## 8. 新增交易所/数据源时的接入清单

- [ ] 在 `symbol_code.NATIVE_MONTH_DIGITS` / `NATIVE_CASE` 登记该所原生写法
- [ ] 采集器入库前统一走 `SC.to_std(raw, exchange, ref_date=该行交易日)`
- [ ] 过滤品种级行（纯字母无数字）与汇总行（`rank >= 999` 或会员名为空）
- [ ] `db/init/*.sql` 的表注释写明「symbol = 标准码 4 位」
- [ ] 跑 `contract_code build` + `verify`，确认无「有数据、无映射」
