## 二、关键复核发现（库内实测 vs 文档声明）

### 发现 1（核心，v1.3.5 更正）：条件反转 —— "生产回测 vs 文档验收背离"实为**阈值口径脱节**（非文档高估）

| 来源                                | reversal dir_acc                          | 样本/覆盖                    | 显著性                       |
| --------------------------------- | ----------------------------------------- | ------------------------ | ------------------------- |
| 文档 §18.11 验收                      | **0.5368**（CI[0.5240,0.5496]，p=2.04e-08）✅ | 覆盖 12.9%（声明）             | 声称显著                      |
| 文档 P6 节                           | 以「条件反转 OOS **0.535**」为方向主信号锚              | —                        | —                         |
| **生产回测 run `20260909_171921_bt`** | **0.5000**（signaled 子集）                   | n=2192 / coverage=0.3575 | Wilson CI 跨 0.5 → **未显著** |
| 同 run ensemble                    | 0.5050                                    | n=6132 / coverage=1.0    | 未显著                       |

**结论（v1.3.5 更正）**：该"不复现"**并非反转边沿虚假**，而是**验收阈值（研究 τ\*=2.0%）与部署阈值（`gate_pct=1.0%`）不一致**所致——1.0% 门控下 reversal=0.5000。**阈值对齐为 2.0% 后**（run `20260910_143938_bt`，见 §七）**池化 dir_acc = 0.5492（显著）**，与研究 0.5368 收敛同区间。故本条的正式结论是：**"文档验收口径与部署口径脱节"，而非"文档高估"**。

### 发现 2（v1.3.5 更正）：0.5368 的落差**主因是阈值错配，不是 3 日抽样伪影**

> **更正说明（2026-09-10，阈值对齐后回填）**：本节初版曾把 0.5368 → 0.5000 归因于"平台 3 日 eval 抽样"。
> 阈值对齐（`gate_pct=2.0%`）后独立实测生产**池化** dir_acc = **0.5492（显著）**，与研究 0.5368 **同量级**，
> 证明**抽样并非主因**（3 日抽样不损害该边沿）；真正的落差来源是 **`gate_pct` 误用 1.0%**。
> 下表保留为"错误阈值（1.0%）下的弱效力"证据。

复刻平台真实 3 日 eval 抽样（`eval_dates = all_dates[-(test_days+1):][::step]`，step=3），**在错误阈值 `gate_pct=1.0%` 下**：

| 复刻口径                        | n    | dir_acc    | p 值           |
| --------------------------- | ---- | ---------- | ------------- |
| ① 无门控（全抽样点）                 | 6132 | 0.5176     | 6.04e-03（弱显著） |
| ② `\|ret\|>1%`（当时生产门控）       | 2206 | **0.5109** | 3.17e-01（不显著） |
| ③ `\|ret\|>1%∩Δoi>0`（研究全规则） | 1079 | 0.5236     | 1.28e-01（不显著） |

- 该三组均 ≈0.51 或（不显著）→ **1.0% 阈值区间内确无可用边沿**，这正是"阈值错配"的危害所在。
- **对照**：同口径但 **τ\*=2.0%**（= 生产对齐后的 run `20260910_143938_bt`）→ 池化 **0.5492**（n=914，p=3.22e-03 **显著**）。差异全部来自**阈值**，与抽样无关。
- 模型方向逻辑经抽查 14 行 + 全量 JOIN 校验 **100% 正确**（`pred_dir == −sign(今日收益)`）→ **非逻辑 bug**。

### 发现 2b（本次新发现）：验收阈值 ≠ 上线阈值 —— τ\*=2.0% 被选中，生产却部署 1.0%

一手证据 `logs/research_m5_validate_20260909_114608.md` 显示，报告 1b/1c 的阈值选择为：

| τ(%) | TRAIN 反转 acc | n      |
| ---- | ------------ | ------ |
| 0.5  | 0.5224       | 64703  |
| 1.0  | 0.5260       | 40212  |
| 1.5  | 0.5280       | 25358  |
| **2.0（tau\*，被选）** | **0.5293** | 16423 |

- 报告选定规则 = **「反转 ∩ |ret|>2.0%」**，其 TEST acc = **0.5368**（n=5829，覆盖率 12.9%）。
- 但**生产实际部署 `gate_pct = 1.0%`**（`config/cloud.yaml` → `predict.reversal.gate_pct: 1.0`）。
- 即「通过验收的规则」与「上线的规则」**阈值不一致**：2.0% 是更稀疏、更高置信的子集（研究覆盖 12.9% vs 生产覆盖 35.75%）。用生产自己的 1.0% 门控，本就不可能复现 2.0% 子集的 0.5368。
- **主因**：0.5368 → 0.5000 的落差**几乎全部来自阈值错配**（研究 τ\*=2.0% vs 生产 1.0%）。**阈值对齐后**（v1.3.5，run `20260910_143938_bt`）生产池化 = **0.5492**（显著），与研究 0.5368 收敛 → 说明 3 日抽样**不**损害该边沿。这也是 §18.11 验收"方法与部署不一致"的实证。

### 发现 3（已解决）：生产 run 与日线复刻的 n / acc 错位 → 复核脚本方法学伪影，非生产代码 bug

> 用户要求"代码级根因排查"，排查结论：**无需修复生产代码**。

| 来源                          | reversal signaled n | dir_acc |
| --------------------------- | ------------------- | ------- |
| 生产 run `20260909_171921_bt` | 2192                | 0.5000  |
| 日线复刻 ②（`\|ret\|>1%`，3 日抽样）  | 2206                | 0.5109  |

**根因定位（决定性证据）**：

- **[A] 生产自洽性核对**：用生产自有函数（`load_canonical_series` + `features_from_series` + `ReversalModel.predict` + `_next_ret`）在 backtest_detail 已存的 (symbol, eval_date) 上重算，**前 200 行 pred_dir / signaled / actual 一致率 = 200/200**。→ 生产回测逻辑完全自洽，**无代码 bug**，0.5000 为真实生产口径数字。
- **[B] 错位来自"评估窗口未对齐"，非计算**：逐品种比对生产 eval 日期集与"钉到 run 边界 2026-09-08 重建的 last251[::3]"集合，平均重叠 **0.918**、中位 **1.000**，但 **TF888 / CS888 / IC888 重叠 = 0.000**（三者在 daily_bar 均有 2300~2800 行）。即绝大多数品种窗口完全一致，仅少数品种（指数/长历史类）生产 run 时数据快照与复刻快照错位 → 3 日网格整体平移 → 集合看似"错位"。
- 排除项：`ret_series(close) == close.pct_change()*100`（口径一致）；生产 71/73 品种 source=akshare_tqsdk=daily_bar（与复刻同源）；方向逻辑 100% 正确。

**结论**：`review_eval_sample.py` 从 daily_bar 重建评估窗口时**未钉住生产 run 的数据快照（2026-09-09，数据截至 2026-09-08）**，且少数品种（TF888/CS888/IC888）run 时数据较旧/已回填，导致重建窗口与生产窗口错位，表现为 n/acc 差异。**这是复核脚本的方法学伪影，生产代码无需改动。** 若需 apples-to-apples 复核，应直接以 backtest_detail 的 (symbol, eval_date) 为基准，而非重建窗口。

### 发现 4（v1.3.5 更正）：文档已自察趋势市失效；「0.5368 不可复现」的原判**已更正**

- §18.12 实证补充已知近 60 交易日趋势市 reversal acc=0.43 显著低于 0.5，处置为「维持长周期 OOS 0.5368 结论 + 月更自动降权」。
- 初版曾据此判定"§18.11 的 0.5368 需降级为 ~0.51 弱边沿"。**阈值对齐后该判定被推翻**：0.5368 无需降级，它本就是 **τ\*=2.0% 口径**的正确效力；此前"不可复现"是因为拿它去比 **1.0% 门控**的生产 run。**正确处置 = 把部署阈值对齐到 2.0%（已完成）**，而非下调验收值。
- **保留的有效结论**：趋势市（如近 60 日）反转确实失效，仍由 ⑳ 月更降权 + §18.12 状态过滤兜底。

### 8.5 结论：验收两门槛**数学上不可同时满足**（结构性问题）

- 满足「覆盖率 ≥ 15%」的阈值只有 **0.5%（acc 0.4992 不过）** 与 **1.0%（35.67%，acc 0.5231 < 0.53 不过）**。
- 满足「acc ≥ 0.53」的最低阈值是 **2.0%，但覆盖率 14.87% < 15%**。
- **两个约束的可行域不相交**——因 acc 与覆盖率单调反向。这不是"差 0.13pp 的运气问题"，而是**指标结构性 trade-off**。

**Gate 选择建议**：
1. **维持 `gate_pct=2.0%`（已采纳）**：acc 0.5493（显著，p=0.0029）、净 P&L **+0.1335%/笔**（1.5% 的 6.0 倍）、资金效率 0.0199（1.0% 为负 −0.0052）。覆盖率 14.87% 与门槛仅差 0.13pp。
2. **不建议为凑 15% 下调至 1.5% / 1.0%**：1.5% 的 acc=0.5296 **更不达标**（<0.53），净 P&L 仅 2.0% 的 17%；1.0% 净 P&L **转负**——**越降越差**。
3. **若要真提覆盖率**，唯一途径是**扩品种/扩样本**（如纳入更多流动性品种），而非调阈值迎合。

- **量化缺口**：gate=2.0% 实测覆盖率 **14.87%**，距 15% 门槛 **−0.13pp**；由 §8.5 可知该缺口**无法通过任何阈值调整闭合**（覆盖≥15% 与 acc≥0.53 的可行域不相交）。
- **处置纪律**：① `gate_pct` **保持 2.0%**（唯一同时满足 acc≥0.53 与净 P&L>0 的阈值）；② **禁止**为凑覆盖率下调阈值（1.5% acc 更差、1.0% 净 P&L 转负）；③ 提覆盖率的**唯一合规路径 = 扩品种/扩样本**（新增流动性品种进入评估池）。
