## 0. 评审结论与采纳项

**总结论**：数据层 PRD「去天勤（T 系列）」尚余 `app/ingest/fdf` 历史 ETL 模块、3 个离线回填脚本、以及约 45 个文件中的 `天勤` 引用未清理。经代码实证，**fut_kline 已全面孤儿化，应退役删除而非 akshare 替代**；其余按「三线并行、覆盖优先」推进，最终达 `grep -rn 天勤 app scripts → 0`。

**用户采纳的两项拍板**：
1. **fut_kline 处置 = 退役（删非替）**。证据链：迁移 `027_retire_fut_kline_continuous.sql` 已退役 `continuous`/`cont_adj`；仅存活的 `kind='contract'` 只被已退役的 `adjust_fdf.py` 读取（`load_contract_frames` 调用点仅 `adjust_fdf.py:220` + `_diag.py:8`）；`build_roll_segments` 读 `bar_5m/15m/30m/60m` 不读 `fut_kline`；容器内直查 `fut_kline` **2026-10-01 之后 0 行**（天勤 增量实际停写）。替代它会造出新的孤儿数据。
2. **离线回填脚本 = 保留 akshare 版**（删除其 天勤 分支，改用 akshare 历史源）。理由：三者均写 **L0 原始层**（`bar_5m`/`bar_15m`/`minute_bar`/`daily_bar`），属灾难恢复能力，akshare `futures_zh_minute_sina`(period=1/5/15) + `futures_zh_daily_sina` 可等价覆盖。

**交付边界**：本报告为文档与评审，不含代码改动；所有执行动作交 CB。删除类操作均给出精确命令与回滚。
