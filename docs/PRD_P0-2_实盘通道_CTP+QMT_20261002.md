## 0. 为什么必须做

`PRD_P0-1` 已把"信号 → 真实合约可执行订单建议"做齐（输出 `ExecutionOrder(real_symbol, price, lots, blocking_reasons, ...)`），但**明确未覆盖经纪商通道**（§1.2、§8）。当前链路最末一公里：

```
fusion_signal → /execution/reverse → ExecutionOrder → [断在这里] → 真实下单
```

没有真实下单通道，订单建议只能停留在"打印/推送"层，qhyc 永远无法从研究链走向生产。

**资金约束**：用户当前资金 < 10 万，**股票 QMT 10 万门槛是硬门槛不可绕开**（券商/监管准入）。期货普通商品程序化多数头部公司**无资金门槛**，商品期权需 10 万验资。故本层采用**双通道并行**：

- **CTP 通道**：覆盖普通商品期货（RB/M/MA/C 等），低门槛立即可上。
- **QMT 通道**：覆盖商品期权（RB 期权/M 期权等）+ 未来股票账户（资金到位后）。

## 1. 范围

## 2. 架构（v2.0：统一网关进程架构）

### 2.1 架构决策：为什么两个通道都用"网关进程 + HTTP"

| 方案 | 描述 | 取舍 | 结论 |
|---|---|---|---|
| A. 库内直连 | qhyc 主应用直接 `import vnpy_ctp` / `xtquant` | ❌ xtquant 是 Windows 库，容器是 Linux，**根本装不上**；vnpy 事件循环与 APScheduler 冲突 | 否决 |
| B. **统一网关进程**（采用） | 两通道各跑一个网关进程，qhyc 侧均为 HTTP 客户端 | ✅ 架构对称、`broker_ctp.py`/`broker_qmt.py` 可共用基类；隔离第三方库（vnpy/xtquant）与 C++ 依赖；故障域隔离 | **采用** |
| C. RPC/消息队列 | gRPC / Redis Stream 替代 HTTP | 延迟更低但引入新依赖；本层 ≥100ms 容差 HTTP 足够 | 备选（未来高频再升级） |

| 术语 | 定义 |
|---|---|

### 4.1 对 PRD_P0-1 的三个实盘硬缺口（必须补）

| # | 缺口 | 影响 | 补法 |

### 4.2 ExecutionOrder → CTP 报单字段映射

CTP 报单结构：`CThostFtdcInputOrderField`（vnpy 侧抽象为 `OrderRequest`）。

| qhyc 字段（`ExecutionOrder`） | CTP / vnpy 字段 | 转换规则 |
|---|---|---|
| `real_symbol`（例 `FG2701`） | `InstrumentID` | **必须 `symbol_code.to_native(sym, exchange)`**：CZCE→`FG701`（3位）；SHFE/DCE/GFEX/INE→`rb2610`（小写）；CFFEX→`IF2609`（不变） |
| `exchange`（`SHFE` 等） | `ExchangeID` | 大写直传；CTP 可从 InstrumentID 推断，但显式传更稳 |
| `direction`（`LONG`） | `Direction` | `LONG`→`THOST_FTDC_D_Buy`；`SHORT`→`THOST_FTDC_D_Sell` |
| **`action`（新增，G1）** | `CombOffsetFlag` | `OPEN`→`THOST_FTDC_OF_Open`；`CLOSE`→`OF_Close`；`CLOSETODAY`→`OF_CloseToday`；`CLOSEYESTERDAY`→`OF_CloseYesterday` |
| — | `CombHedgeFlag` | 固定 `THOST_FTDC_HF_Speculation`（投机）；套保账户才改 |
| `price` | `LimitPrice` | 原始价（P0-1 已反解）；须 tick 对齐 |
| `lots` | `VolumeTotalOriginal` | 整数手（≥1） |
| — | `OrderPriceType` | 限价=`THOST_FTDC_OPT_LimitPrice`；市价=`OPT_AnyPrice`（仅止损平仓用） |
| — | `TimeCondition` | 限价=`THOST_FTDC_TC_GFD`（当日有效）；市价/FAK=`TC_IOC` |
| — | `VolumeCondition` | 限价=`THOST_FTDC_VC_AV`（任意数量）；FOK=`VC_CV` |
| — | `MinVolume` | 固定 `1` |
| — | `ContingentCondition` | 固定 `THOST_FTDC_CC_Immediately` |
| — | `ForceCloseReason` | 固定 `THOST_FTDC_FCC_NotForceClose` |
| — | `IsAutoSuspend` / `UserForceClose` | 固定 `0` |
| — | `OrderRef` | **qhyc 生成**：12 位内数字字符串，单调递增（CTP 用 (FrontID, SessionID, OrderRef) 三元组唯一定位订单） |

**vnpy 抽象层**（若用 vnpy `OrderRequest`）：
```python

    symbol="FG701.CZCE",      # 原生码 + 交易所后缀
    exchange=Exchange.CZCE,
    direction=Direction.LONG,
    type=OrderType.LIMIT,     # LIMIT / MARKET / FAK / FOK
    volume=3,
    price=3112.0,
    offset=Offset.OPEN,       # OPEN / CLOSE / CLOSETODAY / CLOSEYESTERDAY
    reference="qhyc_<order_id>",
)
```

### 4.3 开平标志解析规则（§4.1 G1 落地）

实盘 `action` 由 `position_manager` 推导，规则：

| 信号方向 | 当前持仓 | 推导 `action` | 说明 |
|---|---|---|---|
| `LONG` | 0（空仓） | `OPEN` | 新开多 |
| `LONG` | >0（已多） | —（不动作或加仓，见 §5.2） | 已持多，重复开多需按加仓规则 |
| `LONG` | <0（持空） | `CLOSE` + 反向 `OPEN` | 先平空（买平），再开多 |
| `SHORT` | 0 | `OPEN` | 新开空 |
| `SHORT` | <0 | — | 已持空 |
| `SHORT` | >0 | `CLOSE` + 反向 `OPEN` | 先平多（卖平），再开空 |
| `FLAT` | ≠0 | `CLOSE` | **平掉该品种全部持仓** |
| `FLAT` | 0 | — | 无持仓，不动作 |

**平今/平昨细分**（按交易所）：

| 交易所 | 平仓 `action` | 依据 |
|---|---|---|
| SHFE（上期）、INE（能源）、CFFEX（中金） | 今仓→`CLOSETODAY`；昨仓→`CLOSEYESTERDAY` | 交易所强制区分 |
| DCE（大商）、CZCE（郑商）、GFEX（广期） | 统一 `CLOSE` | 不区分今昨 |

```python
def resolve_close_action(exchange: str, today_vol: int, yesterday_vol: int) -> list[tuple[str,int]]:
    """返回 [(action, volume), ...]，可能拆成两笔（先平今再平昨或反之）。"""
    if exchange in ("SHFE", "INE", "CFFEX"):
        out = []
        if today_vol > 0:     out.append(("CLOSETODAY", today_vol))
        if yesterday_vol > 0: out.append(("CLOSEYESTERDAY", yesterday_vol))
        return out
    return [("CLOSE", today_vol + yesterday_vol)]
```

> ⚠️ **平今手续费**：上期所部分品种平今手续费极高（如某些品种平今万分之 N），`resolve_close_action` 的拆单顺序会影响成本。**默认先平昨后平今**（成本更低），可在配置 `CLOSE_SEQ` 切换。

**两通道 `action` 转换对照**（同一 `OrderIntent` 在不同通道的落地差异）：

| 场景 | CTP 落地 | QMT 落地 |
|---|---|---|
| 开多 3 手 | 1 笔：`Direction=Buy` + `OF_Open` | 1 笔：`FUTURE_OPEN_LONG` |
| 平多（上期，今 1 昨 2） | **拆 2 笔**：`CLOSETODAY` 1 手 + `CLOSEYESTERDAY` 2 手 | **1 笔即可**：`FUTURE_CLOSE_LONG_HISTORY_FIRST`(先平昨)；或拆 2 笔用六键精确控制 |
| 平多（大商，共 3 手） | 1 笔：`CLOSE` 3 手 | 1 笔：`FUTURE_CLOSE_LONG_HISTORY_FIRST` 或六键 |
| **反手（多→空 3 手）** | **拆 2 笔**：平多 3 手 + 开空 3 手 | **1 笔组合键**：`FUTURE_CLOSE_LONG_TODAY_HISTORY_THEN_OPEN_SHORT` |

> 💡 **实现建议**：`OrderIntent` 设计为 `list`（支持拆单），`broker_ctp` 按 CTP 规则拆分，
> `broker_qmt` 优先用组合键合并（少一次往返 + 少一次滑点）。二者对上层透明。

|---|---|---|
| `real_symbol` | `stock_code` | **格式待实测**（§4.4），如 `RB2510.SHF` 或 `rb2510.SHFE` |
| `direction` | `order_type` | `LONG`→`xtconstant.STOCK_BUY`；`SHORT`→`xtconstant.STOCK_SELL` |
| `lots` | `order_volume` | 整数手（期货按手；QMT 是否有 100 的倍数限制待实测） |
| — | `price_type` | 限价=`xtconstant.FIX_PRICE`；市价=`xtconstant.LATEST_PRICE`（或 `MARKET_PEER_PRICE_FIRST_CLASS`，仅深市） |
| `price` | `price` | 限价时必填 |
| — | `strategy_name` | 固定 `"qhyc"`（便于券商端归因） |
| `order_id` | `order_remark` | **qhyc 侧 UUID 写入备注**，用于异步回执反查（关键！QMT 回调只给 order_id） |
| **开平** | **`order_type` 内建** | ✅ **已确认支持**（见下方 T3.0 结论）：开平语义编码在 `order_type` 枚举里，**不是独立参数** |

### ✅ T3.0 结论（2026-10-02 23:30 已确认，**风险 R1 解除**）

**原疑点**：`order_stock()` 签名无 `offset` 参数 → 怀疑 QMT 不支持期货开平。
**结论**：**完全支持**。开平语义编码在 **`order_type` 枚举**中；`offset_flag` / `direction` 是**回报结构字段**（`XtOrder`/`XtTrade`/`XtPosition`），用于确认而非下单传参。
**依据**：迅投官方 XtQuant 文档 `dict.thinktrader.net/nativeApi/xttrader.html` 版本历史 2023-10-20 条目 + 枚举常量页 `innerApi/enum_constants.html` + 第三方 xtquant skill 交叉验证（三源一致）。

**期货 `order_type` 枚举（六键，推荐直接用）**：

| 常量 | 值 | 含义 | 对应 qhyc `action` |
|---|---|---|---|
| `FUTURE_OPEN_LONG` | 0 | 开多 | OPEN + LONG |
| `FUTURE_CLOSE_LONG_TODAY` | 1 | 平今多 | CLOSETODAY + LONG |
| `FUTURE_CLOSE_LONG_HISTORY` | 2 | 平昨多 | CLOSEYESTERDAY + LONG |
| `FUTURE_OPEN_SHORT` | 3 | 开空 | OPEN + SHORT |
| `FUTURE_CLOSE_SHORT_TODAY` | 4 | 平今空 | CLOSETODAY + SHORT |
| `FUTURE_CLOSE_SHORT_HISTORY` | 5 | 平昨空 | CLOSEYESTERDAY + SHORT |

**四键 / 两键（战略价值：可减少下单笔数）**：
- 四键：`FUTURE_CLOSE_LONG_TODAY_FIRST`(6) 平多优先平今、`..._HISTORY_FIRST`(7) 平多优先平昨、`FUTURE_CLOSE_SHORT_TODAY_FIRST`(8)、`..._HISTORY_FIRST`(9)
- 两键：`FUTURE_OPEN`(14) 买入不优先平仓、`FUTURE_CLOSE`(15) 卖出不优先平仓
- **反手组合键**：`FUTURE_CLOSE_LONG_TODAY_HISTORY_THEN_OPEN_SHORT`(10) 卖出→优先平多（先今后昨）→余量开空

> 💡 **架构优化（v2.1）**：`position_manager` 的反手信号（LONG→SHORT）**不必拆成 2 笔单**，可用组合键 `..._THEN_OPEN_...` 一笔完成（少一次网络往返、少一次滑点）。CTP 无此能力仍需拆两笔 —— **故 `OrderIntent` 保留 `list` 形态**，QMT 侧合并、CTP 侧拆分。

**商品期权 `order_type` 枚举**：
| 常量 | 含义 |
|---|---|
| `STOCK_OPTION_BUY_OPEN`(50) | 买入开仓 |
| `STOCK_OPTION_SELL_CLOSE`(51) | 卖出平仓 |
| `STOCK_OPTION_SELL_OPEN`(52) | 卖出开仓 |
| `STOCK_OPTION_BUY_CLOSE`(53) | 买入平仓 |
| `STOCK_OPTION_COVERED_OPEN`(54) / `COVERED_CLOSE`(55) | 备兑开/平仓 |

**回报确认字段**（用于状态机校验，不是下单参数）：
- `offset_flag`：48=开、49=平、51=平今、52=平昨、50=强平
- `direction`：48=多、49=空（股票无此字段）

**其他确认项**：
- 期货账号：`StockAccount('资金账号', 'FUTURE')`
- 委托状态枚举：48 未报 / 50 已报 / 55 部成 / 56 已成 / 54 已撤 / 57 废单（映射 §6.1 状态机）
- ⚠️ **市价单限制**：官方注明"**期货市价类型仅实盘生效，模拟环境不支持**" → 软件止损（§5.4）在 QMT 仿真环境需改用超价限价单验证；CTP/SimNow 不受此限
- 期货代码格式：官方示例 `ag2407`（原生小写码）**与 `to_native()` 输出一致**；是否带交易所后缀（如 `ag2407.SF`）**仍需实测**（见 §13 T3.1）

## 6. 状态机与时序

### 6.1 订单状态转换表

| 当前 | 事件 | 下一状态 | 动作 |
|---|---|---|---|
| — | `create_order` | `DRAFT` | 落库 |
| `DRAFT` | `send_order` 成功 | `SUBMITTED` | 记录 `broker_order_id` |
| `DRAFT` | `send_order` 业务失败 | `REJECTED` | 记 `error_msg`；**不重试** |
| `DRAFT` | `send_order` 网络异常 | `DRAFT` | 重试 2 次；均失败 → `REJECTED` |
| `SUBMITTED` | 回报 `NoTradeQueueing`（未成交排队） | `SUBMITTED` | 仅刷新 `updated_at` |
| `SUBMITTED` | 回报 `PartTradedQueueing` | `PARTIAL` | `filled_volume += n` |
| `PARTIAL` | 回报 `PartTradedQueueing`（累计=总量） | `FILLED` | 记 `avg_fill_price` |
| `SUBMITTED`/`PARTIAL` | 回报 `AllTraded` | `FILLED` | 终态 |
| `SUBMITTED`/`PARTIAL` | 回报 `Canceled` | `CANCELLED` | 终态 |
| `SUBMITTED`/`PARTIAL` | 回报 `Error`（错误码） | `REJECTED` | 记 `error_code`/`error_msg` |
| `SUBMITTED`/`PARTIAL` | 主动 `cancel` 成功 | `CANCELLED` | 终态 |
| **终态**（FILLED/CANCELLED/REJECTED） | 任何回报 | **保持不变** | 🚨 **终态保护，防止晚到回报覆盖** |

### 6.2 超时与探查

| 场景 | 阈值 | 探查动作 |
|---|---|---|
| 报单后无回报 | 30s | `query_order(broker_order_id)` |
| 撤单后无回报 | 15s | `query_order` |
| 网关无心跳 | 60s | 告警 + 标记通道不可用 |
| 探查仍无结果 | 3 次（累计 90s） | 告警 + 人工介入（**绝不自动重发**） |

> 🚨 **绝对禁止**：超时后自动重发报单。网络超时不代表未成交，重发 = 重复成交。所有可疑订单走人工确认。

### 6.3 并发与 race condition

| 风险 | 解法 |
|---|---|
| 撤单与成交同时到达 | 终态保护（§6.1）+ 状态更新用 `UPDATE ... WHERE status IN ('SUBMITTED','PARTIAL')` 条件更新 |
| 两个作业同时处理同一订单 | `SELECT ... FOR UPDATE` 行锁（单条订单处理时锁定） |
| 回调与轮询同时更新 | `apply_state` 内部按 `(order_id)` 加锁（Python `threading.Lock` + DB 事务） |
| 网关重启后回报丢失 | 网关启动时全量 `ReqQryOrder` + `ReqQryTrade` 补拉，与本地比对 |

### 6.4 断电/重启恢复

```
qhyc 重启
  ├─ 加载 DRAFT/SUBMITTED/PARTIAL 订单
  ├─ 逐条 query_order 探查真实状态
  ├─ 已成交/已撤 → 推进到终态
  └─ 状态不明 → 保持原状 + P0 告警（人工确认）

网关重启
  ├─ CTP：重新 authenticate → login → 结算单确认 → 全量 ReqQryOrder/Trade 补拉
  ├─ QMT：读 SQLite pending 订单 → query_stock_orders 探查 → push 回 qhyc
  └─ 恢复完成前，/health 返回 connected=false（qhyc 侧暂停下发新单）
```

## 7. 错误处理与重试

### 7.1 CTP 常见错误码 → 处置

| 错误码/类别 | 含义 | 处置 | 重试 |
|---|---|---|---|
| `-1` | 网络连接失败 | 重连 | ✅ 是（限 3 次） |
| `-2` | 未处理请求超限 | 降频（sleep 后重试） | ✅ 是 |
| `-3` | 每秒请求超限 | 降频 | ✅ 是 |
| `3` | 客户端未认证 | 重跑 `ReqAuthenticate` | ✅ 是 |
| `7` | 结算单未确认 | `ReqSettlementInfoConfirm` | ✅ 是（一次） |
| `21` | 报单字段错误 | `REJECTED` + 记 error_msg | ❌ 否 |
| `26` | **资金不足** | `REJECTED` + **P1 告警**（可能需入金） | ❌ 否 |
| `27` | **持仓不足**（平仓超量） | `REJECTED` + **P1 告警**（持仓快照不一致，触发对账） | ❌ 否 |
| `28` | 合约不存在/非交易状态 | `REJECTED` | ❌ 否 |
| `31` | **价格超出涨跌停** | `REJECTED` + 告警 | ❌ 否 |
| `47` | 平今仓位不足 | `REJECTED` + 对账 | ❌ 否 |
| `CTP:Query` 超时 | 查询无响应 | 重连后重查 | ✅ 是 |

### 7.2 QMT 错误处理

| 现象 | 含义 | 处置 |
|---|---|---|
| `order_stock()` 返回 `-1` | 提交失败 | 读 `XtOrderError.error_msg`；记 `REJECTED` |
| `connect()` 返回非 0 | MiniQMT 未登录/未启动 | **看门狗告警 + 尝试拉起客户端** |
| 回调超时 | 异步回执丢失 | 60s 后 `query_stock_orders` 兜底 |

### 7.3 重试策略总表

| 操作 | 最大重试 | 间隔 | 幂等键 |
|---|---|---|---|
| 报单 | 0（业务）/ 2（网络） | 0.5s, 1.5s | `order_id` |
| 撤单 | 2 | 0.5s, 1.5s | `broker_order_id` |
| 查询 | 3 | 1s, 2s, 4s | — |
| 连接 | 5 | 指数退避 1→30s | — |

## 9. 数据依赖与 DDL

```sql
-- db/init/013_execution_channels.sql

CREATE TABLE IF NOT EXISTS execution_order (
    order_id            UUID PRIMARY KEY,
    broker              TEXT NOT NULL CHECK (broker IN ('ctp','qmt')),
    account_id          TEXT NOT NULL,
    real_symbol         TEXT NOT NULL,          -- 标准码 FG2701
    native_symbol       TEXT NOT NULL,          -- CTP/QMT 原生码 FG701 / rb2610
    exchange            TEXT NOT NULL,
    direction           TEXT NOT NULL CHECK (direction IN ('LONG','SHORT')),
    action              TEXT NOT NULL DEFAULT 'OPEN'
        CHECK (action IN ('OPEN','CLOSE','CLOSETODAY','CLOSEYESTERDAY')),
    price               NUMERIC(12,4) NOT NULL,
    price_type          TEXT NOT NULL DEFAULT 'LIMIT' CHECK (price_type IN ('LIMIT','MARKET')),
    lots                INTEGER NOT NULL CHECK (lots > 0),
    status              TEXT NOT NULL DEFAULT 'DRAFT'
        CHECK (status IN ('DRAFT','SUBMITTED','PARTIAL','FILLED','CANCELLED','REJECTED')),
    broker_order_id     TEXT,
    filled_volume       INTEGER NOT NULL DEFAULT 0 CHECK (filled_volume >= 0),
    avg_fill_price      NUMERIC(12,4),
    error_code          TEXT,
    error_msg           TEXT,
    submitted_at        TIMESTAMPTZ,
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    raw_payload         JSONB,
    -- 幂等：同一 order_id 只处理一次；网关侧去重键
    CONSTRAINT uq_execution_order_broker UNIQUE (broker, broker_order_id)
);
CREATE INDEX IF NOT EXISTS ix_eo_status_updated ON execution_order (status, updated_at);
CREATE INDEX IF NOT EXISTS ix_eo_symbol        ON execution_order (real_symbol, submitted_at);

CREATE TABLE IF NOT EXISTS execution_position (
    symbol              TEXT NOT NULL,
    exchange            TEXT NOT NULL,
    direction           TEXT NOT NULL CHECK (direction IN ('LONG','SHORT')),
    volume              INTEGER NOT NULL DEFAULT 0,
    today_volume        INTEGER NOT NULL DEFAULT 0,
    yesterday_volume    INTEGER NOT NULL DEFAULT 0,
    avg_price           NUMERIC(12,4),
    stop_price          NUMERIC(12,4),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (symbol, exchange, direction)
);

CREATE TABLE IF NOT EXISTS broker_config (
    broker_name         TEXT PRIMARY KEY,
    broker_type         TEXT NOT NULL CHECK (broker_type IN ('ctp','qmt')),
    env                 TEXT NOT NULL,          -- simnow / paper / live_xxx
    config_json         JSONB NOT NULL,         -- 敏感字段加密（见下）
    enabled             BOOLEAN NOT NULL DEFAULT FALSE,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**敏感字段加密**：`config_json` 内 `password` / `auth_code` / `investor_id` 用 Fernet 加密，密钥从 `.env` 的 `EXECUTION_SECRET_KEY` 读取。**禁止明文落库、禁止进 git**。

## 12. 运维 runbook（故障处置）

| 故障 | 现象 | 处置步骤 |
|---|---|---|
| **CTP 网关连不上** | `/health` false，错误码 -1 | ①查前置地址是否变更（期货公司可能换）；②查网络/防火墙；③查结算单未确认（错误码 7）；④重启网关容器 |
| **MiniQMT 掉线** | bridge 心跳丢失 | ①`tasklist` 查 MiniQMT 进程；②未启动则拉起；③已启动但连不上 → 检查是否需重新登录（券商可能踢下线）；④重连后 bridge 自动补拉 |
| **订单状态不明** | 超时 90s 无回报 | ①`query_order` 查；②仍无 → 登录期货公司柜台**人工确认**；③**禁止自动重发** |
| **持仓对账差异** | DB ≠ broker | ①人工核对两边；②以 broker 为准修正本地；③查差异来源（漏记回报？移仓？） |
| **疑似重复成交** | 同一意图成交两次 | ①立即平掉多余仓位；②查幂等键是否失效；③**事后必须复盘**（重复成交可能瞬间放大风险暴露） |
| **涨跌停无法平仓** | 错误码 31 | ①改挂对手价限价单排队；②持续无法成交 → 人工电话下单 |
| **资金不足（26）** | 开仓被拒 | ①告警；②查保证金占用；③减仓或入金 |
