# 期货数据入库逻辑与纠错说明（供 workbuddy 纠正用）

> 本文件用于纠正一个常见误解：**"Docker 内入库的期货数据全部是 akshare 获取的、且已经完成了复权"**。
> 结论：日线/小时线的**原始主连+其他合约**确实主要源于 akshare，但**复权数据并非 akshare 做的**，而是用 **tqsdk（天勤）** 重建的，且**没有接入自动调度**。

---

## 一、结论先行（重点纠错）

| 判断 | 实际情况 |
|---|---|
| 日线来自 akshare（主连） | ✅ `daily_bar` 主连由 `ak.futures_main_sina` 拉取 |
| 日线来自 akshare（其他合约） | ✅ `contract_daily` 由 `ak.futures_zh_daily_sina` 拉取（CZCE 走 tqsdk 兜底） |
| 小时线来自 akshare（主连） | ✅ `hourly_bar` 由 `ak.futures_zh_minute_sina(period="60")` 拉取 |
| 数据"完成了复权" | ❌ **akshare 拉来的主连是"拼接但未复权"的**。真正的复权（加法平移前复权）是**用 tqsdk（天勤）原始主连+具体合约重建**的，来源不是 akshare |
| 复权进了自动调度 | ❌ fdf 复权脚本**未接进 scheduler**，需手动/另排触发；`daily_bar` 里的主连价本身就是未复权拼接价 |

**关键证据**：`app/ingest/fdf/build_continuous.py` 第一行注释明确写"把未复权的**天勤主连 / 具体合约**重建为复权主连（加法平移前复权）"——复权锚点来自天勤(tqsdk)，不是 akshare。

---

## 二、数据入库的三条独立路径

### 路径 A：Docker 内在线抓取（scheduler 自动跑，akshare 主源 + tqsdk 兜底）

**(a) 主连日线 — akshare `futures_main_sina`**（`app/ingest/akshare_source.py`）

```python
@staticmethod
def to_sina_symbol(symbol: str) -> str:
    # FG888 → FG0（新浪主连 = 品种 + 0）
    p = symbol.upper()
    if p.endswith("888"):
        return p[:-3] + "0"
    return p

def _call_akshare(self, symbol, start, end):
    import akshare as ak
    sina_symbol = self.to_sina_symbol(symbol)
    df = ak.futures_main_sina(symbol=sina_symbol)   # ← akshare 主连日线（拼接未复权）
    # 按 日期 过滤 start/end，列映射见 utils.normalize_ak_daily
```

归一化 + 涨跌幅：`app/ingest/utils.py` 的 `normalize_ak_daily` 与 `attach_returns`。

**(b) 其他合约日线 — akshare `futures_zh_daily_sina`（CZCE 走 tqsdk）**（`app/ingest/contract_bars.py`）

- 数据源矩阵 + `fetch_sina_contract_daily`（`ak.futures_zh_daily_sina`）
- `fetch_tqsdk_contract_daily`（CZCE 兜底，用 tqsdk）
- 入库 `upsert_contract_daily`

**(c) 主连小时线 — akshare `futures_zh_minute_sina`（period="60"）**（`app/ingest/hourly_collector.py`）

```python
def _fetch_akshare(self, spec):
    import akshare as ak
    sina = AkShareSource.to_sina_symbol(spec.symbol)
    df = ak.futures_zh_minute_sina(symbol=sina, period="60")  # ← akshare 60分钟线
    ...
```

tqsdk 兜底：`_fetch_tqsdk`（`api.get_kline_serial(KQ.m@{ex}.{prod}, 3600)`）。

**(d) 校准 / 缺失补缺 — tqsdk**（`app/ingest/tqsdk_calibrator.py`）

- `fetch_daily`（`KQ.m@{ex}.{prod}`）
- `fill_missing`（按交易日历差集补 `daily_bar`，`src='tqsdk'`）
- `compare_and_ticket`（偏差>0.5% 生成 `anomaly_ticket`，**只留工单不自动覆盖**）

**(e) 调度编排**

- 编排器 `app/ingest/orchestrator.py` `ingest_symbol`：先 akshare 入库 → 再 tqsdk 补缺+比对（校准失败不阻塞主源）。
- 调度 `app/scheduler.py` `_build_scheduler`：每天 `12:00 / 16:00 / 次日08:00` 跑 `_ingest_job`（`ingest_all()` + 收盘后 `HourlyCollector.collect_all()`）；融合策略每 15 分钟 `_fusion_scan_job` 补采小时线。

### 路径 B：CSV/JSON 本地导入（手动，非自动）

`app/ingest/local_importer.py` 从容器挂载 `/app/imports`（docker-compose 绑定的 `E:\QH`）读取：

| 文件 | → 表 | 性质 |
|---|---|---|
| `{P}_daily.json` | `main_continuous.raw_*` | 原始主连 |
| `{P}_cont_adj.json` | `main_continuous.adj_*` | **复权主连日线** |
| `{P}_rolls.csv` | `main_contract_map` | 换月+delta |
| `{P}_contracts.json` | `daily_bar` | 全合约日线 |
| `{P}_cont_adj_adjusted.csv` | `hourly_bar` | **复权主连小时线** |

> 注意：`app/main.py` 启动只做 `sync_symbols`，**不自动跑 CSV 导入**，需手动 `python -m ... import_local` 或调用 API。

### 路径 C：复权重建（fdf 技能，tqsdk 源，**未接入 scheduler**）

- `app/ingest/fdf/build_continuous.py`：核心复权 `build_adjusted_from_frames`（`additive-shift 前复权`，选主力 `pick_dominant` 按持仓量，换月日 `delta=新合约(t-1)收−旧合约(t-1)收`，整段平移）。
- `app/ingest/fdf/adjust_fdf.py`：把复权主连写回 `fut_kline`（`kind='cont_adj'`，日线/小时线/15min 三频）；手动触发 `python -m app.ingest.fdf.adjust_fdf CZCE.FG --freq hourly`。
- `app/ingest/smooth_extender.py` `extend_smooth_series`：从 CSV 末日 `adj_close` 锚点，用 **tqsdk 候选合约**把复权序列延伸到最新（`src='csv_smooth_ext'`，也是 tqsdk 源）。

## 三、入库逻辑及说明

### 目标表与口径

| 表 | 主键 | 内容 | 数据源 | 是否复权 |
|---|---|---|---|---|
| `daily_bar` | (symbol, trade_date) | 主连日线 | akshare+tqsdk+csv | ❌ 拼接未复权 |
| `contract_daily` | (symbol, trade_date, version) | 其他合约日线 | akshare(DCE/SHFE/INE/GFEX)+tqsdk(CZCE) | ❌ |
| `hourly_bar` | (symbol, trade_datetime) | 主连小时线 | akshare+tqsdk+csv | ❌（csv 那份是复权） |
| `main_continuous` | (product, trade_date) | `raw_*` 原始 + `adj_*` 复权 | csv + smooth_ext(tqsdk) | `adj_*`: ✅ |
| `fut_kline` | (freq, kind, symbol, trade_datetime) | `kind='cont_adj'` 复权主连 | fdf(tqsdk) | ✅ |
| `main_contract_map` | (trade_date, exchange, product) | 换月映射+delta | csv + inferred(tqsdk) | — |

### 入库机制（正确性）

- 全部走 PostgreSQL `INSERT ... ON CONFLICT DO UPDATE` 幂等 upsert（`app/repositories/_base.py` 的 `upsert_daily_bars`、`upsert_hourly_bars`），按主键冲突即覆盖，重复跑安全。
- `hourly_bar` 入库前 `upsert_hourly_bars` 做了去重 + 剔除 1970/NaN 脏行（tqsdk 回填空槽位会落在同一时间戳，避免 `CardinalityViolation`）。
- 大批量按列数自动分块（psycopg3 参数上限 65535）。

### 关于"数据是否完整"的提醒

1. **主连日线/小时线、其他合约日线**：在线路径完整且健壮（akshare 主源 + tqsdk 兜底 + 缺失补缺 + 异常工单），这是正确的。
2. **复权数据不完整风险**：`daily_bar` 里存的是**未复权拼接价**；真正的复权序列在 `main_continuous.adj_*` / `fut_kline`，但 fdf 复权**没接进 scheduler**，也不会在 `app/main.py` 启动自动跑——若没手动执行 `adjust_fdf` 且没放好 `*_cont_adj*.csv`，则复权数据为空/滞后。
3. **`daily_bar` 只有主连**：全合约日线只通过 CSV 导入（`_contracts.json`）或 fdf 进来；单跑 scheduler 不会把每个合约写进 `daily_bar`。
4. **小时线历史覆盖**：akshare `futures_zh_minute_sina` 通常只回近期窗口（数月~1年），长历史依赖 tqsdk 兜底或预导入 CSV。

## 四、给 workbuddy 的纠正要点（一句话版）

- 不要假设 `daily_bar` / `hourly_bar` 中的主连价格是**复权价**；它们是 akshare 新浪主连的**拼接未复权价**。
- 复权口径只在 `main_continuous.adj_*` 与 `fut_kline(kind='cont_adj')`，且**由 tqsdk（天勤）重建**，与 akshare 无关。
- 复权生成（`adjust_fdf`）不在自动调度里，需要显式执行；若要做"akshare 全量且已复权"，当前架构做不到（复权锚点必须来自天勤）。
- 若要让复权自动维护，应把 `adjust_fdf` 接入 `app/scheduler.py` 的 `_ingest_job`，或改为基于 akshare 主连价自算换月 delta 复权。
