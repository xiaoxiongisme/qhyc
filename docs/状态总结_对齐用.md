## 2. 未完成 / 需你（用户）裁定

### 2.1 【高】复权缺口：3 个主品种未复权
`INE.sc`（原油）、`SHFE.ru`（橡胶）、`SHFE.sn`（锡）**缺 hourly cont_adj**。
- **根因（已实测定位）**：复权门槛 `RELIABLE_OI = 100_000` 手 + 连续 20 日达标（`build_continuous.py:31-32`）。原油/橡胶/锡单合约持仓量长期 < 10 万手，识别不出"可靠主力区间"，`_build_adjusted_hourly` 直接抛 `没有任何区间主力持仓量达标，无法复权`。
- **裁定选项**：
  - A）对低 OI 品种**按品种设可调阈值**（推荐，改动小、不影响其他品种）；
  - B）**改用成交量选主力**而非持仓量（原油等成交量更稳）；
  - C）接受这 3 个品种不进复权。

### 2.2 【高】复权未接入自动调度
`adjust_fdf` 只能手动 `python -m app.ingest.fdf.adjust_fdf ...` 跑；`app/scheduler.py` 的 `_ingest_job` **不触发复权**。是否把复权收尾接入调度（建议放在每日收盘采集之后）？

### 2.3 【高】两套数据口径并存，需定"权威源"
- `hourly_bar` / `daily_bar` / `contract_daily`：**akshare 口径，未复权拼接价**，是主采集链路产物。
- `fut_kline`（continuous/contract/cont_adj）：**天勤口径，含复权**，是 fdf 技能产物。
- PRD 写明"权威主连 = csv_smooth 主连"，但 **CSV 导入（`local_importer`）当前未跑**，那条口径是空的。
- **需裁定**：线上喂模型/看板到底以哪套为准？避免 codebuddy 与 workbuddy 各自接不同表。

### 2.4 【中】akshare `hourly_bar` 覆盖偏稀
73 品种但平均每品种仅 ~2400 根，远非"1 万根"。若上层需要 akshare 小时线历史，需补采（tqsdk 兜底或预导入 CSV）。**先确认 §2.3 选哪套口径**，再决定要不要补。

### 2.5 【中】部分 cont_adj 已陈旧
如 `CZCE.AP` 仅 490 根 vs 主连 10000、`CZCE.MA` 3534 vs 10000 —— 旧复权数据未对齐当前主连。建议复权缺口裁定后**对全部 57 品种统一重跑一次**（`adjust_all.py`）。

### 2.6 【紧急】git 基线 / 分工冲突
- 仅 1 次提交，全部未提交；`MM`/`AM` 文件两边都在改（见 §0）。
- **需立即**：先 `git commit` 建立共同基线（或各自开分支），否则两边互相覆盖。
