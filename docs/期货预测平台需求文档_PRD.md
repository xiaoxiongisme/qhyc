## 1. 项目概述与目标

构建一个**本地运行**的平台，存储国内期货全品种行情数据，并基于数学 / 统计 / 机器学习模型，预测下一交易日的涨跌方向与幅度。

核心能力：
1. **行情数据仓库**：日线先行，小时线后续；支持自动（定时）+ 手动更新；数据质量可校准。
2. **多模型预测引擎**：傅里叶、小波、ARIMA、GARCH、马尔可夫、HMM、贝叶斯、蒙特卡洛、LSTM、XGBoost 等，集成输出方向与幅度。
3. **可视化看板 + 回测验证**：浏览预测、对比模型、回测评估。

非目标（本期）：实盘下单、多用户账号体系、云端多租户（但架构按云端演进预留，见 §14）。

## 4. 数据层

### 4.1 数据源与校准（已确认）

- **主源 akshare**：免费，覆盖 CZCE / SHFE / DCE / CFFEX / INE 全品种日线 + 小时线。
- **校准源 tqsdk（天勤）**：行情质量高，用于**补缺**与**二次比对**。
- **tqsdk 账号**：已提供（手机号 + 密码），凭据存项目 `.env`，不写入文档 / git / 日志。
- **入库与校准流程**：
  1. akshare 按品种 + 区间拉取，按主键 `(symbol, trade_date)` upsert 入库。
  2. **缺失检测**：入库结果与交易日历比对，标记 akshare 缺失的交易日/品种。
  3. **tqsdk 补缺**：对缺失部分调用 tqsdk 拉取补齐入同一张表。
  4. **二次比对**：全量入库数据再用 tqsdk 拉取同区间比对（重点：收盘价、结算价、成交量）。
  5. **异常判定**：偏差超阈值（默认：收盘价差异 > 0.5%，或成交量异常缺失/翻倍）→ 生成**异常工单**记录。
  6. **异常处置**：在日志/看板给出提示，**由人工（用户）判断接受或修正，系统不自动覆盖**。异常工单包含：品种、日期、akshare 值、tqsdk 值、偏差、建议。
- **兜底**：支持手动导入用户已有本地历史数据（FG/SA 已有成套文件），导入同样走 tqsdk 比对；实际模板见 §4.5。
- 校准阈值、tqsdk 超时/重试参数放配置文件。
- 主力连续合约映射表（akshare 代码 ↔ tqsdk `KQ.m@EXCHANGE.CODE`）以配置维护，实现时内置常见品种。

### 4.2 更新策略

- **自动（每日三次，已确认）**：由 APScheduler 定时触发，针对**主力连续合约**：
  - 日盘午间 **12:00**（捕获上午盘）
  - 日盘收盘后 **16:00**（含当日完整日盘）
  - 夜盘次日早 **08:00**（捕获前一晚夜盘，夜盘约 02:30 收）
- **预测联动**：每次自动 / 手动更新入库完成后，立即对该批主力连续合约触发一次预测（即**一天三次预测**；三次统一预测**下一交易日**，12:00 为盘中快照版，08:00 为含夜盘修正版，见 ⑨）。
- **手动**：提供 API / 看板按钮，立即更新指定品种或全量，并更新后同样触发预测。
- **增量**：以 `(symbol, date)` 为主键 upsert，断点可续；失败重试 + 告警。
- **预测标的**：仅**主力连续合约**（如 FG888、SA888），不逐具体交割合约。
- **数据仓库范围**（⑧）：全品种**所有历史合约**日线都存（量小），主连由映射表合成，便于回溯换月。

### 4.3 数据模型（TimescaleDB 超表）

- `futures_symbol`（品种/合约元数据）：symbol, name, exchange, unit, multiplier, is_main, main_symbol, active
- `main_contract_map`：trade_date, exchange, product, main_symbol, change_flag（每日主连映射与换月标记）
- `daily_bar`（日线超表，time=trade_date）：symbol, trade_date, open, high, low, close, settle, volume, amount, oi(持仓), ret_close(收盘价涨跌幅%), ret_settle(结算价涨跌幅%), ret5, ret20, src(akshare/tqsdk/csv)
- `main_continuous`（主连表，⑪）：原始主连价 + 平滑主连价（换月比例拼接），模型特征默认取平滑
- `hourly_bar`（小时线超表，time=trade_datetime，二期）：symbol, trade_datetime, open, high, low, close, volume, oi, ret
- `trade_calendar`：exchange, trade_date, is_open, sessions(JSON，含日盘/夜盘分段) —— 用于缺失检测
- `prediction_result`：symbol, target_date, as_of_date, run_id, model_set, direction(涨/跌), direction_prob, ret_point(点估计%), ret_low(P5%), ret_high(P95%), confidence, participated_models(JSON)
- `backtest_result`：model, window, start, end, dir_acc, mae, rmse, quantile_hit, sample_n
- `anomaly_ticket`：symbol, trade_date, field, akshare_val, tqsdk_val, diff, threshold, status(待裁决/已接受/已修正/误报), note
- `briefing_signal`（对接简报引擎预留）：source, symbol, trade_date, direction, score, note, received_at

`daily_bar` / `hourly_bar` 建为 TimescaleDB 超表；`ret5/ret20` 可由连续聚合或写入时计算。

### 4.4 向前兼容设计（小时线 M6 预留，已确认按默认）

本期只落 `daily`，但**表空间与代码逻辑按可平滑扩展小时线设计**，M6 接入时不返工：

- **频率维度参数化**：`freq ∈ {daily, hourly}` 贯穿采集、校准（tqsdk）、特征、模型、预测、回测、API。新增小时线 = 加一张表 + 一个配置，不重写逻辑。
- **表结构同构**：`hourly_bar` 与 `daily_bar` 同构（仅 `time` 粒度不同），共用 `BarRepository` 抽象层（按 `freq` 路由表名）。
- **表空间 / 分块规划（TimescaleDB）**：
  - `daily_bar` chunk_time_interval = 3 个月；`hourly_bar` chunk_time_interval = 1 周（小时数据量大）。
  - 建议独立表空间：日线放主存储，小时线后续可挂大容量 / 压缩表空间（如 `ts_hourly`）。
  - 压缩策略：hourly 写入 7 天后转列存压缩；daily 30 天后压缩。
  - 连续聚合：`hourly_1d_rollup` 由小时线自动聚合出日线，作为日线校验 / 备用来源。
- **特征窗口以"根数"表达**：前 5 / 20 用"前 N 根 K 线"而非硬编码天数；小时线下自然对应前 5 / 20 小时，窗口长度放配置。
- **交易日历含 intraday 时段**：午休 11:30–13:30、夜盘 21:00–02:30 分段，供小时线缺失检测。
- **模型频率无关**：模型均作用于收益率序列，同一套模型库直接服务小时线预测；M6 仅补数据接入与校准（见 §10）。

## 5. 计算 / 预测引擎

### 5.1 特征工程

输入窗口：当日涨跌幅 + 前 5 / 前 20 根 K 线的涨跌幅序列（窗口以"根数"表达，见 §4.4），及衍生特征：
- 波动率（5/20 根标准差）、动量（ret5/ret20）、成交量变化率
- Hurst 指数、样本熵（可预测性）、ATR（波动）
- 你已有：Zigzag 拐点标记、Qi(ATR+MACD) 作为辅助信号/特征
- 涨跌幅口径：模型特征与预测目标统一用**结算价涨跌幅**（ret_settle，⑩）

### 5.2 模型库（按族，职责）

**变换类（与傅里叶同族）**
- 傅里叶变换：提取周期成分，给出周期性方向偏向
- 小波变换：多尺度周期 + 突变点检测，适合非平稳行情

**统计时序类**
- ARIMA / SARIMA：线性外推，输出方向与点估计幅度
- GARCH 族：波动率聚类，输出幅度/风险区间
- 卡尔曼滤波：状态估计 + 去噪，动态预测

**状态 / 概率类（与马尔可夫同族）**
- 马尔可夫链：基于历史状态转移矩阵，输出方向概率
- 隐马尔可夫 HMM：识别隐藏市场状态（牛/熊/震荡）
- 贝叶斯更新：随新数据修正方向后验概率
- 蒙特卡洛模拟：路径分布 → 涨跌概率 + 分位幅度

**机器学习 / 深度学习类**
- LSTM / GRU / Transformer：序列预测方向与幅度
- XGBoost / LightGBM / 随机森林：特征 → 方向分类 + 幅度回归
- 高斯过程回归：预测 + 不确定性区间

**复杂系统 / 信息论类**
- 赫斯特指数 Hurst：判定趋势 vs 均值回复，作为**状态门控**选择启用的模型子集
- 样本熵 / 近似熵：市场可预测性度量（低熵→模型更可信）
- 相空间重构 / RQA：非线性动力学特征

重训频率（⑱）：轻模型（ARIMA / 马尔可夫 / XGB 等）随预测在线更新；LSTM 每周重训一次。

### 5.3 集成机制

- **状态门控**：先用 Hurst 判定趋势 / 均值回复，选择启用模型子集（趋势市偏重 LSTM/ARIMA，震荡市偏重马尔可夫/均值回复类）。
- **方向投票**：各模型输出方向概率，加权投票（权重每月按近 60 日回测准确率更新，⑳）；起步为**涨/跌二分类**（⑫），震荡标签后期加。
- **幅度融合**：各模型幅度预测取分位融合（中位数点估计 + [P5, P95] 区间）。
- **输出规范（JSON，v1 契约，对接简报引擎复用）**：
  ```json
  {
    "schema_version": 1,
    "symbol": "FG888",
    "target_date": "2026-09-07",
    "as_of": "2026-09-06T16:05:00+08:00",
    "run_id": "20260906_1600",
    "direction": "up | down",
    "direction_prob": 0.62,
    "ret_point": 0.8,
    "ret_low": -0.5,
    "ret_high": 2.1,
    "confidence": 0.71,
    "participated_models": ["fourier","arima","markov","lstm"],
    "state": "trend|mean_revert"
  }
  ```

### 5.4 预测服务接口

- `POST /predict`：入参 `{symbol, as_of_date}` → 返回 §5.3 结构
- `POST /predict/batch`：批量预测全品种（用于看板热力图）
- 每次预测生成唯一 `run_id`，同一 `as_of` 多次运行可追溯

## 6. 回测引擎

- 输入：历史样本滚动窗口，逐日生成预测并与真实涨跌对比。
- 指标：方向准确率、幅度 MAE / RMSE、分位覆盖命中率、按品种 / 按市场状态（Hurst）分层。
- 用途：模型权重学习、策略评估、看板展示。
- 参数（⑲⑳）：滚动窗口 250 交易日；权重每月按近 60 日准确率更新。

## 9. 部署与运维（本地单机，Docker）

- 日志：采集 / 校准 / 异常分级记录，轮转保留

### 9.1 Docker 资源预估（已确认采用 Docker）

| 容器 | CPU | 内存 | 说明 |
|---|---|---|---|
| timescaledb | 1–2 核 | 2–4 GB | shared_buffers 1GB 起，数据量小 |
| python-api + scheduler | 1–2 核 | 1–2 GB | 采集/校准/轻模型推理 |
| web（nginx + React 静态） | 0.2–0.5 核 | 128–256 MB | 看板渲染，静态资源极轻 |
| 重型训练峰值（LSTM/XGBoost 重训） | 额外 4–8 核 | 额外 4–8 GB | 调度在空闲时段，可降频 |

- **日常运行推荐：4 核 / 8 GB / 50 GB SSD**
- 若每日全量重训深度模型：8 核 / 16 GB
- 最低可跑：2 核 / 4 GB（关闭深度重训，仅轻模型 + 采集 + 看板）
- 磁盘说明：日线全量极小（49 品种 × 10 年 ≈ 十几万行）；小时线 10 年 ≈ 百万行级，列存压缩后很小——**瓶颈在网络拉取时长与训练 CPU，不在存储**。

## 16. 需求增补（v1.2）：跨品种 / 跨大类传导预测

> 来源：用户需求（2026-09-07）。国内期货品种按大类划分（农产品、化工能源、黑色系、有色/新能源金属、贵金属等），**大类之间走势相对独立，大类内部相关性高**，且存在产业链上下游传导与相互制约——如原油→沥青/燃料油/PTA，铁矿石→螺纹钢/热卷，焦煤→焦炭→钢材，纯碱→玻璃（成本链），大豆→豆粕/豆油，豆粕↔菜粕（替代）。本节把"品种之间涨跌幅的传导"与"大类/品种权重"正式纳入预测因素。

### 16.1 分类与权重体系

- **新表 `sector_map`**：product, sector(大类), chain_role(上游/中游/下游), active。初始分类内置配置，覆盖全部目标品种，支持 CSV 覆盖。示例划分：
  - 黑色系：螺纹钢 RB、热卷 HC、铁矿石 I、焦煤 JM、焦炭 J、硅铁 SF、锰硅 SM、不锈钢 SS
  - 化工能源：原油 SC、燃料油 FU、低硫燃料油 LU、沥青 BU、PTA、乙二醇 EG、甲醇 MA、PP、塑料 L、PVC、苯乙烯 EB、纯碱 SA、玻璃 FG、尿素 UR、橡胶 RU、20号胶 NR、纸浆 SP、PX、烧碱
  - 农产品：豆一 A、豆二 B、豆粕 M、豆油 Y、棕榈油 P、菜粕 RM、菜油 OI、玉米 C、淀粉 CS、白糖 SR、棉花 CF、棉纱 CY、苹果 AP、红枣 CJ、花生 PK、生猪 LH
  - 有色/新能源金属：铜 CU、铝 AL、锌 ZN、铅 PB、镍 NI、锡 SN、氧化铝 AO、工业硅 SI、多晶硅 PS、碳酸锂 LC
  - 贵金属：黄金 AU、白银 AG
  - 金融期货（IF/IH/IC/IM/国债）默认**不纳入**本轮预测范围，配置开关可开
- **大类指数 `sector_index`**：板块内品种涨跌幅按权重合成日度指数；初始**成交额加权**（可配置等权）；成分变动留痕（composition JSON）。
- **品种在板块内权重**：用于大类指数合成与传导强度基准。
- **传导权重矩阵 `transmission_weights`**：src 品种 → dst 品种的方向、时滞档（当日/1日/5日）、权重值；三个来源融合（见 16.2）。

### 16.2 传导建模（三层）

1. **先验链路（配置）**：`transmission_config.yaml` 内置产业链先验，每条含方向、时滞档、强度档(0–1)、成本占比参考：
   - 成本链：原油→石脑油→PX→PTA；原油→燃料油/沥青；焦煤→焦炭→螺纹/热卷；铁矿石+焦炭→钢材；**纯碱→玻璃**；大豆→豆粕/豆油；玉米→淀粉
   - 替代/互补：豆粕↔菜粕；豆油↔棕榈油↔菜油（油脂板块内部）
   - 需求反馈：钢材↔铁矿石（下游需求→上游原料）
2. **数据驱动**：滚动 60/120 日相关系数、Granger 因果检验（滞后阶搜索 1/2/5）、**传递熵**（量化信息流强度与时滞）、VAR 脉冲响应。与先验融合：`w = 0.5×先验 + 0.5×数据`；样本不足时回落纯先验。
3. **层级预测**：先用同一模型库预测**大类指数**的方向/幅度，结果作为品种级特征（仅用 as_of 之前数据，防前视）。

### 16.3 特征工程扩展（全部使用滞后数据，防前视）

| 特征 | 含义 |
|---|---|
| `sector_ret_1d/5d/20d` | 所属大类指数动量 |
| `sector_excess` | 品种涨跌 − 大类涨跌（板块内强弱/背离） |
| `upstream_ret_lag1/lag5` | 权重 top-k（默认 k=3）上游品种的滞后涨跌幅 |
| `cost_gap` | 理论成本传导幅度（上游 ret × 成本占比系数）− 品种实际 ret（背离=信号） |
| `sector_corr_regime` | 板块内 60 日平均两两相关（高相关期传导更可信） |
| `te_topk` | 对本品种信息流最强的 top-3 品种近期方向 |

### 16.4 模型与集成影响

- VAR / Granger / 传递熵正式纳入 §5.2 模型库，新增"跨品种联动"族
- XGBoost / LSTM / 高斯过程等特征集统一加入 16.3 传导特征
- 集成投票机制不变；传导模型输出与单品种模型**同票参与**加权
- 防共线性：每品种仅取"大类指数 + top-k 上游"，不把整个板块塞入特征

### 16.5 数据层新增

- `sector_map`（分类与产业链角色）
- `sector_index`（大类指数，合成数据，无需 tqsdk 校验）
- `transmission_weights`（权重快照：method=prior/corr/granger/te, weight, lag_days, updated_at；**每周重算**，与 LSTM 周训对齐）

### 16.6 看板与对外契约

- 看板：单品种详情新增**"传导来源"卡片**（上游品种当日/5日涨跌 → 预期影响方向与幅度）；新增**大类热力图**与板块强弱排名
- 对外契约：v1 JSON 不变；**v2 预留 `drivers` 字段**（大类动量、top 上游影响、cost_gap 背离标记），保证简报引擎平滑升级

### 16.7 实现排期与注意事项

- **排期**：M2 = sector_map / sector_index / 静态先验传导特征（特征 v1）；M3 = 动态权重（Granger/传递熵/VAR）+ 层级预测 + 特征 v2；M5 = 看板传导卡片与大类热力图
- **注意**：①传导特征一律用滞后数据，严禁当期数据进特征（前视偏差）；②板块内高相关品种不重复入模（top-k + 大类指数）；③新品种/样本不足回落先验权重；④大类指数成分变动留痕；⑤权重每周重算一次，与 LSTM 周训对齐

### 18.12 风险与边界
- **净边际薄**：方向信号毛增益有限，须小仓位 + 严控成本；更适合"高置信子集增强"。
- **趋势大年失效**：反转在单边牛市（如 2021）弱化，可叠加 Hurst 状态过滤，但 v1 先保持简单。**（v1.3.5 实证更正：2024–2026 窗口内 `trend` 状态反而为正边沿——gate 2.0% 时 acc=0.5395；当前真正逆效的是 `mean_revert` 状态，acc 0.375–0.444，即反转在均值回复市遭遇"二次反转"。样本量偏小（mean_revert @gate2% 仅 n=8），仅作方向性提示。详见复核结论 §8.3。）**
- **截面多腿限制**：多空配对依赖做空与双边流动性，部分品种受限，不计入 v1 主信号。
- **阈值数据驱动**：门控阈值须年度重估，禁止硬编码 0.5628 等历史最优值。
- **研究方法学 / 生产口径差异（v1.3.3 新增；v1.3.5 更新）**：`research_m5_validate.py` 的 0.53 为**未施加平台 3 日 eval 抽样**的研究口径；生产回测引擎对 eval 点做 `step=3` 抽样。阈值对齐后（`gate_pct=2.0`，run `20260910_143938_bt`）生产**池化** `dir_acc = 0.5492`（显著），与研究 0.5368 同区间；此前的 0.5000 系 gate_pct=1.0% 错配所致，已作废。口径纪律：验收只用**池化（信号加权）**，`sample_n` 加权/宏平均仅作 ⑳ 权重输入。
- **验收阈值 ≠ 部署阈值（v1.3.3 新增；✅ 2026-09-10 v1.3.5 结案）**：research 选定 τ\*=2.0%（高置信子集，覆盖 12.9%），生产曾部署 `gate_pct=1.0%`（覆盖 35.75%）——**已按①对齐为 `gate_pct=2.0` 并全量重跑**（见 §18.11 结案段）。保留原则：**任何验收阈值与部署阈值必须一致**，改阈值须同步重跑验收，禁止用 A 阈值子集的效力为 B 阈值部署背书。

**`EXCHANGE_COVERAGE` 矩阵设计（解决 K1 一键扩展）**：在 `app/ingest/member_position.py`（或共享 config）声明**单点配置**，采集器仅遍历矩阵中 `active=True` 的交易所、按 `symbols` 拉取并写表；新增覆盖 = 改配置（翻转 flag / 补齐品种列表），**不触碰采集与入库逻辑**。akshare 修复 SHFE/DCE 后，扩展即「一键」。

```python
# app/ingest/member_position.py  (或 shared config)
EXCHANGE_COVERAGE: dict[str, dict] = {
    "CZCE":  {"func": get_rank_table_czce,       "active": True,  "symbols": "<郑商所主连列表>"},
    "CFFEX": {"func": get_cffex_rank_table,      "active": True,  "symbols": "<中金所主连列表>"},
    "DCE":   {"func": futures_dce_position_rank, "active": False,  # K1: 先穷尽 get_dce_rank_table / futures_dce_position_rank_other 兜底
              "fallbacks": [get_dce_rank_table, futures_dce_position_rank_other],
              "symbols": "<大商所主连列表>", "known_issue": "K1"},
    "SHFE":  {"func": get_shfe_rank_table,       "active": False,  # K1: akshare 接口坏
              "symbols": "<上期所主连列表>", "known_issue": "K1"},
```
