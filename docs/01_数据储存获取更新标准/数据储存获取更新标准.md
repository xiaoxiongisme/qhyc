> 适用对象：qhyc 项目（`E:/Docker/qhyc`）后续开发。
> 目标：数据**尽可能全量入库**、口径**统一**、字段**统一**、便于回测直接消费。
> 代码依据：`app/ingest/*`、`app/repositories/_base.py`、`app/ingest/fdf/*`、`app/scheduler.py`、`config/local.yaml`。
>
> **本次修订要点**：① 明确数据落盘在 Docker 内的 TimescaleDB；② 厘清日线/小时线分属两套表的双表架构；③ 补全并写明数据更新规则（日线 cron、小时线采集、回测底座重建、周/月维护）。

## 1. 落盘位置（物理与逻辑）

**所有行情最终落盘到 Docker 容器内的 PostgreSQL/TimescaleDB，不是本地 CSV 或任何文件。**

| 项 | 值 |
|---|---|
| 容器 | `qhyc-timescaledb`（docker-compose 服务名 `timescaledb`） |
| 引擎 | PostgreSQL 16 + TimescaleDB 2.17.1（超表） |
| 数据库 / 用户 | `futures` / `futures`（端口 `5432` 已映射宿主机） |
| 物理落盘点（宿主机） | `E:/Docker/qhyc/pgdata/`（容器 `/var/lib/postgresql/data` 经卷挂载） |
| 编排文件 | `E:/Docker/qhyc/docker-compose.yml` |
| 启动前提 | **必须 Docker Desktop 处于运行状态**（沙箱内 `wsl.exe` 被安全策略拦截，无法由脚本自动拉起 daemon；需手动打开 Docker Desktop 后，容器随 `restart: unless-stopped` 自启） |

**访问方式（需 Docker 运行）**
- 进容器：`docker exec -it qhyc-timescaledb psql -U futures -d futures`
- 宿主机直连：`psycopg` 连 `localhost:5432`（端口已映射），库 `futures`、用户 `futures`。

**明确排除**：本地 `E:/QH/...`、容器 `/app/runtime/data/` 下的 CSV/JSON 仅为**离线备份与导入源**，是辅助而非落盘点；上线不应依赖，回测/信号一律读数据库。

## 2. 统一储存标准（双表架构）

系统存在**两套相互独立**的行情表，用途完全不同，切勿混用：

### 2.1 运行时行情表（由 `app/ingest` 维护，线上实时用）
| 表 | 周期 | 主键 | 写入方 | 说明 |
|---|---|---|---|---|
| `daily_bar` | 日线 | `(symbol, trade_date)` | `orchestrator.IngestOrchestrator` → `upsert_daily_bars` | akshare 主源 + tqsdk 校准；含 `src` 列 |
| `hourly_bar` | 小时线 | `(symbol, trade_datetime)` | `HourlyCollector` → `upsert_hourly_bars` | akshare 新浪 60 分钟主源 + tqsdk 兜底；含 `src`、`oi` 列 |
| `main_continuous` | 主连 | `(product, trade_date)` | `upsert_main_continuous` | 同时存 `raw_*` 裸价与 `adj_*` 复权价 + `underlying`/`change_flag` |

> 融合信号引擎实时读取 `hourly_bar`（按 `fusion.hourly_src` 取唯一口径，默认 `akshare`）；`daily_bar` 供日级特征/展示。

### 2.2 回测底座表（由 `app/ingest/fdf/*` 脚本维护，全历史 + 复权）
**`fut_kline` 超表**（单一超表，按 `(freq, kind, symbol, trade_datetime)` 四维定位）：
- `freq`：`daily` / `hourly` / `min15` / `min5` / `min1` / `weekly` …
- `kind`：`continuous`（未复权主连 `KQ.m@...`）/ `contract`（具体合约 `EX.CODE`）/ `cont_adj`（复权主连）
- 列：`open/high/low/close NUMERIC(20,4)`、`volume/oi BIGINT`、`adj NUMERIC(20,4)`（仅 `cont_adj` 有意义）、`src TEXT`。
- 主键 `(freq, kind, symbol, trade_datetime)` → upsert 天然去重。
- 写入方：`fdf/fetch_fdf.py`（落 `continuous`/`contract`）、`fdf/build_continuous.py`+`adjust_fdf.py`（落 `cont_adj`）、`_build_daily_*.py`（由 hourly 聚合落 `daily`）。

### 2.3 日线 / 小时线在两类表中的分布
| 周期 | 运行时表（实时） | 回测底座（全历史+复权） |
|---|---|---|
| **日线** | `daily_bar`（`src=akshare`） | `fut_kline(freq='daily', kind∈{contract,continuous,cont_adj})` |
| **小时线** | `hourly_bar`（`src∈{akshare,tqsdk}`） | `fut_kline(freq='hourly', kind∈{contract,continuous,cont_adj})` |

**结论**：日线与小时线**两份都存在**，分别服务于"线上实时"与"回测/研究"，由不同代码路径维护。

## 3. 数据获取标准（各路径与落库表）

### 路径 A — akshare 日线主连 → `daily_bar`（已接调度）
- 代码：`akshare_source.py` + `orchestrator.py`（`ingest_symbol`）。
- 流程：akshare `futures_main_sina`（库内 `FG888` → 新浪 `FG0`）拉日线 → 标准化 → `upsert_daily_bars` 入 `daily_bar`（`src=akshare`）。
- 校准：`tqsdk_calibrator` 补缺 + 二次比对，异常开**工单**（校准失败**不阻塞**主源数据）。
- 范围：`history_start`（默认 `2015-01-01`）起至今日。
- 性质：akshare 主连「拼接但未复权」，**不等价于复权价**，仅作日线参考与 tqsdk 缺口对照。

### 路径 H — 小时线采集 → `hourly_bar`（★原文档遗漏，重点）
- 代码：`ingest/hourly_collector.py`（`HourlyCollector`）。
- 主源：akshare `futures_zh_minute_sina(symbol, period="60")`（新浪主连，免登录）。
- 兜底：tqsdk `get_kline_serial(KQ.m@<EX>.<PROD>, 3600)`（全品种**复用单连接**，避免 50×登录超时）。
- 落库：`upsert_hourly_bars` 入 `hourly_bar`（主键 `(symbol, trade_datetime)`，幂等覆盖）。
- 范围：akshare 仅返回近期窗口（数月~一年量级），适合**每日增量刷新**；tqsdk 受 `data_length` 控制可拉更长历史，用于**一次性回填**（CLI `--prefer tqsdk`）。
- 注意：郑商所代码须大写、其余小写，否则兜底失效（详见 `hourly_collector.py` 内 `_TQ_PROD_CASE`）。

### 路径 B — tqsdk 在线抓取 → `fut_kline`（`continuous`/`contract`，小时/15 分钟）
- 代码：`fdf/fetch_fdf.py`（`run` → `fetch_continuous` + `fetch_contracts`）+ `db_pg.save_bars`。
- 落库：`fut_kline` 的 `continuous` 与 `contract`（`freq=hourly`/`min15`，`src=tqsdk`）。
- 模式：专业版按年/季切窗拉全 2020 起历史；免费版 `get_kline_serial` 尾部回退。

### 路径 C — tqsdk 复权重建 → `fut_kline`（`cont_adj`）
- 代码：`fdf/build_continuous.py` + `fdf/adjust_fdf.py`。
- 算法：**加法平移前复权**（详见 §4）。落 `fut_kline(kind=cont_adj, src=tqsdk_fdf)`，`adj` 列标记已/未复权段。

### 回测用本地 CSV（离线备份，非在线路径）
- 位置：容器 `/app/runtime/data/` 或宿主机 `E:/QH/...`。用途：回测对照、断网兜底；与在线路径**独立**。

## 4. 复权标准（加法平移前复权）

- **为什么用加法平移**：期货主连换月仅一处「新旧合约价差」断层，正确修复是「把断层之前全部历史整体平移 delta，使序列连续」。加法平移**不改变任何两点价差**，不影响盈亏点数，只修复 AMA/ATR/分形等指标；乘法连乘会系统性抬高/压低全部历史，导致 ATR/止损位偏移（早期 FG 版回撤虚高根因）。
- **算法要点**（`pick_dominant` + 平移循环）：
  1. 每日取**持仓量最大**合约为主力；需连续 `ROLL_CONFIRM=3` 日领先才确认换月。
  2. 主力**只向前换**（只接受到期更晚的合约），不回退。
  3. 换月日 `t`：`delta = 新合约(t-1)收盘 − 旧合约(t-1)收盘`，前复权 = `t` 之前全部历史 `+= delta`。
  4. 剔除未走完当日 K；截掉主力持仓量不达标（`RELIABLE_OI=100000` 手、连续 `RELIABLE_HOLD=20` 日）的早期区间。
  5. `adj` 列：`True`=已复权段，`False`=前段未复权段（回测只取 `adj=True` 段）。
- **口径归属**：`fut_kline.cont_adj` 是唯一复权权威来源（回测用）；运行时 `main_continuous.adj_*` 另存一份主连复权裸价，供线上特征使用。
- **连续主连兜底（通用，决策 6）**：当某品种逐合约帧**缺失或过旧**（最新一根距今天数 > 400，免费档取不到近期逐合约历史），`adjust_fdf._fallback_from_continuous` 直接把天勤**连续主连 `KQ.m@`**（本身已前复权）作为 `cont_adj` 落库（oi 置 0、标记为未复权段）。**该兜底是全品种通用机制，不限于 RU（橡胶）**——任何低活跃 / 远月 / 免费档取不到逐合约历史的品种都会触发；与逐合约换月复权无缝共存于 `cont_adj`，缺哪段补哪段。

## 5. 数据更新规则（★重点）

### 5.1 触发方式
- **自动**：`app/scheduler.py`（APScheduler blocking 调度）。容器 `qhyc-scheduler` 随 Docker 启动常驻。
- **手动**：CLI / `python -m app.ingest...` 按需跑单品种或全量补数（如 `HourlyCollector(prefer='tqsdk').collect_all()` 回填、`fdf` 脚本重建）。
- **并发保护**：品种级锁 `try_symbol_lock` 防 boot 与定时任务同品种并发写。

### 5.2 日线更新规则（路径 A）
- **频率**：每日三档 cron（`config/local.yaml` → `scheduler.cron`，决策 7）：
  - `08:00` 早盘前（`pre_open`，09:00 开盘前）
  - `12:30` 午盘时（`midday`，11:30 收盘后、13:30 开盘前）
  - `20:00` 夜盘前（`pre_night`，21:00 夜盘开盘前）
- **动作**：三档均触发 `_ingest_job(label)` → `IngestOrchestrator.ingest_all()` → 逐个品种 `ingest_symbol`：
  1. akshare 拉日线 → `upsert_daily_bars` 入 `daily_bar`（增量 upsert，覆盖同主键）。
  2. tqsdk 补缺 + 比对 → 异常开 `anomaly_ticket`（不阻塞主源）。
- **范围**：`2015-01-01` ~ 当日，`ON CONFLICT DO UPDATE` 幂等，重复跑安全。
- **失败处理**：主源（akshare）失败才置 `error` 并告警；校准失败仅记 `calibration_error`，主源数据已入库。

### 5.3 小时线更新规则（路径 H，↔ `hourly_bar`）
- **触发一（每小时自动更新，决策 7）**：新增整点 cron 任务 `_hourly_job`（`config/local.yaml` → `scheduler.hourly`，默认开启，每小时 `:00` 触发，`hour="*"`）全品种小时线增量采集 → `upsert_hourly_bars`。与日线三档调度解耦，保证非交易时段（如夜盘前 19:00/20:00）也及时刷新。
- **触发二（实时刷新）**：融合信号扫描每 **15 分钟**一次（`_fusion_scan_job` → `_collect_hourly_settled`，仅交易时段窗口内）：
  - 采尾部 ~`data_length=800` 根（覆盖 `max_bars=400` + `min_bars=160`，避免每次全历史回填）。
  - **定稿守卫**：若库内最新小时 K 距现在 < `settle_delay_sec=150` 秒，判定数据源未定稿，等够后再重采一次覆盖（防新浪收盘瞬间过渡值致 JD 案例式反手）。
- **主源/兜底**：akshare 新浪 60 分钟主源；失败/限流则 tqsdk `get_kline_serial` 兜底（全品种复用单连接）。
- **幂等**：`(symbol, trade_datetime)` 主键覆盖；写入前除 `1970`/NaN 脏行并去重。
- **限制**：akshare 仅近期窗口，历史回填须 `--prefer tqsdk` 并调大 `data_length`。

### 5.4 回测底座 `fut_kline` 更新规则（路径 B/C + 聚合，非 scheduler 自动）
- **continuous/contract**：`fdf/fetch_fdf.py` 拉取 → `db_pg.save_bars`（按 `(freq,kind,symbol,trade_datetime)` upsert）。
- **cont_adj**：`build_continuous.py` + `adjust_fdf.py` 重建 → `save_adjusted`；**复权重跑先 `delete_bars` 清旧再插**，避免脏数据累积。
- **daily（回测用）**：由 hourly 聚合生成（`_build_daily_contract.py` / `_build_daily_continuous.py`，含**夜盘归属修正**：≥20:00 的 bar 归下一交易日），写入 `fut_kline(freq='daily', ...)`。
- **触发**：需**手动/CI** 执行（容器 `RUN_ON_BOOT=0`，避免每次重启重复全量回补）。数据更新后应重跑路径 B/C + 日线聚合，再跑回测。

### 5.5 周 / 月维护任务（scheduler）
| 时间 | 任务 | 说明 |
|---|---|---|
| 每日 08:00 / 12:30 / 20:00 | 日线三档采集 | 决策 7：早盘前 / 午盘时 / 夜盘前 |
| 每小时 `:00` | 小时线增量采集 | 决策 7：`_hourly_job`（`scheduler.hourly`，全品种） |
| 每日 17:30 | 龙虎榜（新浪）入库 | 决策 1：仅商品期货，金融（CFFEX）不补 |
| 每日 17:10 | 基差 / 现货入库 | 决策 2：`akshare.futures_spot_price_daily` |
| 每周五 17:00 | 库存 / 仓单入库 | 决策 2：`akshare.futures_inventory_em` |
| 周六 06:00 | LSTM 周重训 | 全主连品种，权重落 `/app/runtime/lstm` |
| 周六 06:30 | 传导权重周重算 | corr/granger/te/var/blend |

### 5.8 补充因子数据采集（龙虎榜 / 库存 / 基差，决策 1 / 2）
- **龙虎榜（会员持仓排名）**：数据源改为**新浪财经期货成交持仓**（`app/ingest/rank_position.py` → `ak.futures_hold_pos_sina` + `ak.match_main_contract`）。仅**商品期货**（CZCE/SHFE/DCE/GFEX/INE）；**金融期货（CFFEX：IF/IH/IC/IM/T/TF/TS/TL）不纳入、不补**（决策 3）。逐交易所取主力合约 → 拉「成交量 / 多单持仓 / 空单持仓」三类排名 → 按会员名合并为一行 → `upsert` 入 `member_position_rank`（`src='sina_cot'`）。历史回补需逐日期的主力合约，仅"当日"拉取为准确路径。
- **库存 / 仓单**：`app/ingest/inventory.py` → `ak.futures_inventory_em`，周频（周五 17:00）全品种增量入库 `inventory`（决策 2）。
- **基差 / 现货**：`app/ingest/spot_basis.py` → `ak.futures_spot_price_daily`，日频（17:10）回填空品种最近 `window_days` 天增量窗口入库 `spot_basis`（决策 2）。
- 三者均由 `config/local.yaml` 的 `rank_position` / `inventory` / `spot_basis` 开关控制，默认开启。

### 5.6 幂等 / 增量 / 一致性红线
1. **单源消费**：融合引擎按 `fusion.hourly_src`（默认 `akshare`）读 `hourly_bar` 唯一口径；回测按 `(freq,kind,symbol,src)` 单源读 `fut_kline`。**杜绝双源混读**（akshare 结束时刻标签 vs tqsdk/csv 起点标签两套 K 线会被当成两根喂入指标）。
2. **剔除未收盘 K**：`drop_forming_bars` 丢弃 `now < dt` 的正在形成 K，避免信号自我翻面。
3. **定稿守卫**：`drop_unsettled` 剔除收盘距现在不足 `settle_delay_sec` 秒的最新一根。
4. **合约窗口过滤**：`_contract_window` 按真实交易窗口剔除 phantom 行情（郑商所 3 位码跨十年合并尤需注意）。
5. **标签完整**：任何新数据源入库必须带 `src`；回测/信号指定 `src` 读取。
6. **复权唯一权威**：回测复权价只取 `fut_kline.cont_adj`（路径 C）；`daily_bar`/`hourly_bar` 的 akshare 主连**未复权**。

### 5.7 数据完整性自检清单（每次大批量更新后执行）
- [ ] `daily_bar` / `hourly_bar` / `fut_kline` 各 `(freq,kind,src)` 行数、品种数、起止日期符合预期。
- [ ] 头部品种（`j/au/ag/lh/jm` 等）历史区间无断层（2020 起连续）。
- [ ] `fut_kline.cont_adj` 的 `adj=True` 段起止、行数合理；`adj` 列非空。
- [ ] `hourly_bar` 无 1970/NaN 脏行；`hourly_src` 覆盖完整（akshare 优先、tqsdk 兜底达标）。
- [ ] 无 phantom 行情（合约窗口外日期应为 0 行）。
- [ ] 回测脚本能按 `(freq,kind,symbol,src)` 单源读全，无 `None`。

## 7. 后续开发注意事项
- 新增品种：先在 `symbols.json` 加规格（`code_digits` 必须正确），再跑路径 A/H（运行时）与 B/C（回测底座）。
- 新增频率（如 min5）：`db_pg.FREQS` 加 duration，复权链已支持任意子日线；聚合脚本 `_build_daily_*` 同步扩展。
- 数据缺口修复：优先补 `continuous`+`contract`（路径 B/C 重建 cont_adj），而非直接改 `cont_adj` 数值。
- 任何「盈利金额/回撤」结论必须标注所用 `(freq,kind,src)` 与品种窗口——不同口径结论可差 5~30 倍。
- **落盘位置变动须同步本文件**：若迁移数据库/容器/挂载路径，先改 §1，避免后续开发在宿主机文件与容器内库之间迷失。
