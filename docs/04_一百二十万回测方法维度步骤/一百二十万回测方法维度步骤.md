> 目的：还原历史任务里「回测盈利一百多万（+1,209,197 元）」的**方法学、测试维度、复现步骤**，

## 1. 原始结论（2026-09-14《48 品种 · 融合策略 V2.0 实盘回测报告》）

| 口径 | 净利(元) | 本金倍数 | 最大回撤 | 成交笔数 |
|---|---|---|---|---|
| 信号层毛利（19,730 笔 / 48 品种） | +5,537,552 | — | — | 19,730 |
| **组合 · 容量 5 · 5bp · 4 万本金** | **+1,209,197** | **30.2×** | −19.25% | 4,327 |
| 组合 · 容量 2 | +741,547 | 18.5× | −10.83% | 1,802 |
| 组合 · 容量 1 | +334,261 | 8.4× | −20.87% | 921 |

- 200 次随机并列均值 **+1,067,731**（区间 789,609 ~ 1,380,348）。
- 天勤前复权 `cont_adj` 交叉验证：组合净利 **+1,116,973**，结论一致。
- 9/9 年全正、48/48 品种全赚；头部 5 品种（j/au/ag/lh/jm）贡献毛利 **44.5%**。

**它用的「方式」**：数据库全量小时线主连（`continuous` 未复权主连基准）、48 品种池、初始 4 万本金、同屏最多 5 仓、每品种固定 1 手、成本 5bp、组合层 FIFO 填充（容量瓶颈使 19,730 笔只成交 4,327 笔）。

## 2. 方法学（两层回测架构）

### 2.1 信号层（逐品种前向循环，与引擎同一套逻辑）
- 来源：`_bt_fusion.bt_symbol` / `_bt_multi.bt_symbol` / `_bt_fusion_timeweight.bt_symbol`，与 `fusion_signal.fusion_state_detail` **逐位一致**。
- 输入：某品种小时线（按 `(freq,kind,symbol,src)` 单源读取）。
- 逻辑：日线/小时 `EMA140` 定方向 → `MA20` 回踩重启 + 10 根突破入场（`both_nm`）→ `2×ATR` 初始止损 + `2×ATR` 吊灯 + `0.5×ATR` 保本 → `close-only` 收盘价判定。
- 输出：每笔成交 `(entry_i, entry_px, entry_atr, dir, exit_i, exit_px, R)`（未平仓 `exit_i=-1` 单独列，不计入 R 统计）。

### 2.2 组合层（时间轴 FIFO 重放，闸门）
- 来源：`_bt_multi.replay` / `_bt_fusion_timeweight.replay`。
- 把所有品种的成交事件按时间轴 `entry_dt`/`exit_dt` 排序重放。
- **闸门**：`max_positions=5`（最多同时 5 仓）、各品种 `lots=1`。
- 净金额：`Y = R × entry_atr × multiplier − 往返成本(bp)`；`R` 为风险单位（1R=单笔愿亏）。
- 指标：均 R、净 R、净 ¥、盈利因子 PF、胜率、最大回撤（R 与 ¥ 双口径）。

### 2.3 时段加权（可选增强）
- 由本数据集**分时段期望值**推导参与概率 `p ∈ [0.30, 1.00]`（`p = 0.30 + 0.70×(edge−min)/(max−min)`，样本不足 `N_MIN=100` 取满参与）。
- 入场时用 `rng.random() >= p` 概率性跳过 → 降参与而非硬跳过；跑多 `seed` 取均值±标准差。

## 3. 四维测试维度（多方法对照矩阵）

| 维度 | 取值 | 说明 |
|---|---|---|
| **① 数据源 src** | `tqsdk` / `akshare` / `csv` | tqsdk=唯一覆盖 2020 起；akshare=仅 2025-26；csv=仅 FG/SA |
| **② 容量 max_pos** | 1 / 2 / 3 / 5 仓 | 同屏最大持仓数（资金门控） |
| **③ 成本 cost_bp** | 5 / 10 / 20 / 30 / 50 bp | 往返交易成本 |
| **④ 时段权重** | 不加权(p=1) / 加权(tqsdk 分时段期望) | 加权为概率闸门，多 seed |

> 交叉组合：3 源 × 4 容量 × 5 成本 × 2 权重 = 最多 120 组对照。`_bt_multi.py` 一次跑出「容量×成本」表 + 加权对照。

## 4. 复现步骤（命令）

> 以下均在 **qhyc 容器内**执行（`docker exec qhyc-scheduler python /app/runtime/...`）。
> 依赖：DB 已就绪、`fut_kline` 有目标 `(freq,kind,src)` 数据。

### 4.1 单口径完整回测（还原原始口径）
```bash
# akshare 口径（默认，对齐同花顺）
docker exec qhyc-scheduler python /app/runtime/_bt_fusion.py
# 天勤口径对照
docker exec qhyc-scheduler python /app/runtime/_bt_fusion.py --src tqsdk
# 指定读取根数（默认 2000≈全历史；引擎实时上限 400）
docker exec qhyc-scheduler python /app/runtime/_bt_fusion.py --src tqsdk --limit 300000
```
输出：`/app/runtime/bt_out/fusion_bt_{src}.json`（每品种均 R/胜率/回撤 + 汇总 PF/净 R）。

### 4.2 多方法矩阵（数据源×容量×成本×权重）
```bash
docker exec qhyc-scheduler python /app/runtime/_bt_multi.py \
    --src-list tqsdk,akshare,csv \
    --seeds 60 \
    --max-pos-list 1,2,3,5 \
    --cost-list 5,10,20,30,50 \
    --min-year 2021 \          # 干净窗口：只保留起始年≤该年的品种
    --tag 20260916             # 输出文件名后缀，避免覆盖
```
输出：`/app/runtime/bt_out/fusion_bt_multi_20260916.json`。

### 4.3 实盘加权回测（48 品种 / 1 手 / 5 仓 / 2020-2026）
```bash
docker exec qhyc-scheduler python /app/runtime/_bt_fusion_timeweight.py \
    --src tqsdk --seeds 30 --max-pos 5
```
输出：`/app/runtime/bt_out/fusion_bt_timeweight_tqsdk.json`（加权 vs 不加权、分年度、分时段权重）。

## 5. 当前数据缺口（为何不能直接 1:1 复现）

原 `+120 万` 基于 **`continuous` 未复权主连 48 品种 × 2020–2026 全跨度**，且头部 5 品种（j/au/ag/lh/jm）贡献毛利 44.5%。
当前 DB 现状（以 `fut_kline` 为准，非旧 `hourly_bar`）：

- `fut_kline.hourly/continuous`：57 品种但被 **10,000 根截断**，长窗口不全。
- `fut_kline.hourly/cont_adj`：52 品种 2019-04 起（cu 2021-11、au 2022-06、ag 2022-05 均在）。
- 头部品种 2020–2025 历史仍偏短 → 用现存口径做相同方法学，盈利金额落在 **−20 万 ~ +5 万**（见 §6 历史对照），**不可等同原结论**。

> 结论：**原连续口径已不可得，必须用「相同方法学 + 当前可用底座」做近似**，并明确标注口径缺口。

## 6. 历史多方法对照（2026-09-15，供对比基线）

| 底座 | 窗口/品种 | 不加权(净¥) | 加权(净¥) | PF | 成交 |
|---|---|---|---|---|---|
| **原结论(continuous)** | 48品/2020-26 | **+120.9万** | — | 1.81* | 4,327 |
| tqsdk 全 50 品 | 混合(多数仅2026) | −20.2万 | +5.0万 | 0.96→1.08 | 1792→1410 |
| tqsdk 2021 窗口 | 9品/近5年 | −10.8万 | −1.4万 | 0.94→1.05 | 1942→1380 |
| akshare 全 50 品 | 2025-26 近期 | +5.0万 | +3.8万 | 0.97→1.09 | 386 |
| csv（FG/SA） | 2020-26 | +4.3万 | +4.1万 | 1.38 | 589 |

- 容量越大越亏（长窗口 tqsdk 5 仓触发多品种叠加风险）；近期小容量质量最高（akshare 1仓 PF=1.44，csv 1仓 PF=1.68）。
- 成本盈亏平衡点在 **20~30bp**（与原测 33bp 方向一致）；成本 >20bp 所有底座转亏。
- 时段权重对长窗口/易冲突底座稳健改善（60/60 seed 跑赢不加权）。

## 7. 数据更新后「重跑 + 调参对比」方案

### 7.1 先补齐数据（见 01 文档）
1. 跑路径 B/C 重建全量：`fetch_fdf`（hourly/min15）+ `adjust_fdf --freq daily/hourly/min15` 生成 `cont_adj`。
2. 重点补**头部品种**（j/au/ag/lh/jm）2020–2025 连续区间，消除断层。
3. 自检：48 品种 × 2020 起 `cont_adj` 行数、起止、无 phantom。

### 7.2 重跑（复现原结论）
```bash
# 用复权主连口径重跑（最接近原 continuous 的可用底座）
docker exec qhyc-scheduler python /app/runtime/_bt_multi.py \
    --src-list tqsdk --seeds 60 --max-pos-list 1,2,3,5 \
    --cost-list 5,10,20,30,50 --tag after_rebuild
# 复权主连专项（若已建 cont_adj）
docker exec qhyc-scheduler python /app/runtime/_bt_fusion.py --src tqsdk --limit 300000
```

### 7.3 调参对比（改 `config.local.yaml` 的 `fusion.*` 后重跑）
| 想验证 | 改哪里 | 对照做法 |
|---|---|---|
| 容量灵敏度 | `max-pos-list` | 1/2/3/5 全扫，看净¥/PF/回撤 |
| 成本灵敏度 | `cost-list` | 5→50bp，找盈亏平衡点 |
| 时段权重 | `_bt_*_timeweight` 的 `N_MIN`/映射 | 加权 vs 不加权，多 seed |
| 止损/保本 | `sl_atr`/`trail_atr`/`be_r` | 改 yaml 后跑 `_bt_fusion` 对比均 R |
| 入场模式 | `entry_mode` | pullback/breakout/both/both_nm 切换 |

> ⚠️ **铁律**：引擎 `fusion_signal` 与回测 `_bt_*.bt_symbol` 必须同步。改信号逻辑后两处都要改，并跑回测确认口径未分叉。

### 7.4 输出归档
- 每次回测 JSON 落 `bt_out/`，命名带 `--tag`（日期/数据版本）。
- 对比时横向拉 `fusion_bt_multi_*.json` 的 `cap5_5bp_unweighted` / `cap5_5bp_weighted` 字段。
