> 生成日期：2026-09-16
> 数据前置：见 `01_数据储存获取更新标准`；日线复权（task 1）同日完成，`fut_kline.daily.cont_adj` 已落库 47 品种。
> 本回测使用**小时线**数据（原 120 万结论即基于小时线主连）。

## 一、结论速览（先讲结果）

| 数据源 | 覆盖品种 | 容量/成本 | 不加权净¥ | 加权净¥ | PF | 判定 |
|---|---|---|---|---|---|---|
| **fdf continuous**（清洗后未复权主连，2018→2026） | 50 | 5仓/5bp | **+17.8 万** | +12.9 万 (±2.2) | 1.05 | ✅ 盈利 |
| **fdf cont_adj**（清洗后复权主连，2019→2026） | 48 | 5仓/5bp | **+12.5 万** | +3.0 万 | 1.04 | ✅ 盈利 |
| tqsdk（旧口径 hourly_bar，2020→2026） | 47 | 5仓/5bp | -20.2 万 | +5.0 万 | 0.96/1.08 | ⚠️ 弱 |
| 原 48 品种实盘回测（历史结论） | 48 | 5仓/5bp | **+120.9 万** | — | — | 📌 参照 |

**核心结论**：
1. 在**清洗后、全量**的更新数据上，融合策略**确实具备正期望（PF>1、净¥为正）**，验证了策略逻辑成立。
2. 但更新数据下的盈利幅度为 **+12~+20 万**，与原 +120.9 万相差约 **6–10 倍**，**无法 1:1 复现**原结论。这与前期诊断一致——原回测所用的 continuous 小时线数据集已不在当前库中（见 `融合策略_盈利金额_多方法对照_20260915.md`）。
3. **复权（cont_adj）与未复权（continuous）结果不同**：本批数据中 continuous 略优于 cont_adj；但前期小样本（14 品种）曾显示 cont_adj 更优，说明结论对品种覆盖与时间窗口敏感。

## 二、测试方法、维度、步骤（与原方法一致）

### 2.1 两层回测架构（忠實复刻 `fusion_signal.fusion_state_detail`）
- **信号层**：48/50 品种独立前向循环，逐根判定 EMA(140) 定方向、EMA(20) 回踩/突破入场、收盘价盯盘止损（sl=2×ATR 初始 + 2×ATR 吊灯 + 0.5R 保本），记录每笔成交（FLAT→多/空为开仓，反向为离场）。
- **组合层**：把所有成交事件按时间轴 replay，应用闸门 `max_positions=5`、`lots=1`，按成交金额 = `R × 入场ATR × 合约乘数 − 往返成本(bp)` 累加。

### 2.2 四维测试维度
1. **数据源**：`fdf`(清洗后 fut_kline.hourly) / `tqsdk`(旧 hourly_bar) / `akshare` / `csv`
2. **容量 max_pos**：1 / 2 / 3 / 5 仓
3. **成本 cost_bp**：5 / 10 / 20 / 30 / 50
4. **时段权重**：不加权(p=1) / 加权（由本数据集分时段 mean_R 推导参与概率）

### 2.3 执行步骤
```bash
# 前置：日线复权（task 1，已执行）
docker exec qhyc-scheduler python -m app.ingest.fdf.adjust_all --freq daily

# 回测脚本：runtime/_bt_multi.py（已扩展支持 --src fdf 直读 fut_kline.hourly）
docker exec -e PYTHONPATH=/app qhyc-scheduler python /app/runtime/_bt_multi.py \
    --src-list fdf --fdf-kind continuous --seeds 60 --tag v3_fdf_cont
docker exec -e PYTHONPATH=/app qhyc-scheduler python /app/runtime/_bt_multi.py \
    --src-list fdf --fdf-kind cont_adj  --seeds 60 --tag v3_fdf_adj
```
> 注：`fdf` 源通过品种代码自动映射（`FG888 ↔ KQ.m@CZCE.FG`，大小写归一），无需改动 `hourly_bar`。

## 三、参数对比矩阵（不加权，确定性结果）

### 3.2 fdf cont_adj（48 品种，2019–2026）— 净¥
| 容量\成本 | 5bp | 10bp | 20bp | 30bp | 50bp |
|---|---|---|---|---|---|
| 1 仓 | -3.8万 | -6.6万 | -12.2万 | -17.8万 | -29.1万 |

| 5 仓 | **+12.5万** | -1.5万 | -29.5万 | -57.5万 | -113.4万 |

### 3.3 关键观察
- **成本高度敏感**：5bp 盈利、10bp 勉强、20bp 起全面转亏。策略每笔 R 期望值薄（≈0.03R），对滑点/手续费极敏感——这是原 120 万难以复现的主因之一（原数据或成本假设更优）。
- **容量非单调**：continuous 在 3 仓达峰值（+19.8万），5 仓回落至 +17.8万；说明 5 仓并非最优，存在边际递减。
- **加权 vs 不加权**：tqsdk 旧口径下加权(+5.0万)显著优于不加权(-20.2万)；但 fdf 全量下加权反而不如未加权（连续数据本身已含时段结构）。时段权重需结合数据质量使用。

### 3.4 时段权重（由本数据集推导，fdf continuous）
`09:00=0.65  10:00=0.99  11:00=1.0  13:00=0.78  14:00=0.53  21:00=0.61  22:00=0.63  23:00=0.30  00:00=0.78`
→ 夜盘（21–23 点）参与概率被压低，日盘（09–11、13）维持高位，符合"夜盘噪声大、edge 薄"的直觉。

## 四、与原 +120.9 万的差距归因

| 可能因素 | 影响方向 | 说明 |
|---|---|---|
| 原 continuous 数据集已不在库 | 主因 | 当前 fut_kline.hourly 为重建数据，品种/窗口/拼接方式与原生数据不同 |
| 成本假设差异 | 显著 | 原结论或基于更低成本；当前 5bp 已逼近盈亏线，20bp+ 全亏 |
| 品种覆盖差异 | 中等 | 当前 main_contracts=50，原 48；且各自数据窗口不同 |
| 策略参数未重新寻优 | 待查 | 当前固定使用 settings 默认值，未针对新数据调参 |

**结论**：策略逻辑有效（PF>1），但原 120 万是特定历史数据+假设下的结果，更新数据后量级回落至 +12~20 万量级。若要逼近原量级，需：(a) 恢复/重建原 continuous 数据源，或 (b) 针对当前数据重新寻优参数（见下一节）。

## 五、建议的下一步（参数调优对比）

当前仅做了**组合层**参数对比（容量/成本/权重）。若要进一步逼近原量级，建议补充**信号层**参数扫描：
- `sl_atr`（初始止损 ATR 倍数）：1.5 / 2.0 / 2.5
- `trail_atr`（吊灯倍数）：1.5 / 2.0 / 3.0
- `be_r`（保本 R 阈值）：0.3 / 0.5 / 0.8
- `entry_mode`：pullback / breakout / both
- `W`（摆动窗口）：8 / 10 / 12

上述扫描可直接在 `runtime/_bt_multi.py` 基础上扩展 `--param-sweep` 实现，复用现有两层回测框架。
