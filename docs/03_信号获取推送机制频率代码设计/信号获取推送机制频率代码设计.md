# 融合策略 · 信号获取 / 推送机制 / 频率 / 代码设计（终版）

> 适用：后续调整信号逻辑、推送频率、通道时的唯一参考。
> 代码依据：`app/strategies/fusion_signal.py`、`app/notify/pushplus.py`、`app/scheduler.py`。

---

## 1. 架构总览

```
每 15 分钟（CronTrigger minute="*/15"）
   │
   ├─ 0) 闸门：非交易日 / 非推送窗口 → 整轮跳过（冷启动除外，需先建基线）
   │
   ├─ 1) 拉最新小时线（HourlyCollector，akshare 主源 + tqsdk 兜底）
   │        + 定稿复核（settle_delay_sec：刚收盘的 K 等够秒数重采，防未定稿价）
   │
   ├─ 2) evaluate_all()：对 48 品种跑 fusion_state_detail → 每个品种：state + 入场价/ATR + 止损/保本位
   │
   ├─ 3) 状态机去重（FusionPosition 持久化）：
   │         db(FLAT/LONG/SHORT) vs eng(state) 比对
   │         ├─ 不同 → 🚨 信号（开/平/反手），附 ⛔止损 / 🎯保本位
   │         └─ 相同 → ⚠️ 止损变动（吊灯上移≥阈值 / 首次触发保本）补推
   │
   ├─ 4) 持仓一览（heartbeat 行，用展示阈值，夜盘/周末不消失）
   │
   └─ 5) 推送决策：信号 > 盘前 > 止损变动/定时 → send_notify → FusionPushLog 留痕
```

## 2. 信号获取机制（fusion_signal.py）

### 2.1 状态机
- 三态：`0=FLAT`（空仓）/ `1=LONG`（持多）/ `2=SHORT`（持空）。
- `fusion_state(o,h,l,c,htf_dir,p)` 只取状态；`fusion_state_detail(...)` 返回**明细**（入场价、入场 ATR、peak/trough、保本触发价、初始止损、吊灯止损、当前生效止损）。
- **单一真源**：引擎与回测共用同一循环 `_bt_fusion.bt_symbol` 逐位对齐，无口径分叉。

### 2.2 指标（与回测一致）
- 方向层：日线/小时 `EMA140`（`ema(c, ema_k)`）。
- 入场：`MA20` 回踩重启 + 10 根突破（`both_nm`，去 MACD）。
- 离场：`2×ATR` 初始止损 + `2×ATR` 吊灯移动止损 + `0.5×ATR` 保本。
- ATR：`atr14`（Wilder RMA），`ema` 用 `ewm(adjust=False)`。

### 2.3 关键校正（与历史口径对齐）
- **保本触发距离 = `be_r × 入场ATR`（= 0.5×ATR），不再乘 `sl_atr`**（旧式 `be_r×sl_atr×ATR` 在 sl_atr=2.0 下被放大成 1.0×ATR，与文档/同花顺图不符）。
- **HTF 方向门控用前一根方向**（`htf_dir = concat([0], dir_raw[:-1])`），对齐「已收盘、无前视」。

### 2.4 数据来源与读取口径（落盘位置 / 双表架构 / 更新规则）

> 本节与「数据储存/获取/更新标准」§1、§2、§5.3 严格对齐，信号逻辑调整时务必同步。

**① 落盘位置（标准 §1）**
- 所有行情落在 **Docker 容器 `qhyc-timescaledb` 内的 PostgreSQL/TimescaleDB 库 `futures`**（宿主机物理卷 `E:/Docker/qhyc/pgdata`，需 Docker Desktop 运行）。**不是本地 CSV / 文件**。
- 信号引擎实时读取的是运行时表 **`hourly_bar`**（表内 `src` 列区分来源），经 DB 查询取最新 N 根，引擎本身不直连第三方 API。

**② 双表架构（标准 §2）：日线、小时线两份都在库内**
- 运行时表（线上实时）：`daily_bar`（日线）、`hourly_bar`（小时线）、`main_continuous`（主连）。
- 回测底座（全历史+复权）：`fut_kline` 超表（`freq/kind/symbol/trade_datetime` 四维）。
- 引擎只读 `hourly_bar`（单源口径）；回测读 `fut_kline` 的 `cont_adj` / `continuous` / `contract`。

**③ 小时线主源 / 兜底（标准 §3 路径 H）**
- `read_hourly_bars(symbol, limit)`：**按 `fusion.hourly_src` 单源读取**（默认 `akshare`，即 **akshare 新浪 60 分钟主连** `futures_zh_minute_sina`，对应图表「收盘时刻」标签的 K）。主源根数不足 `min_bars` 才回退 `tqsdk` 兜底并告警（故障期无奈之举，非预期状态）。
- ⚠️ 纠正：原稿曾误作「同花顺图上看到的 K」——**实际主源为新浪（sina），非同花顺（Tonghuashun）**；二者均为「结束时刻标签」的 K，但与 tqsdk/csv 的「起点标签」不可混读（见标准 §5.6）。

**④ 数据更新规则（标准 §5.3）**
- **日更联动**：ingest 的 `close` 档（16:00）成功后自动联动 `HourlyCollector.collect_all()` 入 `hourly_bar`。
- **实时刷新**：融合扫描每 **15 分钟**采尾部 `data_length=800` 根，覆盖 `max_bars=400` + `min_bars=160`，避免每次全历史回填。
- **定稿守卫**：`drop_unsettled` 剔除「收盘距现在 < `settle_delay_sec=150` 秒」的最新一根（新浪收盘瞬间过渡值，JD 09:00-10:00 根 close 3814→3810）。
- **幂等**：`(symbol, trade_datetime)` 主键覆盖，写前除 1970/NaN 脏行；akshare 仅近期窗口，历史回填用 `--prefer tqsdk`。

**⑤ 准确度命门（剔除脏 K）**
- `drop_forming_bars(df)`：丢弃 `now < dt`（收盘时刻）的「正在形成」K，否则同一小时信号会自我翻面（实测 50 品种里 2 个翻转）。
- `drop_unsettled(df, settle_delay_sec)`：剔除「收盘距现在不足 `settle_delay_sec` 秒」的最新一根（数据源定稿漂移，JD 09:00-10:00 根 close 3814→3810）。

## 3. 推送机制与决策（scheduler._fusion_scan_job）

### 3.1 状态机去重（FusionPosition 表）
- 每品种持久化：`position` / `entry_price` / `entry_at` / `last_stop` / `last_be_done` / `signal_at` / `pushed_at`。
- **冷启动**：表为空时无条件以引擎当前状态建基线（即便数据陈旧），否则基线永远建不起来。
- **信号判定**：`db != eng` 且数据新鲜（`age_min ≤ stale_minutes`）→ 产生信号；数据陈旧抑制状态变化。
- **止损变动**：`eng≠FLAT` 且 `(cur_stop - prev_stop) × sign ≥ trail_push_atr×ATR` → 补推；`be_done` 由 False→True 一次性事件必推。

### 3.2 推送形态（三段式，越上越需动作）
1. 🚨 **新信号**：开/平/反手，附 ⛔止损 / 🎯保本位。
2. ⚠️ **止损变动**：吊灯止损上移、首次触发保本（可选推项）。
3. 📋 **持仓一览**：一行一个品种（代码+中文名+方向+入场→现价+浮盈%+止损/保本）。
- 另加 ⏳ **待执行复提**：开仓信号在 `signal_repeat_min` 分钟内每轮重复置顶，防漏看。

### 3.3 推送决策优先级
```
kind = 信号(signals 非空) ? "signal"
     : 盘前(pre_session_times 命中) ? "presession"
     : (止损变动 or 定时心跳 due) ? "heartbeat"
     : None（本轮不推）
```
- 心跳节流：距上次推送 ≥ `heartbeat_interval_min` 分钟（`now.minute % interval == 0` 且 gap_ok）才发。
- 非交易日 / 非推送窗口整轮冻结（不采集、不评估、不更新状态）。

## 4. 推送频率（汇总）

| 触发 | 频率 | 说明 |
|---|---|---|
| 融合信号扫描 | **每 15 分钟** | `CronTrigger(minute="*/15")`，与每日三次 ingest 并行 |
| 🚨 即时信号 | 状态变化时 | 开/平/反手立即推（受数据新鲜度约束） |
| ⚠️ 止损变动 | 变动达阈值时 | 吊灯上移≥`trail_push_atr×ATR` 或首次保本 |
| 🌅 盘前预播报 | `pre_session_times`（如 08:45/13:15/20:45） | 强制推，带完整止损/保本位 |
| 📊 定时简报 | 每 `heartbeat_interval_min`（默认 30） | 对齐 :00/:30，持仓清单 |
| ⏳ 待执行复提 | 开仓后 `signal_repeat_min`（默认 120）内 | 每轮置顶同一笔开仓信号 |

> 推送窗口 `push_windows` 如 `["08:45-12:00","13:15-15:30","20:45-23:30"]`，窗口外不推（睡眠时段）；隔夜/跨窗口变化在下一窗口首扫合并成一条推出。

## 5. 推送通道（pushplus.py）

| 通道 | 端点 / 方式 | 降级 |
|---|---|---|
| 主通道 | pushplus `https://www.pushplus.plus/send`，POST JSON（`token/title/content/template=markdown`） | 失败重试 1 次（退避 1.5s） |
| 备用 | 通用 webhook（企业微信/钉钉/飞书群机器人） | `fusion.fallback_webhook` 配置，按域名自动选载荷格式 |
| 留痕 | `FusionPushLog` 落库（kind/title/content/n_signals/delivered/via） | 防漏看，可随时回查 |

- **推送是旁路**：任何失败只记日志、绝不抛异常，不影响调度主流程。
- 通道选择：`send_notify()` 先 pushplus，失败降级 webhook，返回 `(是否送达, 实际通道)`。

## 7. 代码设计要点（后续调整去哪改）

| 想改什么 | 改哪里 |

| 推送文案/分段/优先级 | `scheduler._format_push` / `_fusion_action` / `_row_line` |
