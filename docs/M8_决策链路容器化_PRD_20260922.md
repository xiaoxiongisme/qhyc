## 4. 部署拓扑裁定 ★

> 用户原话：「当前 docker 已经实现了数据获取和入库，其余功能你看是新建 docker 容器还是合并？」

### 4.1 结论

> **合并镜像（复用现有 image，不写新 Dockerfile）+ 新增 1 个 compose service `qhyc-pipeline`（角色隔离）；
> API 侧并入现有 `qhyc-api`（新增 `/pipeline/*` 路由，不新建容器）。**

一句话：**合 dependencies、分式 process**。

### 4.2 三方案对比

| 候选 | 描述 | 优点 | 缺点 | 裁定 |
|---|---|---|---|---|
| **A. 合并镜像 + 新增 service** ✅ | 同 image，`ROLE=pipeline`，同网络、同 config/env | ① 依赖已 99% 齐 **② 共享 config/.env/挂载，零重复配置 ③ 进程隔离，崩溃不拖垮数据入库 ④ 可单独重启/缩容 ⑤ 增量内存仅 ~200–400MB** | 多一个进程 | **选** |
| B. 全并入现有 `qhyc-scheduler` | 在 `app/scheduler.py` 里加 cron | 零新增资源 | **致命**：APScheduler 默认线程池会被长时间任务占满（决策链路 = 49 品种 live 抓取 + 研究层 `fut_kline` 回放，分钟级），会推迟/丢失 `*/15 fusion_scan` 与 17:30 `rank_position`；且崩溃连带数据入库主线 | ❌ |
| C. 新建独立 stack（新 Dockerfile + 新 compose） | 独立一套 | 完全解耦 | 重 ~1GB 镜像（torch / scrapling 可选层重复构建）、akshare 版本双轨漂移、两套配置两个 PG 连接串。与本项目一贯的「**不另起炉灶**」原则直接冲突 | ❌ |

### 4.3 为什么进程必须隔离（补充说明）

现有 scheduler 的关键节奏（实测 `app/scheduler.py` 注册点）：

| 时刻 | 任务 | 性质 |
|---|---|---|
| `*/15` | `fusion_scan`（融合信号直推） | **强时效，15 分钟内必须跑完，用户已定保留不动** |
| 17:10 / 17:30 | `spot_basis` / `rank_position` 入库 | 数据层命脉 |
| 02:30 | `adjust_cont_adj` | 重 |
| 周×06:00–07:00 | lstm / transmission / weekly backtest | 重 |

决策链路若塞进同一个 APScheduler，17:30 那一下必然与 `rank_position` 抢线程池 → 数据入库延迟 → 轻基本面读到陈数据。**这是选 A 的决定性理由。**

### 5.3 启动快照（copy-on-start）——解决"运行期被改"与"Windows 文件锁"

容器**启动时**把只读挂载 `/app/pipeline_src` 整体复制到**容器内可写目录** `/app/runtime/pipeline_snapshot`，之后所有子进程跑这份副本：

- 消除「宿主正在编辑 → 容器读到半截文件」
- 消除跨 OS 文件锁
- 语义与本项目既有心智一致（「改代码需重启容器才生效」，与 `./app:/app/app:ro` 现状同构）
- 复制时计算 md5 manifest 存入 `pipeline_run.src_manifest`，**作为单一真源审计凭据**

### 5.4 worker 设计约束

- **必须**用 `subprocess` 调用 `run_pipeline.py`（沿用 `_run()` 语义），不要用 `import`。理由：隔离、日志流承接、避免模块重入。
- 子进程 cwd = 快照目录；`env` 继承 + 注入 `QH_BRIEF_BASE` 等。
- 每 step 独立超时（默认沿用 1800s），超时计 FAIL 但**继续后续步骤**并在 `pipeline_run.status='partial'`。
- APScheduler job misfire_grace_time 建议 ≥ 300s；`max_instances=1`；`coalesce=True`。

| `fusion_scan`（每 15 分钟直推） | `qhyc-scheduler` | **保留不动** ✅ | 用户既定决策，**CB 不得改动 `app/scheduler.py` 的 fusion_scan** |
| 数据入库类 cron | `qhyc-scheduler` | **保留不动** ✅ | |
| 18:00 媒体发布 | WB `qh-observe-publisher` / `qh-douyin-article` | **保留在 WB** | 消费容器写出的 `简报内容/*.md` |

### 6.2 17:30 竞争的处理（重要）

`qhyc-scheduler` 的 `rank_position`（会员持仓入库）在 **17:30**；决策链路步骤①轻基本面要读 `member_position_rank`。

**规则**：
1. 决策链路 daily cron 改为 **17:40**（给 `rank_position` 10 分钟）。
2. 步骤①前先跑 **readiness 闸门**（`app/pipeline/readiness.py`）：轮询检查当日 `spot_basis` 与 `member_position_rank`（CZCE/SHFE/DCE/GFEX）行数 > 0；**每 60s 一次、最多等 10 分钟**。
3. 超时仍不满足 → 记录 `data_ready=false` 并**照常往下跑**（轻基本面该品标 `N/A`，符合现有「诚实边界」写法），同时 pushplus 发一条降级通知。

### 6.3 交易日 / 窗口

- 非交易日：`--daily` / `--signal` / `--intraday` 全部静默跳过（沿用 `is_trading_day()`）。
- `push_windows` 沿用现有 `fusion.push_windows` 语义，不新增一套。

## 7. 落库（`db/init/09_pipeline.sql`，幂等 `IF NOT EXISTS`）

```sql
CREATE TABLE IF NOT EXISTS pipeline_run (
  run_id       BIGSERIAL PRIMARY KEY,
  kind         TEXT        NOT NULL,            -- daily | signal | intraday | check
  run_date     DATE        NOT NULL,
  started_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at  TIMESTAMPTZ,
  status       TEXT        NOT NULL,            -- running | ok | partial | fail
  steps        JSONB,                           -- [{i,name,ok,dur_s}]
  artifacts    JSONB,                           -- 产出绝对路径清单
  src_manifest TEXT,                            -- 源码 md5 清单（单一真源审计）
  data_ready   BOOLEAN     DEFAULT NULL,        -- readiness 闸门结果
  error        TEXT,
  created_by   TEXT        NOT NULL DEFAULT 'scheduler'
);
CREATE UNIQUE INDEX IF NOT EXISTS uq_pipeline_daily
  ON pipeline_run(kind, run_date) WHERE kind = 'daily';      -- 日链幂等：一天一条
CREATE INDEX IF NOT EXISTS ix_pipeline_run_recent
  ON pipeline_run(kind, started_at DESC);

CREATE TABLE IF NOT EXISTS pipeline_push_log (
  id       BIGSERIAL PRIMARY KEY,
  run_id   BIGINT REFERENCES pipeline_run(run_id) ON DELETE CASCADE,
  sent_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  channel  TEXT,                                -- pushplus | webhook | none
  ok       BOOLEAN     NOT NULL,
  title    TEXT,
  resp     TEXT
);
CREATE INDEX IF NOT EXISTS ix_pipeline_push_run ON pipeline_push_log(run_id, sent_at DESC);
```

> 备注：`daily` 重跑时若撞唯一键 → **更新**该行（幂等），不要用新行；`status` 字段同时更新。
> 这张表**不是** hypertable（运行元数据，行数极小），无需 TimescaleDB 转换。
