## 一、总体判定

> **M4 回测管道已跑通，但当前落库的回测指标不构成"模型有预测力"的证据，且存在 1 个数据完整性级（P0）缺陷。**

## 二、发现清单（按优先级）

### 🔴 P0-1｜backtest_result 主键缺 symbol 维度 → 多品种批量回测互相覆盖

- **证据**：表内仅 34 行 / 3 个 run_id（100612 / 101744 / 101845），每个 run 只有 8~13 行 = 单品种的模型数。若 73 品种正常落库应约 949 行。
- **机理**：`backtest_symbols` 对整批品种共用一个 run_id，而主键是 (run_id, model)，后写品种经 `on_conflict_do_update` 覆盖先写品种 → **每次批量回测实际只保留最后一个成功品种**。
- **连锁伤害**：`update_model_weights` 读"最新 run"全部行 → **月更权重实际只由单一品种决定**。
- **修复**：主键改为 (run_id, symbol, model)，run_id 生成加入 symbol 或批量时逐品种加后缀；Alembic 迁移 + 重跑。

### 🟠 P1-1｜LSTM 回测前视泄漏未真正消除（M4.1 名存实亡）

- **证据**：
  - LSTM 平均 dir_acc 0.614 vs 其他模型 0.496（+11.9pp）；
  - run 101744 中 LSTM dir_acc=0.850（n=20，p=0.0026），是全表唯一显著>50% 的行；
  - `runtime/lstm` 73 个权重文件 mtime 全部为 2026-09-07 09:07-09:08（早于全部三次回测）→ **不存在任何历史权重快照**，"按评估日动态加载历史权重"无处可加载，回测 LSTM 实际仍使用"训练至 2026-09-07"的同一份权重。
- **影响**：LSTM 的回测优势（+0.119）是泄漏的直接产物；且该分数已写进 model_weights（LSTM 权重被抬到 1.4，全表最高）。
- **修复**：回测时对每个评估点只用 `last_train_date <= t` 的权重；无快照则跳过该点或退化为不参与 ensemble。修复后重跑 M4，预期 LSTM dir_acc 回落到 0.50 附近。

### 🟠 P1-2｜权重月更被 n=20 的小样本 run 决定，且无最小样本门槛

- **证据**：model_weights 7 行的 dir_acc/sample_n 与 run 101744 完全一致（全部 sample_n=20）；公式复算全部 ✓（机制正确），但来源不可靠。
- **伤害**：线上 ensemble 权重已从 config 的近等权（0.8~1.2）变成极端分布：LSTM 1.4，而 arima/fourier/rf/xgb 0.1、hmm 0.2 → **一个 n=20、且含泄漏模型的回测 run 正在主导线上预测**。
- **修复**：`update_model_weights` 增加 `min_sample_n >= 60` 门槛；样本不足回退 config 权重；权重更新只在整批 73 品种 run（P0 修复后）上执行。

### 🟠 P1-3｜分位区间大面积失效（过度自信）

- **证据**（quantile_hit 目标 90%）：
  - kalman 0.58 / 0.50、rf 0.68 / 0.45、xgb 0.57 / 0.25 / 0.40、wavelet 0.25 / 0.00（p 值均 <1e-5）
  - run 101845 中 lstm/garch 覆盖 1.00 但样本 1~15，无意义。
- **含义**：P5~P95 区间过窄——实际次日收益越界率远超 10%。看板若展示该区间会系统性误导。
- **修复**：ML 类（rf/xgb）与 kalman/wavelet 的区间构造需改用分位数回归或经验残差分位 + 滚动校准；上线前看板标注"区间未校准"。

### 🟠 P1-4｜各模型样本数严重不一致（模型静默失败被吞掉）

- **证据**：同一 run 内 n 从 1 到 500 不等（markov/montecarlo/bayesian n=93、rf/xgb n=47、wavelet/garch n=16/1）；ensemble n=500 而 lstm n=407。
- **含义**：模型在部分评估点抛错被 `errors` 收集但不落库 → 无法区分"模型不适用"与"模型崩溃"；ensemble 每个点的参与模型集合都在漂移。
- **修复**：落库 per-eval-point 明细行（含 errors），或至少把 per-model 成功/失败计数写入 by_state。

### 🟡 P2-1｜回测标签为 canonical close-to-close，非 PRD-⑩ settle 口径

- **证据**：抽样 22273 个交易日，close 与 settle 日收益方向不一致率 **29.1%**（幅度差均值 0.6~1.8%）。
- **澄清**：线上预测（ret_point）与回测口径**内部自洽**（都用 canonical close），故 ensemble 回测指标对线上是公平的；偏离的只是 PRD-⑩"结算价涨跌幅"的承诺。
- **建议**：二选一——(a) 修订 PRD-⑩ 为"收盘口径"（最省事）；(b) `_next_ret` 改用 settle 收益对齐原设计。需在小熊侧裁决后写入 §15。

### 🟡 P2-2｜回测 ensemble 用 config 固定权重，线上用 DB 权重 → 回测≠线上

- **证据**：7 个模型 DB 权重与 config 差异 >0.05（lstm 1.2→1.4、arima 1.0→0.1 等）。
- **含义**：即使 P0/P1 修复，回测 ensemble 数字也不代表线上行为。
- **修复**：回测 engine 与 predict_symbol 统一权重来源（推荐都走 `get_model_weights`，fallback config）。

### 🟢 已验证正确的部分

- 防前视特征切片（`df.index <= t`）正确；
- 权重公式 `w=clip((acc−0.5)×4, 0.1, 2.0)` 复算 7/7 一致；
- 落库幂等（on_conflict）与 eval 点框架（251 根 / 步长 3 → ≈84 点）按设计工作；
- 基线宇宙 73 品种可正常构建（canonical 序列加载健康）。

## 三、对照基线：模型究竟有没有用？

基线宇宙 = 73 品种、与回测相同的评估点框架（251 根 / 步长 3）：

| 基线 | 数值 | 对比 |
|---|---|---|
| 常涨基线（up-rate） | 均值 0.510，范围 [0.417, 0.655] | 模型 0.35~0.56 区间，无超额 |
| 动量1（昨收方向延续） | 均值 0.480，最优 0.631 | — |
| 动量5 | 均值 0.511，最优 0.607 | — |
| 反转1 | 均值 0.518 | — |
| 零预测 MAE | 均值 1.042% | 模型 MAE 1.13~1.69%，**更差** |

**一句话结论**：当前 13 模型 + ensemble 在回测中既没有跑赢随机，也没有跑赢"恒预测 0"的幅度下界。这不是灾难——它说明引擎诚实地测出了"这些模型在这些参数下对该任务没有增量"，反而证明了回测框架（除 P0/P1 外）在正常工作。**下一步的价值排序应是：修 P0 → 统一口径与权重 → 用修复后的框架筛选/淘汰模型，而不是先做 M5 看板展示当前这些数字。**

## 四、给 CodeBuddy 的修复工单（建议顺序）

1. **[P0] BacktestResult 加 symbol 维度**：主键 (run_id, symbol, model)；`backtest_symbols` 逐品种隔离 run 或加 symbol 列；Alembic 迁移 + 清洗旧数据 + 全量重跑。
2. **[P1] LSTM 泄漏根治**：权重快照带 `train_until` 日期，回测点只允许加载 `train_until <= t` 的快照；无快照则该点 LSTM 缺席。修复后 LSTM 回测分数应显著回落，作为验收标准。
3. **[P1] 权重月更护栏**：`min_sample_n>=60`、仅取整批 run、LSTM 修复前冻结其权重为 config 值（1.2）；建议先手动清空 model_weights 表回退 config。
4. **[P1] 区间校准**：rf/xgb/kalman/wavelet 改分位数回归或滚动经验分位校准；验收标准 quantile_hit ∈ [0.85, 0.95]。
5. **[P2] 口径裁决**（需小熊拍板）：close 口径入 PRD §15 或改 settle 标签。
6. **[P2] 权重来源统一**：回测 ensemble 与线上同走 model_weights（fallback config）。
7. **[P2] per-point 明细落库**：新增 backtest_detail 表（run_id, symbol, model, eval_date, state, pred, prob, point, low, high, actual），支撑 M5 看板下钻与后续误判归因。
