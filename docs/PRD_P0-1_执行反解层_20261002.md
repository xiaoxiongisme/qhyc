> **落地入口**：`app/execution/`（代码骨架已随本 PRD 一并提交）

## 0. 为什么必须做

策略信号目前运行在**连续主力合约（`<品种>888`）的后复权价空间**：`fusion_signal` 输出 `{symbol: "RB888", direction, entry_px, stop_px, lots, atr}`（见 `FusionSignalLog`）。这套价位是"缝合连续序列"，**不能直接对真实合约下单**：

1. `RB888` 不是可交易合约，必须反解到当日真实主力合约（如 `RB2510`）；
2. 连续后复权价 = 真实合约原始价 + 缝合偏移 `cum_offset(t)`，下单价须还原成原始价；
3. 手数、保证金、合约乘数要联动校验；
4. 反解结果必须与盘口价自洽——否则就是"反解到错误合约/错误价格"的实盘灾难。

复权口径切换文档（归档 2026-09-30）阶段 4 已定性："**执行层反解（不做则实盘出错）**"，反解公式 `real = adj − offset(t)`（roll_segment as-of join）。本 PRD 把它变成可开发、可验收的模块。

> 即使近期只做"**信号 → 人工下单对照卡**"（不接自动下单通道），本层也是刚需：复权切换后，推送给用户的价位必须与盘口对得上，否则人工下单会下错价。

## 1. 范围

### 1.1 In Scope
- 把一条融合策略信号（`连续888 + 复权/连续价`）反解为一条可执行订单建议（`真实合约 + 原始价 + 整数手 + 校验结论`）。
- 四大组件：① 价格反解；② 换月规程；③ 手数计算；④ 点位校验。
- REST 端点 `/execution/reverse`（POST），供简报/推送链路或人工对照卡调用。

### 1.2 Out of Scope（本 PRD 不覆盖）
- 真实经纪商/交易所下单通道（CTP / 易盛 / 飞马等）——仅产出"订单建议"，不下单。
- 资金账户的实时权益/保证金查询（手数计算支持"目标风险 R"模式，但账户侧实时数据接入另立项）。
- 风控熔断（属 P0-2，见 `risk/portfolio_brake.py`，本层只消费其开关结论）。

## 2. 接口契约

### 2.1 输入 `ReverseRequest`
| 字段 | 类型 | 说明 |
|---|---|---|
| `symbol` | str | 连续主力码，如 `RB888`（`is_continuous` 必须为 True，否则直接拒绝） |
| `trade_date` | date | 信号交易日（用于换月映射与偏移 as-of join；必须显式传，避免跨年错） |
| `trade_datetime` | datetime \| None | 精确到 K 的时点；不传则用 `trade_date` 收盘近似 |
| `direction` | str | `LONG` / `SHORT` / `FLAT`（FLAT 不反解，直接返回空单） |
| `entry_px` | float \| None | 信号入场价（**连续/复权价空间**） |
| `stop_px` | float \| None | 信号止损价（同空间） |
| `lots` | int \| None | 信号手数（融合引擎已给；若传 `target_risk` 则改为由本层算） |
| `target_risk` | float \| None | 单笔目标风险（R，金额元）；与 `lots` 二选一 |
| `atr` | float \| None | 入场 ATR（手数按风险模式时需要） |

### 2.2 输出 `ExecutionOrder`
| 字段 | 类型 | 说明 |
|---|---|---|
| `real_symbol` | str | 反解出的真实可交易合约，如 `RB2510` |
| `exchange` | str | 交易所 |
| `product` | str | 品种码 `RB` |
| `direction` | str | 沿用输入方向 |
| `price` | float | **原始（未复权）价**，下单用 |
| `stop_price` | float \| None | 反解后的原始止损价 |
| `lots` | int | 整数手（≥1；校验不通过时 `blocking=True` 且 lots 置 0） |
| `multiplier` | float | 合约乘数（手数计算用，回传便于前端展示） |
| `notional` | float | 名义金额 = lots × multiplier × price |
| `tick` | float \| None | 最小变动价位（见 §3.4 数据依赖） |
| `warnings` | list[str] | 非阻断提示（如 tick 未知、价偏离盘口偏大都在此） |
| `blocking_reasons` | list[str] | 阻断原因（任一非空则该单**禁止下单**） |
| `meta` | dict | 调试信息：`cum_offset`、换月 `change_flag`、盘口偏离度等 |

## 3. 四大组件设计

### 3.1 组件① 价格反解（reverse_price.py）
- **公式**：`real_px = adj_px − cum_offset(t)`。
- **复用**：`app.data.back_adjust.unadjust_price(adj_px, cum_offset)` 已实现该数学；
  `load_segments(session, symbol, freq)` + `map_offset(ts, segs)` 给出 `t` 时刻的 `cum_offset`（as-of join，末段视为无穷大）。
- **freq 选择**：信号基于小时线 → 用 `hourly` 对应的 `roll_segment`（freq 字符串与 `back_adjust.TABLE` 对齐；连续合约段表按 `symbol` 存，无需区分 888/8888）。
- **口径风险（CB 落地必须确认）**：融合引擎消费的 `hourly_bar.<RB888>.close` 到底是**原始连续价**还是**已后复权价**？
  - 若是**已后复权** → 直接用 `unadjust_price` 减偏移即可。
  - 若是**原始连续价**（缝合但未加偏移）→ 则 `entry_px` 本身已是真实合约原始价空间，`cum_offset` 取 0，但仍须用 `real_symbol` 校验盘口一致性（见 3.4）。
  - **判定方法**：取任一品种最近一根 `hourly_bar` 的 close，与同 `trade_datetime` 的 `roll_segment.cum_offset` 相加，看是否等于 `bar_60m`/`hourly` 该真实合约原始价。**CB 落地第一步先写这个判定脚本**（也进 deploy_gate 校验）。
  - PRD 默认假设：**信号价为已后复权价**（与归档文档 `real = adj − offset(t)` 一致），并以 §3.4 一致性校验兜底；若实测为原始价，则 `ReverseRequest` 增 `price_space: "raw" | "adj"` 字段，反解分支置 offset=0。

### 3.2 组件② 换月规程（roll_policy.py）
- **选合约**：`product = symbol_code.product_of(symbol)` → `MainContractRepository(session).query(product=product, start=trade_date, end=trade_date)` 取当日 `main_symbol` 作为 `real_symbol`。
- **移仓时点规则**（反解层只声明"当前该交易哪一份"，真正平旧开新由操作手册/自动下单层执行）：
  - 默认取 `main_contract_map.main_symbol`（官方主力判定）。
  - 若 `change_flag=True`（当日发生主力切换），在 `warnings` 标注"今日换月"，并建议人工确认。
- **交割月护栏（强制阻断）**：
  - `yy, mm = symbol_code.delivery_ym(real_symbol)`；
  - 计算该合约**最后交易日**（默认启发式：交割月前一月的倒数第 `N` 个工作日，`N` 按交易所可配；郑商/大商/上期多为交割月第 10 个交易日，简版取「交割月前一日历月末」已足够保守）；
  - 若 `trade_date` 距最后交易日 ≤ `ROLL_BUFFER_DAYS`（默认 5，可配）→ 加入 `blocking_reasons`（"合约进入交割月，禁止新开"）。
- **活跃性校验**：`real_symbol` 必须在 `futures_symbol` 中 `active=True`，否则阻断。

### 3.3 组件③ 手数计算（lot_sizing.py）
- **模式 A（信号给定 lots）**：校验 `lots ≥ 1` 且为整数；可追加"不超过单品种持仓上限 `MAX_LOTS_PER_PRODUCT`（可配，默认 10）"。
- **模式 B（目标风险 R）**：`lots = floor(target_risk / (atr × multiplier × 合约单位风险))`——注意 ATR 与 price 必须同空间（都用反解后的原始价空间，或都用连续空间，二者一致因差值为常数偏移）。
  - 必须 `lots ≥ 1`，且 `lots ≤ MAX_LOTS_PER_PRODUCT`。
- **名义金额**：`notional = lots × multiplier × price`（回传，供风控与前端展示）。
- **依赖**：`multiplier` 来自 `futures_symbol.multiplier`（`SymbolRepository.get(real_symbol).multiplier`）；若 `None` → 阻断（数据缺失）。

### 3.4 组件④ 点位校验（validator.py）
逐项检查，结果进 `warnings` / `blocking_reasons`：

1. **合约可交易**：`real_symbol ∈ futures_symbol` 且 `active=True`；否则阻断。
2. **tick 对齐**：`price` 须为 `tick` 的整数倍（`round(price/tick)*tick == price` 容差 1e-6）。
   - **tick 来源（数据依赖！）**：`futures_symbol` 当前**无 `price_tick` 列**，须新增（见 §6 DDL）或从交易所规则常量表读取。落地前若取不到 → 不阻断，仅 `warnings` 标注"tick 未知，跳过对齐校验"，并记入 deploy_gate 待办。
3. **盘口一致性（核心安全闸）**：反解出的 `price`（原始价）必须与 `real_symbol` 在同一 `trade_datetime` 的**实际市场价**（`bar_60m`/`hourly` 中该真实合约的 close，或实时 tick）偏差 ≤ `PRICE_TOL`（默认 0.5%，可配）。
   - 偏差超限 → **阻断**（"反解价与盘口不符，可能偏移/换月映射错误"）。这是防止"反解到错误合约/错误价格"的最后一道闸。
4. **涨跌停**：若当日该品种有涨跌停价（来自 `daily_bar.settle`/涨跌停表），`price` 须在 `[limit_down, limit_up]` 内，否则阻断。
5. **方向合法性**：`LONG`/`SHORT` 与合约可空性一致（期货普遍可空，此条默认通过，预留）。

## 4. 编排流程（service.py `resolve_signal_to_order`）

```
reverse_request
  │
  ├─[guard] symbol 非连续 → 阻断
  ├─[guard] direction == FLAT → 返回空单(blocking)
  │
  ├─ ① roll_policy: product→main_symbol(real_symbol) + 交割月护栏
  ├─ ① reverse_price: cum_offset(t) → real_entry/real_stop (unadjust_price)
  ├─ ③ lot_sizing: lots(给定或按R) + multiplier + notional
  ├─ ④ validator: 可交易/tick/盘口一致性/涨跌停
  │
  └─ ExecutionOrder(real_symbol, price, lots, blocking_reasons, warnings, meta)
```

任一阻断项 → `blocking_reasons` 非空，`lots=0`，订单禁止下发；非阻断问题进 `warnings`。

## 7. 验收标准
- **单元**：给定 `RB888` + 已知 `cum_offset` + 已知 `main_symbol`，反解 `price` 与手算一致；交割月内合约被阻断；tick 不对齐被标 warning/阻断。
- **集成（进 deploy_gate）**：
  1. `app/execution` 可 import；
  2. 路由 `/execution/reverse` 已在 `api_router` 注册；
  3. 选 3 个品种跑一轮反解，输出 `real_symbol` 与 `futures_symbol.main_symbol` 一致、`price` 与盘口偏差 ≤ 容差；
  4. `futures_symbol.price_tick` 非空覆盖度 ≥ 95%（否则告警）。
- **盘口一致性判定脚本**（§3.1 口径风险用）：作为 deploy_gate 子项，确认信号价空间假设。

## 9. 实测勘误与落地决议（CB 2026-10-02，云端库直查）

CB 落地时在云端权威库（`timescaledb` / `futures`）实测，发现 PRD 原假设与真实数据模型有 5 处不符，已据实修正代码（非照搬假设）：

| # | PRD 原假设 | 真实库实测 | 落地修正 |
|---|---|---|---|
| 1 | `main_contract_map.main_symbol` 即真实可交易合约（如 RB2510） | `main_symbol`=连续码（`FG888`）；**真实合约在 `underlying` 列**（`FG2701`） | `select_real_contract` 改取 `underlying` 为 `real_symbol` |
| 2 | `futures_symbol` 含真实合约，可查 `multiplier`/`active`/`exchange` | `futures_symbol` 仅 73 个 888 连续码，**无真实合约** | 新增 `real_contract_metadata`：真实合约元数据**回退同品种 888 连续码**（`multiplier`/`exchange`/`price_tick` 为品种级不变属性，语义正确、非编造） |
| 3 | `bar_*`/`hourly_bar` 含真实合约小时线，供盘口一致性闸 | `hourly_bar`/`bar_*`/`minute_bar` **只存 888 连续序列**，无真实合约分钟/小时线 | 一致性闸源改为 `contract_daily`（真实合约日频价，原生大小写符号）；日频参照引入 `DAILY_TOL`(2%)/`BLOCK_TOL`(5%) 两级阈值 |
| 4 | 融合信号价为「已后复权价」，反解 `real = adj − offset` | 888 序列收盘是**原始连续价**（RB888 c=3112、`cum_offset`=2400；若已后复权则 real=712 不可能） | `price_space` 默认 `"raw"`（偏移置 0）；仅显式传 `"adj"` 才减偏移。`ReverseRequest` 增 `price_space` 字段 |
