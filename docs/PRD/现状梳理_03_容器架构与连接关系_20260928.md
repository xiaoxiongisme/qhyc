# 现状梳理 03 · 容器架构与连接关系

> 盘点时间：2026-09-28 ｜ 盘点人：WorkBuddy
> 依据：`docker-compose.yml`（本地）、`docker-compose.cloud.yml`（云端）、`Dockerfile`、`.dockerignore`、`docker ps` 实测

---

## 0. 先看结论（4 条）

1. **4 个容器**：`qhyc-timescaledb`（库）、`qhyc-api`（HTTP 服务）、`qhyc-scheduler`（常驻调度）、`qhyc-pipeline`（M8 决策链路）。本地实测 4 个都在 `Up`。
2. **没有独立的 web 容器** —— 前端在 Docker 多阶段构建里被 `node:20-alpine` 编译成 `web/dist`，由 **api 容器静态托管**。所以"前端页面存在但看板没起来"的原因是：dist 由镜像提供，而本地 compose 又把 `./web/dist` 只读挂进去覆盖。
3. **同一份编排有两套**：本地用 bind mount 挂源码（改代码免重建），云端用 named volume + 镜像内代码（零宿主路径依赖）。**这个差异是后面一系列"本地能跑云端不能跑"问题的根源。**
4. **本地 compose 里 `POSTGRES_HOST=timescaledb` 与 `DATABASE_URL=…host.docker.internal:15432` 并存，而代码里 `DATABASE_URL` 优先** → **本地容器实际连的是云端库**，本地 `qhyc-timescaledb` 基本只服务于裸机脚本。

## 3. 本地 vs 云端编排差异（关键）

| 项 | 本地 `docker-compose.yml` | 云端 `docker-compose.cloud.yml` |
|---|---|---|
| 源码 | **bind mount**：`./app`、`./scripts`、`./web/dist` 只读挂入 → 改代码免重建 | **不挂**，全部来自镜像（`COPY app ./app` / `COPY scripts ./scripts`） |
| `config` | `./config:ro` 挂载 | **不挂**（注释明确：空目录会把镜像内配置盖没） |
| `runtime` | `./runtime` bind mount（**因此本地有 250+ 调试脚本**） | named volume `runtime`（**初始为空**） |
| 数据库卷 | `./pgdata` bind mount（本地有数据） | named volume `pgdata`（云端独立数据盘） |
| DB 端口 | `5432:5432` 映射宿主 | **不映射**，且 `-clisten_addresses=localhost` |
| DB 连接 | `DATABASE_URL → host.docker.internal:15432`（云端隧道） | 未设 DATABASE_URL → 走 `POSTGRES_HOST=timescaledb`（本网络内） |
| pipeline 源码 | `${WB_PIPELINE_PATH}` bind mount（WB skill 只读） | 镜像内 `/app/pipeline_src`（由 `vendor_pipeline_src.py` 内化） |
| 简报目录 | `${QH_BRIEF_PATH}:ro` | named volume `qh_brief:rw` |
| imports | `${LOCAL_QH_PATH}` | named volume `imports`（可空） |

### 3.1 这个差异造成的后果

| 后果 | 机制 |
|---|---|
| **云端复权作业必然失败** | scheduler 调用 `/app/runtime/_adjust_bars.py`、`_adjust_minute.py`；云端 runtime 是空 named volume，且 `runtime` 被 `.dockerignore` 排除、不进镜像 → 文件不存在 → 日志"找不到增量脚本"后静默返回 |
| **云端可能缺配置** | `config/local.yaml` / `cloud.yaml` 被 `.gitignore` 排除；`COPY config ./config` 只在"构建机上恰好有这两个未入库文件"时才把它们打进镜像 → **不可复现** |
| **云端代码与 git 分叉** | 曾用手写补丁脚本 `_patch_minute*.py` / `_patch_inventory.py` 直接改云端容器内源码 |
| **本地与云端行为不一致** | 本地改 `app/` 立即生效（挂载），云端必须重新 build + 推镜像 |

## 4. Dockerfile 构建范围

```
阶段1  node:20-alpine (webbuilder)
   COPY web/package.json → npm install → COPY web/ → npm run build → /build/dist
阶段2  python:3.11-slim
   COPY requirements.txt → pip install
   COPY app ./app
   COPY scripts ./scripts
   COPY config ./config
   COPY --from=webbuilder /build/dist ./web/dist     ← 前端产物进镜像
   COPY vendor/pipeline_src ./pipeline_src
```

`.dockerignore` 排除：`web/node_modules`、`web/dist`、`web/package-lock.json`、`*.md`、**`runtime`**、`logs`、`imports`、`pgdata`。

> **关键**：`runtime` 被排除 → 任何放在 `runtime/` 里的脚本**永远不会出现在镜像里**，但 `app/scheduler.py` 却在定时调用其中两个（复权）。这就是 P0 断裂点。

## 5. 初始化 SQL（`db/init/`，15 个）

`01_schema.sql`、`02_seed_main_contracts.sql`、`03_sector_tables.sql`、`04_model_weights.sql`、`05_backtest_m4_fix.sql`、`06_caliber.sql`、`07_reversal_gate.sql`、`08_member_position.sql`、`09_inventory.sql`、`10_spot_basis.sql`、`11_contract_daily.sql`、`12_vol_forecast.sql`、`13_fut_kline.sql`、`14_contract_code.sql`、`15_pipeline.sql`

由 `docker-entrypoint-initdb.d` **仅在首次初始化空数据卷时执行**；已有数据的库（本地 pgdata、云端 pgdata）不会重跑 → 后续 schema 变更靠 `scripts/ensure_fundamental_schema.py` 等幂等脚本补。

## 6. 健康检查与重启

| 容器 | 本地 | 云端 |
|---|---|---|
| timescaledb | `pg_isready` 10s/5次 | 同 + `start_period: 60s` |
| api | 继承 Dockerfile 的 HTTP 检查（healthy） | 同 |
| scheduler | **禁用**（不监听端口） | 禁用 |
| pipeline | `python -m app.pipeline.healthcheck` 5m/30s/3次 | 同 |

`restart: unless-stopped` 全部一致。

## 7. 问题清单（容器侧）

| # | 问题 | 严重度 | 建议 |
|---|---|:--:|---|
| C1 | 调度依赖的复权脚本在 `runtime/`，不进镜像 | **P0** | 移入 `scripts/` 并提 git |
| C2 | `config/*.yaml` gitignore，镜像配置不可复现 | **P0** | 提供 `.example.yaml` 入库 + 构建时渲染，或改纯 env 覆盖 |
| C3 | 本地 `DATABASE_URL` 指向云端隧道，`POSTGRES_HOST` 形同虚设 | **P0** | 二选一并写死；本地应连 `timescaledb`，云端由 compose 覆盖 DATABASE_URL |
| C4 | 云端曾用补丁脚本直接改容器内源码 | **P0** | 回滚 + 走镜像发布 |
| C5 | 前端无独立服务，dist 由 api 托管且本地又被挂载覆盖 | P1 | 明确"构建进镜像"还是"挂宿主"，二选一 |
| C6 | 本地/云端两套 compose 挂载策略完全不同 | P1 | 抽成 `compose.base.yml` + override，减少分叉 |
| C7 | 云端 `imports` named volume 可空，依赖它的功能会失败 | P2 | 明确云端是否需要 imports |
