## 1. 部署模型（用户 2026-09-29 拍板，已定稿）

```
云端（主）                                本地（从）
├─ qhyc-scheduler 全量作业                 ├─ qhyc-scheduler CLOUD_SYNC_ENABLED=1
│   采集 / 重建 / 派生 / 回测 / 因子 / 监控  │   → 只注册 cloud_local_sync（云→地）
├─ 云端库（唯一真源）                       └─ 本地库（只连本地库，**不连云端库**）
└─ 定时任务完成后 → sync_cloud_local 推送 ↓
```

* **取消双跑**：本地实例顶部 `CLOUD_SYNC_ENABLED=1` 直接 early-return，
  只注册 `cloud_local_sync`，其余作业一律不注册。
* 云端库 = 真源；本地库 = 同步目标。**所有 schema 迁移两端同构执行**。

## 4. 可扩展：后续如何增删因子 / 策略

**加一个因子（4 步）**
1. 写计算脚本（幂等 upsert → `factor_value`，照抄 `compute_factor_v1v6.py`）；
2. `factor_registry` 插一行（`enabled=false, default_weight=0, max_weight ≤ 0.05`）；
3. `python scripts/admit_factors.py --factors <id> --apply` 跑六道闸门；
4. 通过后把 `default_weight` 调到目标值；`max_weight` 之和须 ≤ 1.0。

**加/减一个因子（运维）**：改 `factor_registry.enabled` 即可；
`enabled=false` 走恒等路径（T18 双向等价，回归待补）。

**加一个策略**：`app/strategies/registry.py` 里加一条 `StrategySpec`
（`key/freq/caliber/fn/default_params/enabled`），或运行时 `register(...)`；
再在取数时用 `app.data.load(symbol, freq, caliber)` 保证口径唯一。

**加一个数据口径**：`app/data/caliber.py` 的 `ROUTES[(freq, caliber)]` 登记；
未登记即抛 `CaliberError` —— 防止"随手换表"造成跨表口径漂移。

## 5. 因子准入实测结论（重要，需人工确认）

`python scripts/admit_factors.py --factors ... --since 2020-01-01 --horizon 5`

| 因子 | IC(h=5) | t | 结论 |
|---|---|---|---|
| `f_vol_z` | 0.008 | 1.88 | **FAIL** —— IC 与 t 均不过，后半段衰减 |
| `f_vol_ratio` | 0.007 | 1.75 | **FAIL** |
| `f_atr_pctile` | 0.004 | 0.76 | **FAIL** |
| `warehouse_receipt_z` | 0.031 | 4.87 | **FAIL（新）** —— 与 `inventory_z` 面板 \|ρ\|=**0.96** |
| `member_net_z` | 0.012 | 1.66 | **FAIL** |
| `inventory_z` | −0.058 | −1.76 | **FAIL**（\|t\|<2） |

两条必须人工拍板的发现：

1. **借鉴来的 V1 量价因子（VR/VZ/ATR分位）在日频 h=1/h=5 上没有 alpha**
   （IC≈0.004~0.008，t<2）。已按 PRD 铁律保持 `enabled=false`，
   **不建议**为"用上借鉴项"而强行开权重。
2. **仓单因子与库存因子 \|ρ\|=0.96** —— 要么是真共线（同一信息的两个口径，
   同时计入等于重复加权），要么是**口径 bug**（两者数据同源错位）。
   建议下一步人工核对 `warehouse_receipt` 与 `inventory` 的取数逻辑。

## 7. 一键部署 / 回滚

```bash
bash scripts/deploy.sh local          # 本地
bash scripts/deploy.sh cloud          # 云端：git pull → build → up -d → 迁移 → 重启
bash scripts/deploy.sh cloud --no-build
SKIP_MIGRATE=1 bash scripts/deploy.sh cloud
```

**回滚**
* 代码：`git revert` / 回到上一个 tag（代码是唯一真源）；
* 数据库：迁移均为**加法**（建表/加列/加约束/元数据更新），
  无 DROP 表/列，故代码回滚即可；确需撤销时按 `migrations/00X` 反向操作；
* 功能开关：全部新功能默认关闭（`FACTOR_*` 除外，因子计算与 IC 监控为纯旁路写入）。

**验收清单**
1. 调度日志出现 `[scheduler][ASSET] 生产脚本自检通过 9 个`；
2. 云端实例注册 `16:20 factor_v1v6_daily` / `16:45 factor_ic_monitor_daily`；
3. 本地实例出现 `SYNC-ONLY mode: registered cloud_local_sync`；
4. `SELECT sum(max_weight) FROM factor_registry` ≤ 1.0（启动校验可过）；
5. `SELECT count(*) FROM factor_value v LEFT JOIN factor_registry f USING(factor_id)
   WHERE f.factor_id IS NULL` = 0。
