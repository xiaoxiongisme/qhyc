# 主力合约口径裁决（丙/丁方案）— PRD 增补

> 增补对象：《量化系统-数据层PRD》(docs/PRD_最终版_20261001.md) 模块④「合约管理」与 P0-1 执行反解层设计。
> 事实来源：G2（`scripts/build_roll_segments.py`）实测 + `scripts/infer_main_contract.py` 价格匹配反推（2026-10-03 ~ 10-04）。
> 裁决日期：2026-10-04。裁决人：用户（采纳 CB 推荐的丙/丁，并明确**允许交易非最大持仓合约**）。
> ⚠ 2026-10-04 WB 评审注入修正（各节以「WB 修正」标注）：§3.2 信号连续取舍与 +8h 缺陷保留、§4.1 反解改用下单时刻价 + OI 排名 WARN、§4.3 `roll_segment` 事实纠正（不能「复用不改动」）、§4.5 近月流动性护栏本方案内落地（不外挂）、§5 G2 稳定性判据、§6/§7 历史覆盖验收、§8 R1/R2/R6 补强。

## 0. 一句话结论
**采用丙/丁方案，且允许策略交易「非最大持仓」合约**：888 连续序列（信号源）保留其外部选合约规则；执行反解**按价格匹配**落到 888 当日实际所跟合约（`dim_main_contract_inferred.inferred_symbol`），不再强制对齐 `main_contract_map.underlying`（持仓量最大口径）。`main_contract_map.underlying` 降为「参考主力」可观测字段。

## 1. 背景与问题（为何需要裁决）
- G2 实测暴露：`MA888` 连续序列跟踪**近月 MA2610**，而 `main_contract_map.underlying` 说主力是**远月 MA2701**，近远月价差 878 点 / 29%。这不是采集缺口，是**两套选合约规则不一致**。
- 888 连续序列（新浪/天勤主连）的选合约规则 ≠ `main_contract_map`（持仓量最大）口径；不同品种规则不同（已实证）：
  - `MA888` 恒跟**近月**（MA2610）
  - `EG888` 跟**次月**
  - `FG/SA` 仅 **159 合约**一致（与主力换月不同步）
  - 其余品种待全量核实
- 旧 P0-1 反解层设计「取 `main_contract_map.underlying` 作真实合约」，在 MA 上会落到 MA2701，与 888 信号价 3384 vs 盘口 2972 偏差 13.86%，被一致性闸 BLOCK——但这是**口径冲突**，不是数据 bug。

## 2. 候选方案回顾（甲/乙/丙/丁）
- **甲 以 888 为准（改写 main_contract_map 跟随 888）**：信号/执行一致，但「主力」语义被篡改为数据源拼接规则，对 MA 等实为近月，流动性/语义失真。
- **乙 以标准主力为准（重建连续序列跟随 main_contract_map，弃用外部 888）**：口径语义正确，但需重建历史连续序列、**作废旧 888 回测锚点**、工程量大。
- **丙 双轨并存，反解按价格匹配裁决（不强制一致）** ✅ 采用：保留 888 作信号连续，`main_contract_map` 作执行主力参考，反解按价格匹配落 888 所跟合约。
- **丁 工程化落地丙** ✅ 采用：给每个品种在 `dim_variety` 标注「888 跟随规则」（NEAR_MONTH / NEXT_MONTH / TRUE_MAIN / FIXED_MONTH），系统化双轨。

## 3. 裁决结论（丙 + 丁 + 允许非最大持仓）
1. **允许策略交易非最大持仓合约**：信号所跟合约（888 实际跟踪的，可能是近月/次月）→ 即为执行合约。不强制对齐持仓量最大的「标准主力」。
2. **信号连续 = 888（保留外部来源，raw 连续价空间）**，研究/信号层不变。⚠ **WB 修正**：此条等于**回退**《数据层PRD》§6.2「以自管后复权 `roll_segment` 替代 sina 888」的方向——本方案信号继续沿用厂商已拼接的 sina 888。后果：(a) **+8h 时区错标缺陷（T4/R7，P0）继续存活于信号路径**，须在口径注册表显式标注；(b) `roll_segment`（main 口径）退化为仅因子/P&L 研究用连续，与信号成「两套连续」并存，多模块拼装须标注各自所用连续，防静默错配。若未来改回信号用后复权输出，则执行反解必须同步改用 main 口径，否则跨换月对不上合约。
3. **执行合约 = `dim_main_contract_inferred.inferred_symbol`**（按 trade_date + variety 价格匹配反推的 888 当日实际所跟合约），与信号价天然一致。
4. **`main_contract_map.underlying` 降为「参考主力（OI 最大）」**：仅用于可观测/告警，不约束执行。
5. **品种级 follow_rule 标注（丁）**：`dim_variety.continuous_follow_rule` 枚举，全品种 100% 标注。

## 4. 对现有设计的修正（重点审查项）
### 4.1 反解层（app/execution）修正
- 旧：`real = main_contract_map.underlying`（P0-1 设计）。
- 新：`real = dim_main_contract_inferred.inferred_symbol`，并带 `caliber` 标签（= 该品种 `continuous_follow_rule`）。
- ⚠ **WB 修正 — 反解须用下单时刻价，非日线收盘**：`infer_main_contract.py` 目前用日收盘反推（:13），但实盘订单在盘中多时刻；临换月盘中 888 价归属模糊，且 sina 888 有 +8h 错标（T4/R7），时间戳对齐脆弱。须改为：**用下单时刻的 888 价 vs 当时各合约价**反解 `inferred_symbol`（新增 `reverse_resolve_at(symbol, when)` 接口，复用 `contract_daily` 当日全部合约快照 / 或盘中 tick 缓存）。
- `main_contract_map.underlying` 仅作 WARN 对照：当 `inferred_symbol != underlying` 时记一条 WARN（口径差异可观测），**不再 BLOCK**。
- ⚠ **WB 修正 — 增 OI 排名 WARN**：仅比 `underlying` 不足以捕获静默错配（TRUE_MAIN 品种 `inferred == underlying` 时 WARN 不触发）。新增：当 `inferred_symbol` 的持仓量排名**不符合**其 `follow_rule`（如 NEAR_MONTH 却非最近月、TRUE_MAIN 却非 OI 最大）时，亦记 WARN，提升可观测性。

### 4.2 一致性闸修正
- 旧闸：888 价 vs `contract_daily` 盘口价偏差 > 5% → BLOCK。
- 新闸：先按 `inferred_symbol` 取盘口价比对；偏差 > 5% → BLOCK（真数据问题）；`inferred` 与 `underlying` 不一致属**预期口径差异** → WARN，不阻断。

### 4.3 roll_segment（WB 修正：不能简单「复用不改动」）
- ⚠ **事实纠正**：经核代码，`build_roll_segments.py` 换月真源 = `main_contract_map.change_flag`（`load_change_points`，:89-111），`contract_code` 由 `contract_at()` 解析为 `main_contract_map.underlying`（持仓量最大口径，:148-161）。即 `roll_segment.contract_code` 对 MA 存的是 **MA2701（OI 主力）**，**并非** 888 实际跟踪的 **MA2610（近月）**。文档原「已固化 888 实际所跟合约」与代码相反，须更正。
- **二选一，不得「复用不改动」**：
  - **路径 A（推荐，与 §3.2 一致）**：信号用 raw 888，本方案执行反解走 `dim_main_contract_inferred.inferred_symbol`，**`roll_segment` 不进信号/执行热路径**，仅作因子/P&L 研究连续。此时 `roll_segment.contract_code`（main 口径）与执行合约（近月口径）天然不同属预期，§4.2 一致性闸只比 `inferred_symbol`，不比 `roll_segment`。
  - **路径 B（若未来信号改回后复权输出）**：须**重建** `roll_segment`，将 `contract_code` 与换月真源改为 `dim_main_contract_inferred.inferred_symbol` 口径（即按 888 实际所跟合约切段），否则信号连续（main 口径）与执行合约（近月口径）跨换月错位。
- `change_source` 已记，可审计，保留。

### 4.4 股指特殊处理（与 Msg10② 协同）
- CFFEX（IF/IC/IH/IM/T/TF/TS/TL）CLOSE_TODAY 仅存档、不入实盘/回测（另立项，本方案不覆盖）；其 888 跟随规则仍须标注，口径标签与 `is_archive_only` 协同。

### 4.5 近月流动性护栏（WB 修正：本方案内落地，不外挂 R2）
- ⚠ 原 R2 把护栏「并入 Msg10③ roll_segment 换月治理」——意味着**上线时无护栏**，是实盘最高优先级风险。本方案内显式落地：
  - 当 `inferred_symbol` 的 `continuous_follow_rule ∈ {NEAR_MONTH, NEXT_MONTH}` 且**剩余交易日 < N（默认 5 个交易日）** 时：禁止新开仓 + 强制提前换月至下一跟进合约。
  - N 与换月触发参数并入 Msg10③ 的 `roll_segment` 换月治理参数表；上线前在 `reverse_price` / 下单前置校验实现，fail-loud。
  - 近月价差放大已在展期成本模型（§6.2 双轨显式展期成本）覆盖，但**频度**须随近月跟随重标定（见 §8 R4 回测影响）。

## 5. fail-loud 守卫（呼应 G8 CI 门禁）
- **G1（未标注即失败）**：`dim_variety.continuous_follow_rule IS NULL` → 该品种执行层**显式 ERROR**，禁止静默默认（杜绝「未知→有值」类静默失效）。
- **G2（无匹配即失败）**：`infer_main_contract` 某 (品种,日) 价格匹配 diff > MATCH_TOL（0.5%）→ ERROR 并阻断该品种反解；旧 P0-1 测试报告称「元数据回退 888 设计内」，**本方案改为显式降级 WARN，且回退前必须记录**，禁止静默回退。
  - ⚠ **WB 修正 — 稳定性判据防静默错配**：G2 仅捕获「无任何合约匹配（>0.5%）」，不捕获「在 0.5% 内但匹配错合约」。对近/次/主力收盘价常 <0.5% 的品种（平/小 contango），会静默路由到错误合约 → 真实滑点/成本错位无告警。修正：播种推断改用**「窗口内最长连续跟踪」稳定性判据**（取 888 在 N 日窗口内持续匹配同一合约者），而非逐日最小差；并以 sina 已知跟随规则交叉校验，降低误判。
- **G3（覆盖门禁）**：全品种 `continuous_follow_rule` 覆盖率必须 100%；CI 启动自检失败时整体 fail-loud。
- **G4（可观测）**：`inferred != underlying` 的差异率每日统计入数据质量面板（PRD § 数据质量面板）。

## 6. 落地步骤 / 迁移
- **迁移 025**：`dim_variety` 加列 `continuous_follow_rule text`（枚举：NEAR_MONTH / NEXT_MONTH / TRUE_MAIN / FIXED_MONTH），**默认 NULL（强制标注，不设静默默认值）**；并加 `is_archive_only bool`（股指存档标记，与 Msg10②协同）。
- **播种脚本**（扩展 `infer_main_contract.py` 或新脚本）：全品种跑价格匹配（⚠ WB 修正：改用「窗口内最长连续跟踪」稳定性判据，非逐日最小差），自动推断 follow_rule（近月→NEAR_MONTH / 次月→NEXT_MONTH / =主力→TRUE_MAIN / 固定月→FIXED_MONTH），输出待人工抽检清单。⚠ **WB 修正 — 历史覆盖依赖**：推断依赖 `contract_daily` 对 84 品种**全历史**完整；任何缺口 → 该 (品种,日) 无 `inferred_symbol` → 回测/反解空洞。播种前须先校验 `contract_daily` 历史覆盖，缺失品种列入补采清单。
- **反解层改造**（`app/execution/*`）：`real` 改取 `inferred_symbol`，带 `caliber` 标签；`main_contract_map.underlying` 降级为 WARN 对照。
- **一致性闸改造**：先 `inferred` 比对，偏差>5% BLOCK；口径差异 WARN。
- **单测**：给定 MA 某日 888 价 → 落 MA2610（NEAR_MONTH），且 WARN 记录 `underlying=MA2701` 差异。
- **CI 自检**：覆盖率 100% + 无 NULL + 全品种匹配率统计 + ⚠ **WB 修正**：`dim_main_contract_inferred` 对回测窗口内**全 (品种,交易日) 覆盖 100%**（历史空洞数 = 0，fail-loud）。

## 7. 验收 / 门禁
- 全品种 `continuous_follow_rule` 覆盖 100%、无 NULL。
- 全品种价格匹配一致率（MATCH_TOL 内）统计，无匹配品种数 = 0（fail-loud）。
- 反解端到端：MA 落 MA2610、EG 落次月、FG/SA 落 159，与 888 价偏差 < 0.5%（⚠ WB 修正：须含**盘中下单时刻**反解用例，非仅日收盘）。
- `inferred != underlying` 差异率入数据质量面板。
- ⚠ **WB 修正**：`inferred_symbol` 的 OI 排名不符合 `follow_rule` 的告警率入数据质量面板（补足 TRUE_MAIN 品种 WARN 不触发的可观测盲区）。
- ⚠ **WB 修正**：回测窗口内 `dim_main_contract_inferred` 历史空洞数 = 0（否则回测切片沉默缺失）。

## 8. 风险 / 存疑（请 WB 审查重点）
- **R1**：目前仅 MA/EG/FG/SA 实证，全品种 follow_rule 需逐个核实（自动推断 + 人工抽检）。自动推断可能误判（如某品种主力恰在近月，则 NEAR_MONTH 与 TRUE_MAIN 难分），需设抽检阈值。⚠ **WB 补强**：全品种推断依赖 `contract_daily` 对 84 品种**全历史**完整；任何缺口 → 该 (品种,日) 无 `inferred_symbol` → 回测/反解空洞。CI 100% 前须先验证历史覆盖（见 §6/§7 新增项）。自动推断改稳定性判据（见 §5 G2 修正）。
- **R2**（WB 已在 §4.5 本方案内落地，不外挂）：近月流动性护栏已显式写入执行前置校验；剩余风险见 §4.5。
- **R3**：本方案使「执行合约 ≠ 标准主力」，对需要标准主力对冲/套利的场景不适用（当前策略无此需求，已确认允许非最大持仓）。
- **R4**：旧回测锚点若曾假设 `underlying`=执行合约，本修正后锚点口径变化，重跑前需重新确认（与 +65% 漂移排查同源，需分离变量）。
- **R5**：与 Msg10② 股指 `is_archive_only`、Msg10⑤ G9 退役 `continuous` 的协同边界需明确（本方案只动 `main_contract_map` 语义与反解层，不动 `continuous` 表）。
- **R6**（WB 新增）：`follow_rule` 枚举（NEAR/NEXT/TRUE/FIXED）可能不足以覆盖全部品种（如「最活跃」「次远月」等规则；FG/SA 的 FIXED_MONTH 需明确具体月份列表）。建议：无法归类者设 `CUSTOM` + 逐品种显式 `follow_month_list`，不靠自动推断兜底；自动推断仅用于初筛，最终以人工标注为准。
