## 二、用户提出的 L0/L1/L2 分层架构 —— 现状逐层核对

用户的理解：**L0（1分钟）生成后复权 → L1（5/15/30/60分钟）由 L0 合成 → 日线保留采集版并后复权**，三层口径一致。

### 现状对照

| 层 | 你的设计 | 实际实现 | 一致？ |
|---|---|---|---|
| **L0** | 1m 后复权（`minute_bar_adj`） | 1m **前复权**（`adjust_minute.py`：`cum[i]=Σ_{k>i}` 锚定最新段） | ❌ **方向相反** |
| **L1** | 由 L0 合成，统一口径 | `bar_5m/15m/30m/60m` 来自**独立采集**（bar_* 各自的 KQ.m@ 源），**不是由 L0 合成**；后复权靠 `roll_segment` 运行时套用 | ⚠️ **路径不同** |
| **L2 日线** | 采集一份 + 后复权 | `daily_bar`（4 源，**未复权**）+ `fut_kline daily`（continuous，未复权）；**无后复权日线** | ❌ **缺后复权** |

### 三个架构级缺口

| # | 缺口 | 影响 |
|---|---|---|
| **A** | **L0 是前复权而非后复权** | 与"后复权唯一口径"直接冲突；且前复权"每次换月需全历史重写"（caliber.py 原话），`adjust_minute.py` 增量模式每次都全量重算换月品种 → 云端 5,700 万行表的维护成本来源 |
| **B** | **L1 不是由 L0 合成，而是独立采集 + 运行时套 roll_segment** | 好处是省了 L0→L1 聚合开销；但**L0 与 L1 的换月检测必须一致**才敢混用。`adjust_minute.py` 注释已说明这个设计（1m 振幅太小检不准，用 15m 双门检测定位换月）——**这是合理的，但它意味着 L0/L1 的一致性依赖"共用 15m 检测器"这个约定，而非结构性保证** |
| **C** | **日线无后复权** | `roll_segment` 只覆盖 min5/15/30/60，**没有 daily** → 日线/小时线回测只能用 continuous |

### 结论

> **你的架构方向是对的（后复权 + 分层一致），但当前实现有三处偏离：L0 方向相反、L1 非合成而是独立采集+运行时套偏移、日线缺后复权。**
>
> 若要完全对齐你的设计，需要：①L0 改后复权（等于重写 `adjust_minute.py`）②`roll_segment` 补 daily/hourly 覆盖 ③先解决"从未调度"问题。
> 这是**工程量较大的口径重构**，建议单独立项，不夹在本次清理里。

## 三、`minute_bar_adj` 判定：**是前复权，且每天仍在被生成**

### 口径确认 —— 是前复权

`scripts/adjust_minute.py` 文件头原文：

```
"""1 分钟原始数据(minute_bar, 888 主连)加法平移前复权 → minute_bar_adj。
...
前复权（锚定最新段）：cum[i] = Σ_{k>i, roll[k]} cc888[k]；跨换月 bar 收盘差→0。
```

调度器注释（`scheduler.py:1882`）也写「前复权锚定最新段，新换月会整体平移历史」。

### ⚠ 与你的问题不同：它**不是**"没有引用消费"

| 消费者 | 位置 | 状态 |
|---|---|---|
| `cont_adj` 的**唯一上游** | `scheduler.py:920` 05:00 重建：「cont_adj←minute_bar_adj」 | **活跃** |
| 每日 04:30 增量生成 | `scheduler.py:1218` `id="adjust_minute_bar_adj"` | **活跃，每日运行** |
| 口径路由 | `caliber.py:72` `("1m","cont_adj") → minute_bar_adj` | 注册 |
| `barstore.py:55,64` | 声明 `oi` 恒 0 | 注册 |

**规模**：云端 **9,289 MB**（本地无此表）。`scheduler.py:939` 注释称"云端这两个 kind 合计约 1,992 万行"。

### 判定

> **不能直接删。** 它不是"无消费的孤立表"，而是：
> ① `cont_adj` 的唯一上游；② 每日 04:30 自动增量生成；③ `caliber.py` 注册路由。
>
> 但它是**前复权**，与你"后复权唯一口径"的架构目标冲突。
>
> **建议：随 `cont_adj` 一并退役**（顺序：先摘 04:30 作业 + 摘 05:00 重建里的 cont_adj 分支 → 备份 → 删两张表 → 删 `minute_bar_adj`）。
> 保留 `minute_bar`（原始 L0，未复权）作为唯一可再生基础。
> 将来若做后复权 L0，从 `minute_bar` 重算即可。
