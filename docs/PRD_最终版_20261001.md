## 1. 项目概述与目标

构建一个**本地运行的期货量化交易系统**，在统一数据底座上具备四项能力：

1. **预测系统**（CB 主导）：基于数学/统计/机器学习模型，预测下一交易日涨跌方向与幅度。
2. **交易策略判定**（WB 主导）：按**融合策略 V3.4**，在小时线级别判定每个品种的持仓状态与开/平/反手信号。
3. **信号推送**（WB 主导）：将信号实时推送至微信/企微/钉钉/飞书，含止损位、保本位、持仓简报。
4. **回测与研究**（WB+CB）：手动调参回测、鲁棒性测试、walk-forward 验证，纳入系统 UI。

**非目标（本期）**：自动下单执行、多用户账号体系、云端多租户（架构预留云端演进）。

> 一句话定位：**预测系统给"方向概率"，交易策略给"当下该不该动"，信号推送把结论送到手里，回测研究验证策略稳健性**——四者共用同一数据底座与同一套口径铁律。

## 2. 总体架构（分层）

```
[数据源] akshare(主,含新浪60分) ──┐
                                  ├─→ [采集/校准层] 入库 + tqsdk 补缺/比对 + 异常工单 + 小时线逐根增量
[校准源] tqsdk(天勤) ──────────────┘
                                       ↓
[数据层] PostgreSQL 16 + TimescaleDB
   · 运行时表：daily_bar(日线) / hourly_bar(小时线,逐根增量) / main_continuous(主连)
   · 回测底座：fut_kline 超表(freq×kind×symbol×trade_datetime，含 cont_adj 复权)
                                       ↓
[计算层] ┌─ 预测引擎（方向/幅度，模型库集成）            ← CB
         ├─ 交易策略引擎 fusion_signal（开/平/反手状态机） ← WB
         └─ 回测引擎（信号层 walk-forward + 组合层 FIFO 重放） ← WB/CB
                                       ↓
[服务层] FastAPI：行情 / 预测 / 信号 / 回测 / 数据更新 / 任务 / 异常 / 对接
                                       ↓
[展示层] React 看板（预测 / 信号 / 回测调参）+ 微信推送（pushplus/webhook）
```

**分层职责（一句话）**：数据层只负责"准确、单一口径地把数据落下"；计算层三个引擎各自独立、互不改写对方输出；服务层只做暴露；展示层只做呈现。

### 4.2 表架构（四表，用途不同，禁止混用）

| 表 | 周期 | 主键 | 写入方 | 用途 |
|---|---|---|---|---|
| `daily_bar` | 日线 | `(symbol, trade_date)` | `orchestrator.upsert_daily_bars` | akshare 主源+校准，日级特征/展示 |
| `hourly_bar` | 小时线 | `(symbol, trade_datetime)` | `HourlyCollector`（逐根增量 + 定时全量兜底） | **信号引擎实时读取**（按 `fusion.hourly_src` 单源） |
| `main_continuous` | 主连 | `(product, trade_date)` | `upsert_main_continuous` | 同时存裸价与复权价 |
| `fut_kline`（超表） | 全频率/全口径 | `(freq, kind, symbol, trade_datetime)` | `fdf/*` + `runtime/_build_daily_*` | **回测/研究底座**，含 `cont_adj` 复权权威 |

`fut_kline.kind ∈ {continuous, contract, cont_adj}`；`freq ∈ {daily, hourly, min15, ...}`；`adj` 列标记已/未复权段（回测只取 `adj=True`）。

### 4.3 获取与更新机制

#### 4.3.1 日线更新（路径 A，已接调度）

- 主源 akshare `futures_main_sina` → `daily_bar`（`src=akshare`，未复权拼接价）。
- 校准：tqsdk 补缺 + 二次比对，异常开 `anomaly_ticket`（不阻塞主源）。
- **频率**：每日三次 cron —— `12:00`(noon) / `16:00`(close) / 次日 `08:00`(night)。
- 增量幂等：`(symbol, trade_date)` upsert，断点可续；范围 `2015-01-01` 起。

#### 4.3.2 小时线更新（★逐根增量 —— 用户硬性要求）

> **需求：小时线更新必须"每完成一根小时线，更新一根"**，而非定时批量重抓整段。

**机制 `HourlyBarIncrementalUpdater`（扩展 `app/ingest/hourly_collector.py`）：**

- **触发**：每个交易时段内的小时 K 线**收盘时刻之后**增量采集。推荐组合：
  - (a) **分钟级 cron**：小时线收盘时点后 1 分钟触发（`:01`/`:31`/`:46`，覆盖白盘 10:15/11:30/13:30/14:15/15:00、夜盘 21:00/22:00/23:00/23:30/01:00/02:00/02:30 等，由配置化收盘时刻表驱动）；
  - (b) **轮询兜底**：每 5 分钟检测"比本品种上次成功更新更晚收盘的 bar"，补采遗漏。
- **行为**：只抓「自上次成功更新以来**新收盘**的小时 K」，**逐根 upsert** 到 `hourly_bar`（主键覆盖）。
- **定稿守卫**：最新一根距现在 < `settle_delay_sec=150s` 时等待定稿后重采一次覆盖（防收盘瞬间过渡值致反手）。
- **主源/兜底**：akshare 新浪 60 分钟主源；失败/限流 → tqsdk `get_kline_serial` 兜底（全品种**复用单 TqApi 连接**）。
- **断点续传**：记录每品种最后更新时间；历史回填用 `--prefer tqsdk` 并调大 `data_length`。
- **与既有机制互补**：保留 ① `16:00` close 档联动的全量快照 `collect_all()`（对齐/校准）、② 融合扫描每 15 分钟尾部 800 根刷新（容错）。逐根增量是"准实时主通道"，批量是"兜底校准通道"。

#### 4.3.3 回测底座 `fut_kline` 更新（非 scheduler 自动）

- `continuous`/`contract`：tqsdk `fetch_fdf.py` → `db_pg.save_bars`。
- `cont_adj`：`build_continuous.py` + `adjust_fdf.py` 重建（**先 `delete_bars` 清旧再插**，防脏累积）。
- `daily`（回测用）：由 hourly 聚合（`_build_daily_*.py`，含夜盘归属修正 ≥20:00 归下一交易日）。
- **触发**：手动 / CI（容器 `RUN_ON_BOOT=0`，避免重启重复全量回补）。数据更新后应重跑路径 B/C + 日线聚合，再跑回测。

#### 4.3.4 周/月维护（scheduler）

| 时间 | 任务 |
|---|---|
| 周六 06:00 | LSTM 周重训 |
| 周六 06:30 | 传导权重周重算（corr/granger/te/var） |
| 周六 07:00 | M4 周度回测 |
| 每月 1 日 06:30 | 模型权重月更（近 60 日准确率） |

> 【修订 2026-10-01 · 用户拍板】**复权口径切换**（演进自 9/22 与 9/30 两次裁定，以此为准）：
> 1. **`DEFAULT_CALIBER` 由 `continuous` 改为复权口径**；策略必须显式声明 caliber，禁止隐式依赖默认值。
> 2. **等差后复权 = 唯一回测口径**（目标态，落地载体 = #8 raw + roll_segment offset 的 as-of join，只追加、历史永不重算）。84 品种实测：等差 ATR 零失真（0% 品种），等比 87.8~90.2% 品种 ATR 失真——期货损益=点数差×乘数为线性，只能等差。

#### 4.3.5 一致性红线（口径铁律）

1. **单源消费**：信号引擎按 `fusion.hourly_src`（默认 `akshare`）读 `hourly_bar` 唯一口径；回测按 `(freq,kind,symbol,src)` 单源读 `fut_kline`。**杜绝双源混读**（两源 K 线时刻标记方式不同，会被当成两根喂指标，砍半周期）。
2. **剔除未收盘 K**：`drop_forming_bars` 丢弃 `now < dt` 的正在形成 K。
3. **定稿守卫**：`drop_unsettled` 剔除收盘距现在不足 `settle_delay_sec` 秒的最新一根。
4. **复权唯一权威**：回测复权价只取 `fut_kline.cont_adj`；`daily_bar`/`hourly_bar` 的 akshare 主连**未复权**。
5. **涨跌口径统一 `close`**（非 settle）。
6. **回测价格口径 = `continuous`**（= 同花顺真主连，50 笔成交逐笔比对 Δ=0.0），**非** `cont_adj`（旧回测系统的偏移价）。
7. **标签完整**：任何数据源入库带 `src`；回测/信号指定 `src` 读取。

### 4.4 复权标准（加法平移前复权）

- 主连换月仅一处「新旧合约价差」断层，正确修复是「把断层之前全部历史整体平移 delta」。
- 算法：`pick_dominant`（日持仓量最大为主力，`ROLL_CONFIRM=3` 日领先确认、只向前换）→ `delta=新(t-1)收−旧(t-1)收` → 前复权 `t` 前全部 `+=delta`；剔除未走完 K 与主力持仓不达标（`RELIABLE_OI=100000`、`RELIABLE_HOLD=20`）早期区间；`adj` 列标记。
- 口径归口：`fut_kline.cont_adj` 唯一权威；`main_continuous.adj_*` 另存主连复权裸价供线上特征。

## 5. 预测引擎（CB · 摘要 + 锁定裁决）

> 详细模型实现沿用旧 PRD §5/§16/§17/§18。本节保留**对编码有约束力的锁定裁决**，CB 照此实现，WB 照此复审。

### 5.1 特征工程

输入窗口：当日涨跌幅 + 前 5/20 根 K 涨跌幅；波动率、动量、Hurst、样本熵、ATR；Zigzag 拐点、Qi(ATR+MACD) 辅助。

### 5.2 模型库（按族）

变换类（傅里叶/小波）、统计时序（ARIMA/SARIMA/GARCH/卡尔曼）、状态概率（马尔可夫/HMM/贝叶斯/蒙特卡洛）、ML/DL（LSTM/GRU/Transformer/XGBoost/LightGBM/RF/GPR）、复杂系统（Hurst/样本熵/相空间重构）。

### 5.3 集成机制

- **状态门控**：Hurst 判定 trend/mean_revert 选择启用子集。
- **方向投票**：加权投票（权重每月按近 60 日回测准确率更新），起步涨/跌二分类。
- **幅度融合**：中位数点估计 + [P5,P95]。
- **输出契约**（v1 JSON，对接简报复用）：`symbol/target_date/as_of/run_id/direction/direction_prob/ret_point/ret_low/ret_high/confidence/participated_models/state`。

### 5.4 锁定裁决（⚠️ 编码必须遵守）

| 项 | 结论 |
|---|---|
| 涨跌口径 | **`close` 收盘价**（禁止回到 settle） |
| 反转门控 `gate_pct` | **2.0%**（验收只用池化口径，禁止调阈值迎合覆盖率） |
| 覆盖率门槛 | ≥15% 为**结构性未达**已知偏差，维持硬门槛、登记已知偏差 |
| 预测标的 | 仅主力连续合约（FG888 等） |
| 预测频率 | 每次数据更新后预测（一天三次：12:00/16:00/08:00） |

### 5.5 跨品种/大类传导

`sector_map` / `sector_index` / `transmission_weights`；先验+数据驱动（Granger/传递熵/VAR）融合；特征一律滞后防前视；权重每周重算。

## 6. 交易策略层（融合策略 V3.4）★ 定稿口径

> 源：`桌面/融合/终版资料/02_融合引擎与额外策略最终版` + `app/strategies/fusion_signal.py`。
> 本层与回测引擎**逐位一致（单一真源）**。线上引擎已落地 V3.4 并验收（10 项锚点偏差全 0）。
> **回归开关**：`fib_confl: false` + `add_max_lots: 1` = 逐位回到 V3.1。

### 6.1 五层结构

```
① 方向层（小时 EMA140）      只做顺势一侧（多或空）
② 入场层（小时线）           A 回踩重启(优先，须过斐波汇流) ∨ B 10根突破(补位)；全体须过 ADX(14)≥15 门控
③ 离场层（小时线·额外口径）   2×ATR 初始硬止损 + 2×ATR 吊灯 + 0.5R 保本；仅小时线收盘击穿才平仓
④ 执行层                    当根收盘成交；开仓恒 1 手；阶梯加码（至多 2 手，浮盈门槛 1.0×ATR）；
                            离场后冷却 3 根；单品种至多 1 仓
⑤ 风控层                    单笔风险封顶；保证金上限；月度熔断
```

**三条不可移除硬约束**：① 不设固定止盈（靠吊灯让利润奔跑）；② 不设结构止损；③ 移动止损只向有利方向移动，永不回撤。

### 6.2 方向层

- 小时 EMA140 方向（等价日线 EMA20）：`REF(C,1) > REF(EMA(C,140),1)` → 只做多；反之只做空；临界两侧都不做。
- 用**已收盘**小时线确认；指标取 `DIRPREV` = 上一根方向，避免未收盘值（无前视）。

### 6.3 入场层

- **A 回踩重启（优先）**：方向允许多 + `C>EMA20(H1)` + `L≤EMA20` + 上一根 `C<EMA20`（刚穿越回）。
  **斐波汇流门控**：`L`（空为 `H`）须落在「最近一个**已确认枢轴**低（高）→ 其后极值」这段"腿"的 **0.382 / 0.5 / 0.618** 回撤位 **±0.5×ATR** 内；不满足则本根回踩信号作废。
  斐波腿取枢轴用**本根做右侧确认**（`l[i-1] < l[i-2] and l[i-1] < l[i]`）、回看窗 `W=60`，天然**无前视**。
- **B 10 根突破（补位）**：方向允许多 + `C>前10根最高价(不含当根)` + `C>O`。**不受斐波汇流影响**。
- **ADX(14)≥15 全员门控**：A/B 两支都必须过；用**上一根**已收盘 ADX 判定（无前视），不满足则本根所有入场作废。
- 入场模式 `entry_mode ∈ {pullback, breakout, both, both_nm}`（默认 `both_nm`）。**两条支路必须都保留**（只做回踩净值腰斩、只做突破负期望）。

### 6.4 离场层

- 初始止损 `init_stop = entry ∓ sl_atr×ATR`（`entry` 取**加权均价**；未加码时 == 首次买入价）。
- 吊灯止损 `trail_stop = peak/trough ∓ trail_atr×ATR`。
- 保本 `be_trigger = first_px ± be_r×ATR`（默认 `be_r=0.5`，基准恒为**首次买入价**）；触发后止损上移至首次买入价。
- 当前生效止损 `cur_stop = 三者中最紧者`（多取 max / 空取 min）。
- **仅小时线收盘击穿 `cur_stop` 才平仓**（盘中插针无视）。
- ★ **「收盘判定」是本系统的 alpha 来源，不是缺陷**：任何"打到保本价即出"的机制都会被小时线插针反复踹出（实测基线会崩到 −142 万）。**保本只能由吊灯顺带承担，绝不引入新的盘中成交假设。**

### 6.5 执行层

- **close-only**：开仓价 = 开仓根收盘价；离场后冷却 `cooldown_bars=3`；单品种至多 1 仓。
- **利弗莫尔·阶梯加码**：开仓**恒为 1 手**；仅当同时满足
  ① 收盘**创入场以来新高**、② **浮盈达门槛**（`c[i] − first_px ≥ lots × add_thr_atr × ATR`，默认 `add_thr_atr=1.0`）
  才加 1 手（`add_max_lots=2`，即至多一次；门槛随手数线性抬升，是"金字塔"而非"倒金字塔"）。
  加码后 `avg_px` 更新为**加权均价**，生效止损仍是「初始止损 / 吊灯 / 0.5R 保本」三者中最紧者，**收盘判定**。
  不要求"吊灯已推进到加码后均价之上"（即**不做结构性保本**）。
- **加码的性质（须向下游如实传达）**：加码单约 53% 以亏损结束（亏损中位仅 −0.16R），但在 9 年样本上，**收到加码的交易贡献了全部净值**，未收到加码的交易合计为负。加码条件本身即强过滤器。**若不能接受"约一半加码单亏损"，应设 `add_max_lots: 1` 关闭加码。**

### 6.6 风控层

- 单笔风险封顶（1R=单笔愿亏）；保证金上限；月度熔断（亏损达阈值停新开）。
- 预热：加载后前 `min_bars=160` 根信号不可用（ATR/EMA 未收敛）。

**必守**：只做顺势一侧；全体入场过 ADX≥15；回踩支路过斐波汇流；两条支路都保留；收盘判定、不引入盘中成交假设；移动止损永不回撤；不设固定止盈。

**禁止（已证实有害或无益，不要再试，也不再展开论证）**：
加码至 3 手 · 保本地板（均价/首价） · 盘中挂单保本 · 三K动能止损 · 结构止损（枢轴） · 方向成熟度过滤 · 时间衰减出场 · 分批/固定止盈 · 突破幅度门槛 · 关键点跟随 · 时间回撤过滤 · 盘中触碰止损 · 收强条件 · 只做单支路 · 实体突破判定 · 外包/内包K线过滤 · 浅/深回调过滤 · 品种级参数优化 · 凯利动态仓位 · 组合级复利手数 · regime 参数切换 · 空仓机制 · 季节性因子 · 跨品种价差 · 跨周期配置 · 换月跳空的**策略层**守卫（改数据/执行面处理）。

> **元结论（决定优化方向）**：在 50 品种 / 9 年 / 3,226 笔样本上，**净值 91% 由 Top5 笔贡献，参数微调的 ±50 万波动全在噪声内**——**靠"加过滤器"已无法取得可信的边际改进**。优化只能走三条路：**修漏洞（数据/执行面）· 扩样本（品种池/min15）· 执行面（滑点/换月/资金规模）**。

### 6.9 方法学铁律（评估任何新条款前必读）

| # | 铁律 |
|---|---|
| 1 | **配对归因 > 重跑链路**：评估"入场过滤器"必须在**同一批已成交交易**上按标志分桶看贡献（重跑会被容量门控的时序重排污染）。 |
| 2 | **判据三件套（缺一不可）**：① 参数曲线单调/成平台（非单点最优）② 跨体系同向（≥3 个体系同号）③ 品种分半同号。 |
| 3 | **框架保真度审计**：证伪任何经典框架（利弗莫尔/斐波那契）前，先审计自己的机械化是否忠实于原始定义。 |
| 4 | **成交假设决定结论**：同一规则换"收盘成交 / 挂单成交 / 盘中挂单"可让结果正负翻转。 |
| 5 | **变手数记账**：`R` 必须是"每手 R"，手数由 `lots` 单独承载；多手变体一律以净¥与 DD 为准（PF 不可比）。 |
| 6 | **参数"不敏感"才是好事**：三档相差 ±5 万 ⇒ 不是调参调出来的；只有单点好、相邻崩 = 噪声。 |
| 7 | **适用边界**：入场过滤 → **只能**配对归因；出场类 → 两法皆可；**仓位/手数类 → 必须真重跑**（改变路径）。 |
| 8 | **多重检验诚实声明**：任何新结论必须报出**累计检验次数与校正后显著性**，回测输出默认带统计加固包（§8.7）。 |

## 7. 信号推送层

> 源：`app/scheduler.py`（`_fusion_scan_job` / `_collect_hourly_settled`）+ `app/notify/pushplus.py` + `app/api/routers/fusion.py`。

### 7.1 扫描调度

- 融合策略扫描**每 15 分钟**一次（与每日三次 ingest 并行），由 APScheduler `minute="*/15"` 触发。
- 每轮：① 拉最新小时线（逐根增量 / 尾部 800 根兜底 + 定稿守卫）；② `evaluate_all` 评估全部品种；③ 状态机去重（仅状态变化时推送）；④ 渲染并发送。

### 7.2 状态机去重

- 持久化 `FusionPosition`（symbol, position, entry_price, entry_at, last_stop, last_be_done, signal_at, pushed_at, **lots**）。
  `lots` = 当前手数；手数较上一轮增加即视为「加码事件」，独立推送。
- 冷启动（表空）：以引擎当前状态无条件建基线，再推送上线通知。
- 数据新鲜度：最新 K 距现在 > `stale_minutes=90` 分钟 → 抑制状态变化信号（防过期数据触发）。

### 7.3 推送形态（三段式）

1. 🚨 **新信号**：开/平/反手即时推，附 ⛔止损位 / 🎯保本位（价位按 `_TICKS` 最小变动对齐，如 FG=1、AU=0.02、SC=0.1）。
   持仓行在加码后显示 `×2手`；加码事件单列 `➕ … 加码 至 2手 ｜ 均价 … ｜ ⛔止损 …`。
2. ⚠️ **止损变动**：吊灯止损朝有利方向移动 ≥ `trail_push_atr=0.5×ATR` 补推；首次触发保本补推。
3. 📊 **持仓简报**：盘前（`pre_session_times` 08:45/13:15/20:45）强制推完整清单；交易时段内每 `heartbeat_interval_min=30` 一档（对齐 :00/:30）。
4. ⏳ **待执行复提**：开仓信号在 `signal_repeat_min=120` 分钟内每轮置顶，防漏看。

### 7.4 通道（旁路，失败不阻塞主流程）

- 主通道 **pushplus**（微信）：`POST https://www.pushplus.plus/send`，`template=markdown`，失败自动重试 1 次。

- 留痕：`FusionPushLog`（pushed_at/kind/title/content/n_signals/n_rows/delivered/via），可回查历史信号。

### 7.5 推送窗口 / 日历

- `push_windows`：08:45-12:00 / 13:15-15:30 / 20:45-23:30；窗口外整轮冻结。

## 8. 回测与研究模块

> 源：`桌面/融合/终版资料/04_一百二十万回测方法维度步骤` + `runtime/_bt_fusion.py` / `_bt_multi.py` / `_bt_fusion_timeweight.py`。本模块把"手动调参回测 + 鲁棒性测试 + walk-forward"做成系统内功能（CB 编码、WB 复审）。

### 8.1 定位

- 用户可在 UI/API **手动调整策略与组合参数**，即时跑回测，对比不同参数下的净¥/PF/回撤/胜率。
- 内置 **鲁棒性测试**（四维矩阵 × 多 seed）与 **walk-forward 测试**（滚动窗口重估），验证策略稳健性。

### 8.2 两层回测架构（与 `fusion_state_detail` 单一真源）

- **信号层（逐品种前向循环）**：逻辑与 `fusion_signal.fusion_state_detail` **逐位一致**（EMA140 方向 → ADX(14)≥15 门控 → MA20 回踩（含斐波汇流）/10 根突破 → 2×ATR 止损/吊灯/0.5R 保本 → 阶梯加码 → close-only）。输出每笔 `(entry_i, entry_px, entry_atr, dir, exit_i, exit_px, R, lots, first_px)`。
- **组合层（时间轴 FIFO 重放）**：把所有品种成交事件按 `entry_dt/exit_dt` 排序重放；闸门 `max_positions`（默认 5）；各品种手数 `lots ∈ {1, 2}`；净金额 `Y = R×lots×entry_atr×multiplier − 往返成本(bp)`（`R` 为**每手 R**）。
- **铁律**：引擎 `fusion_signal` 与回测 `bt_symbol` 必须同步改，改策略后两处都改并跑回测确认口径未分叉。

### 8.3 四维测试矩阵（鲁棒性）

| 维度 | 取值 |
|---|---|
| ① 数据源 `src` | tqsdk / akshare / csv |
| ② 容量 `max_pos` | 1 / 2 / 3 / 5 仓 |
| ③ 成本 `cost_bp` | 5 / 10 / 20 / 30 / 50 bp |
| ④ 时段权重 | 不加权(p=1) / 加权(tqsdk 分时段期望) |

交叉组合最多 120 组，UI 可勾选批量跑。

### 8.4 可调参数面板

| 类别 | 参数 |
|---|---|
| 策略 | `sl_atr` / `trail_atr` / `be_r` / `entry_mode` / `W` / `ema_k` / `atr_n` / `ma_n` / `cooldown_bars` / `adx_min` / `fib_confl` / `fib_tol_atr` / `add_thr_atr` / `add_max_lots` |
| 组合 | `max_positions` / `lots` / `cost_bp` / `seeds` |
| 数据 | `src` / `freq` / `kind` / `symbols` / `min_year` / `limit` |
| 加权 | `N_MIN` / 概率映射 |

### 8.5 walk-forward 设计

- **信号层**：按时间切滚动窗口（训练/评估不泄漏），定期用滚动窗口重估参数（与 §4.3.4 对齐）。
- **组合层**：滚动 FIFO 重放，输出分年度/分时段净值曲线。
- 机制性消除前视：评估点 `step` 抽样、参数估计只用 `as_of` 之前数据。
- **OOS 判据**：报告 OOS 衰减比（OOS 净利 / IS 净利）；衰减比 ≥50% 维持 V3.4 定稿，深度衰减回退 P0（`fib_confl:true + add_max_lots:1`）。

### 8.6 鲁棒性测试

- 多 `seed`（`seeds=30~60`）取均值±标准差，检验随机性敏感。
- 分年度 / 分品种拆解；成本盈亏平衡点扫描。
- 品种池清单 + 各品种上市时间 + **幸存者偏差审计**结论（已退市品种处理方式）。

### 8.7 指标与输出

- 均 R、净 R、净 ¥、盈利因子 PF、胜率、最大回撤（R 与 ¥ 双口径）、覆盖率-准确率曲线。
- **统计加固包（默认输出）**：品种层 Bootstrap 95%CI 与 p(≤0)、置换检验 p 值、**多重检验声明**（累计检验次数 + Bonferroni/FDR 或 expected-max 校正）、CVaR(5%)、最长回撤时长。
- **基准对照行**：每份报告必含 **买入持有(B&H)** 与 **MA 交叉** 两条基准行（同成本口径、同品种池）。
- **容量梯度**：`max_pos ∈ {3, 5, 7, 10}` 一键扫描。
- **成本韧性**：成本 ×1.5 / ×2 对照 + 波动率依赖滑点模型。
- **VWAP 对照**：收盘成交 vs VWAP 成交双口径。
- 每次回测 JSON 落 `bt_out/`，命名带 `tag`；**必须标注口径**：所用 `(freq,kind,src)`、品种窗口、成本——不同口径结论可差 5~30 倍。

### 8.8 API / 前端

- `POST /backtest/run`：提交参数（8.4 面板），返回 `task_id`。
- `GET /backtest/result/{id}`：结果（汇总 + 分品种 + 分年度 + 曲线）。
- `GET /backtest/matrix`：四维矩阵对比表。
- 前端「回测调参」页：参数表单 + 运行 + 结果对比表/图。

## 1. 背景与问题

A/B/C 三组因子已跑完 IC 扫描。**A 组（日内价量）与 C 组（产业链比价）的数据全在库内、无需新数据**，
但 **B 组横截面基本面是整个因子体系里 IC 最高的部分**，其数据覆盖却严重残缺：

| 表 | 当前覆盖 | 缺口 |
|---|---|---|
| `spot_basis` | **仅 8 个报告日** | 几乎全空 → 基差类因子无法评估 |
| `inventory` | 仅 2026-05 ~ 09（3 个月） | 长历史缺失 → `inv_chg` 样本量不足被判剔除 |
| `member_position_rank` | 仅 **2023-01 起** | B 组 `net_pos_top20`（IC 0.0218/t=3.9）2023 前无数据 |
| `warehouse_receipt` | **表不存在** | 仓单维度完全空白 |

**结论：补齐数据的优先级高于开发新因子。** 本 PRD 只解决「数据采得到、存得对、不污染因子」，
因子验证属第 5 阶段，不在本次范围内。

---

## 2. 目标 / 非目标

**目标（本次交付）**
1. 建立 4 张基本面表的采集能力，并把 3 张残缺表的历史补齐到 **2015 年起**。
2. 所有基本面数据带发布时点语义（T 日发布 → 只能用于 T+1 决策），代码层面可强制，不靠自觉。
3. 采集脚本幂等、可重跑、失败可重试、不产生重复行。
4. 落地后能直接响应 `SELECT COUNT(DISTINCT trade_date)` 这类覆盖度自检。

**非目标（本次不做）**
- 不做任何因子计算、不做 IC 扫描、不碰策略逻辑。
- 不做网页爬虫（本 PRD 全部走 akshare 1.18.94，见 §7）。
- 不改动现有 `daily_bar` / `hourly_bar` 的采集链路。

### 4.3 展期收益率 → **新增表 `roll_yield`**


- 字段建议：`report_date, symbol, near_contract, far_contract, near_price,

## 6. 技术约束与红线（**违反即退回**）

### 6.1 `_lag` 语义：T 日发布的数据只能用于 T+1

**这是本次最容易埋雷的地方。** 三个源的发布时点都晚于日内决策时点 14:45：

| 源 | 发布时点 | 是否晚于 14:45 决策 |
|---|---|---|
| `member_position_rank` | **T+1 约 16:30** | 是 |
| `warehouse_receipt` | 日盘收盘后 | 是 |
| `spot_basis`（100ppi 现货价） | 盘后 | 是 |

**要求**：
- 采集脚本可写入 `publish_date` 或 `asof_date` 列（表示数据实际可得日，`= report_date + 1`）；
- 因子取数必须显式 `WHERE asof_date > 决策日`，**禁止靠 memory/注释约定**；
- 若因兼容现有表结构无法加列，则必须提供**一个带 `_lag` 的 SQL 视图**，视图名 `v_*_lagged`，并在文档标注。

### 6.2 幂等与去重

- 全部走 upsert，主键冲突时更新，不要先 `DELETE` 再 `INSERT`（避免覆盖度自检中途读到空表）。
- 现有表统一带 `src` / `version` / `created_at` 三列，新表必须同样具备。

### 6.3 合约代码统一

- 落库 `symbol` 一律用 `XXXX888`（主力连续）口径，如 `RB888`、`I888`。
- ⚠️ 已知陷阱：`'AU8888'.endswith('888')` 返回 **True**。
  判主力连续必须写成 `s.endswith("888") and not s.endswith("8888")`。
  参考 `scripts/factor_ic_scan.py::_is_main()`。

### 6.4 采集节奏与错误容忍

- akshare 走 HTTP，交易所接口高频调用会被限流。建议：单线程（或 `--concurrency ≤ 3`）、相邻请求间隔 ≥ 0.5s、带重试。
- **单个品种/日期失败不得中断全局**，收集失败清单，最后统一打印；脚本退出码体现失败数。

### 6.5 环境

- 脚本互调的模块导入要求 cwd = 脚本所在目录：`cd /e/Docker/qhyc/scripts && python collect_xxx.py`。
- 云端无源码 bind mount，改完代码 push 后服务器**必须**执行
  `docker compose -f docker-compose.cloud.yml build && up -d`。

## 1. 背景：为什么需要这一层

数据层把基本面存进库，只完成了一半。要让因子「参与融合策略决策、形成买卖信号」，还需要四样东西：

1. 因子的**统一产出契约**——否则每个因子各写各的，接入时无法统一调度；
2. 因子的**元数据注册**——否则三个月后没人知道哪个因子还在用、依赖哪张表、能不能关；
3. 统一的**时间对齐（`available_at`）**——这是前视最集中的地方，必须集中实现，禁止各写各的；
4. **接入点**——因子如何作用于 V3.4，而不是另起一套信号。

**本 PRD 只定义「因子层」与「接入接口」，不重写 V3.4 的核心逻辑，不替换现有信号链路。**

---

## 2. 目标 / 非目标

**目标**
1. 因子按统一契约产出，元数据可注册、可查询、可开关。
2. 时间对齐集中实现，任何因子**无法绕过** `available_at` 检查。
3. 因子以「偏置乘子」方式接入 V3.4，提供两个明确插入点，且可一键关闭。
4. 因子上线有**硬性准入门槛**（ablation + 相关性 + 成本），不靠主观判断。

**非目标**
- 不重写融合策略 V3.4 的入场/离场/门控逻辑。
- 不做回测引擎改造。
- 不开发新的策略类型。

---

## 3. 核心概念：`available_at`（全文档唯一时间语义）

**每个因子值必须带一个 `available_at`（可用时点），表示"这个数从这一刻起才真实可得"。**

| 数据 | `trade_date` | 实际发布时点 | `available_at` |
|---|---|---|---|
| 会员持仓排名 | D−2 | D−1 晚 16:30 | **D−1** |
| 现货基差 | D−1 | D 日盘后 | **D** |
| 仓单 | D−1 | D 日盘后 | **D** |
| `bar_15m` 日内因子 | D | D 日内 14:45 已算出 | **D（当日 0:00 等价）** |

**唯一判定规则：**

> 决策时刻 T 可以使用任何满足 `available_at <= T` 的因子值。

推论（容易搞错，务必按此实现）：
- 日内决策 T = 当日 14:45 → **可以用基本面，但最多用到 D−2 的基本面**。
  基本面不是"进不了日内"，而是"进日内必然滞后 1~2 天"，日内高频无 alpha，方向偏置仍有参考价值。
- 日线决策 T = 次日开盘 → 可用 `available_at <= 次日` 的全部数据。

## 4. 因子注册与存储

### 4.1 `factor_registry`（元数据）

```sql
CREATE TABLE IF NOT EXISTS factor_registry (
    factor_id            TEXT PRIMARY KEY,
    name                 TEXT NOT NULL UNIQUE,
    category             TEXT NOT NULL,       -- price_volume | fundamental | cross_section | pairs
    description          TEXT,
    data_sources         TEXT[]               NOT NULL,   -- 依赖表，用于断供排查
    min_history_days     INTEGER  NOT NULL DEFAULT 60,
    horizon              TEXT     NOT NULL,   -- intraday | daily
    lag_days             INTEGER  NOT NULL DEFAULT 0,     -- available_at = trade_date + lag_days
    enabled              BOOLEAN  NOT NULL DEFAULT true,  -- 一键关闭
    default_weight       NUMERIC  NOT NULL DEFAULT 0,     -- 偏置乘子默认权重，0 = 不启用
    max_weight           NUMERIC  NOT NULL DEFAULT 0.3,   -- 硬上限，防单因子过度暴露
    version              TEXT     NOT NULL DEFAULT '1.0',
    created_at           TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

> `max_weight` 默认 **0.3**，与 C 组比价因子的实测结论一致（自相关 0.9+ 的水平非平稳序列，
> 满仓权重 = 长期单边暴露，历史回测好看但实盘会爆）。

### 4.2 `factor_value`（因子值长表）

```sql
CREATE TABLE IF NOT EXISTS factor_value (
    factor_id    TEXT      NOT NULL,
    trade_date   DATE      NOT NULL,
    symbol       TEXT      NOT NULL,
    raw_value    NUMERIC,
    z_value      NUMERIC,          -- 横截面标准化后的值，接入层只消费这一列
    available_at DATE      NOT NULL,   -- 由 lag_days 推导，接入层只读此列
    version      TEXT      NOT NULL DEFAULT '1.0',
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (factor_id, trade_date, symbol)
);
CREATE INDEX IF NOT EXISTS idx_fv_factor_date ON factor_value (factor_id, available_at);
```

- 主键天然幂等，采集/重算可反复 upsert。
- **接入层禁止直接读源表，只读 `factor_value.z_value`。**

## 5. 因子产出契约

### 5.1 统一函数签名

```python
def compute(ctx: FactorContext) -> pd.Series:
    """返回以 (trade_date, symbol) 为索引的因子原始值。
     ctx.asof      : 决策时刻（datetime）
     ctx.symbols   : 参与截面的品种列表
     ctx.lookup(available_at_max: date, tables: list[str]) -> DataFrame
     —— 所有取数必须走 ctx.lookup 并带 available_at 过滤，禁止直接连表。"""
```

**红线**：因子函数内**禁止**出现 `ORDER BY` 之外的直接 SQL，禁止自行做时间过滤。
取数一律经 `ctx.lookup`，该函数强制附加 `available_at <= ctx.asof` 条件。

## 6. 接入 V3.4：偏置乘子（唯一允许的方式）

### 6.1 两个插入点（不改 V3.4 内部结构）

```python
# 1) 仓位上限乘子
position_cap_scalar = 1.0 + bias.clip(-max_weight, max_weight) * K_POS
   # 例：bias=+1 → 顺势一侧仓位上限 ×1.3

# 2) 入场闸门（仅对逆势一侧生效）
entry_gate = bias.clip(-max_weight, max_weight) < -GATE_THRESHOLD
   # 例：bias 强烈反向时，禁止在逆势一侧新开仓
```

- `K_POS`、`GATE_THRESHOLD` 走配置，默认 `K_POS = 1.0`、`GATE_THRESHOLD = 0.5`。
- **禁止**因子直接调用开平仓 API。因子的职责是"调整暴露"，不是"触发交易"。

### 6.2 配置（权重必须在配置里，不能写代码里）

```yaml
factor_bias:
  enabled: true
  k_pos: 1.0
  gate_threshold: 0.5
  weights:
    cs_mom_20d:    0.20
    up_vol_ratio:  0.15
    net_pos_top20: 0.15
    hc_rb_bias:    0.10
    j_jm_bias:     0.10
```

**硬约束**：任一因子 `weight > max_weight`（默认 0.3）时，加载直接报错拒绝启动。

### 6.3 否决项

以下方式**一律不做**，理由已实测支持：
- 因子独立产生买卖信号 → 两套信号互相打架，V3.4 的验证失效；
- 把因子权重并入 V3.4 打分后重调参数 → 三次实测教训都是"改参数就亏"；
- C 组比价做满仓配对交易 → 扣 5bp 全死，且自相关 0.9+ 带来长期单边暴露。

```python
def asof_join(factor_values: pd.DataFrame,
              decisions: pd.DataFrame,
```

## 0. 背景与目标

### 0.1 来源
《量化系列借鉴分析.md》从 5 篇 A 股/统计套利视角的量化科普中，识别出对我们系统有增量价值的工程纪律项（量价维度、前视校验、过拟合五关、数据自检、组合熔断、波动率分位）。本文档把其中**判定为"可以落地"的项**转化为可执行的验证方法与实施规格。

### 0.2 目标
- 为每一项设计**严格、可复现**的验证方法（指明数据、脚本、检验顺序、判定标准）。
- 验证通过的项，固化进系统或写入冻结文档，作为下一步完善内容。
- 验证不通过/预期负的项，明确记录拒绝理由，避免投入。

### 0.3 验证纪律（强制，来自 futures-backtest-merge）
任何"加过滤器/改规则"类改动，发布前**必须**走以下流程，缺一项不得定级：
1. **净值集中度体检**：先算 `Top5 / Top20` 笔交易净贡献占比。若 `Top5 > 50%`，直接判定"该样本不支持过滤器类优化"，后续结论均为噪声。
2. **过滤器改动的唯一可信检验 = 配对归因**：固定同一批已成交交易，按"是否满足新条件"分桶看各桶实际净贡献；**严禁**跑两条完整链路比净利（容量门控重排会污染差值）。
3. **六项走前检验**：时间分半 / 逐自然年 / 锚定式走前 OOS / 参数平台 / 成本敏感性 / 随机入场蒙特卡洛 + 自助 CI。
4. **两道硬闸门**：① 价格取负对称性自检逐笔一致；② 随机入场对照通过。
5. **正交性判据**：状态/信号过滤类与入场多半不正交（预期误杀优势单）；离场/风控类与入场正交（可移植性高）。

## 2. 验证方法设计（核心）

### V1｜量价维度（P0，最重要且最需方法纪律）

**数据前提（已确认满足）**：`build_continuous.py` 产出列 `[date,open,high,low,close,volume,oi]`，`fetch_quotes.py` 读取含 `volume`。故量能特征可直接构造，无需新增数据源。

**量能特征定义（来自 lh5，需期货化重测）**：
- 量比 `VR = vol_t / median(vol, 20日)`：>1.5 显著放量，<0.5 显著缩量。
- 量标准分 `VZ = (vol_t − μ)/(σ)`，滚动 40 日：>2 极端放量。
- 量价背离：价格创新高/新低而 `VZ` 未同步，连续 ≥2 根。

**⚠️ 关键约束（来自 backtest-merge §六-7/8、§七）**：
- 量价过滤属**信号/状态过滤类**，与 Qi Analisy 入场**不正交**。方法论实证：ADX 门、阶段门一致降低收益与盈利品种数（误杀优势单）。因此**不得直接套 naive A/B 净利对比**。
- 正确路径：**先集中度体检，再配对归因，并分两条子路径验证**。

**实验设计**
1. **集中度体检**：对 48 品种基线成交算 `Top5/Top20` 占比。若 `Top5 > 50%`，本项结论上限为"样本不支持过滤器优化"，仅可验证路径 B。
2. **路径 A（入场门禁）**：将"放量确认"作为开仓前置条件 → 用**配对归因**：固定基线同一批已成交交易，分桶为"满足放量确认 / 不满足"，看两桶净贡献。判定：
   - 若"不满足桶"本身为净亏损且其剔除使剩余桶夏普/净利提升 → 门禁有效，采纳；
   - 若"不满足桶"中性或正向（即被门禁砍掉的是优势单）→ **拒绝**，记录"与入场不正交，误杀优势单"。
3. **路径 B（离场/风控预警）**：持仓中监测量价背离 → 触发减仓/提前止盈。离场类与入场**正交**，可移植性高（方法论实证离场类叠加使全 73 品种日线 +24.8%→+62.8%）。用**配对归因**看"背离发生后 N 根内"的后续亏损是否被有效截断。判定：截断后回撤下降且趋势收益不显著牺牲 → 采纳。
4. **判定标准（配对归因三重判据，缺一不可）**：① 参数曲线成平台（非孤立尖峰，最优 ≈ 1.4σ 即噪声）；② 跨体系同向（换基准体系仍有效）；③ 横截面分半（品种奇/偶两半同向）。
5. **引擎内落地设计（D5）**：将 `donchian_main_filter.py` 的过滤器框架语义（`pass_filter` 接口、`grid_search`、`walk_forward`、集中度体检 + 配对归因报告）**移植进 `fusion_signal.py`**，作为引擎原生状态/风控态，而非独立 `volume_filter.py`：
   - 在引擎数据路径直接读取 DolphinDB 的 `volume`/`oi` 列，构造 `VR`/`VZ`/量价背离特征；
   - `walk_fusion_states` 新增量价状态位 `mode ∈ {none, vol_confirm, vol_divergence}`，与现有 ADX/斐波那契·汇流状态并列；
   - 验证报告（集中度体检表 + 配对归因桶表）作为引擎回放产物输出，而非独立链路净利对比；
   - Qi Analisy skill 同步镜像该状态位，保持单一真源 `diff` 一致。

**预期与风险**：路径 A 大概率负（不正交），路径 B 是真正增量。用户决策（D5）：**所有借鉴项统一融入 Docker `qhyc` 预测系统，不作宿主独立拆分**。故量价无论路径 A/B 结果如何，最终均落地于引擎内——路径 B 直接作为 `fusion_signal.py` 风控/预警态；若路径 A 被拒（误杀优势单），其降级形态为**融入引擎风控层（Docker 内）的背离预警**，而非外部独立简报指标。两者均须走 single-source 双源同步（§7）。

### V2｜前视偏差加固（P0，低成本高价值）

**现状**：`futures-backtest-merge` 已将 htf `available_at` 对齐作为头号杀手（实测虚增 100~160 个百分点）。本次新增两个工程断言。

**实验/落地设计**
1. **前项填充断言**（lh4）：回测数据准备阶段增加检查——任何特征计算后，确认无后项泄漏（lh4:331 "回测只用前项填充，后项填充是作弊"）。构造含后项填充的反例数据，断言必须拦截。
2. **期货数据时点对齐**（lh4 财报未来函数 + 期货特有）：持仓排名、仓单、基差为**盘后发布**，禁止用于当日盘中信号；现货基差用于日线信号需对齐"发布日 T+1 可用"。在信号计算入口加"数据可用时点 ≤ 信号时点"断言。
3. **验证方法**：代码审查 + 反例对照测试（注入"偷看未来"的数据，确认断言拦截并报告）。不依赖回测跑批，属工程加固。

**判定**：断言齐全且反例全拦截 → 采纳固化。代码改动遵循"开关 + 默认值等于旧行为 + 双向等价性验证"（backtest-merge §）。

### V3｜过拟合"五关"固化（P1，已有超集）

**现状**：我们已有六项走前检验 + 定级标准（稳健/中等/不稳健），是 lh2"五关"的超集。差距在**未显式固化为流水线闸门**。

**落地设计**
1. 把定级标准固化为引擎发布校验（Docker 内，非独立回测链路）的"发布前闸门"：分半双正 + 逐年≥60% + 走前 OOS 正 + 参数宽平台 + 成本余量足 + 双重显著。
2. **重点补齐"参数稳健性"自检**：对应亲历教训——开关型参数（如 `keyline_excl`）依赖的惰性分支未纳入触发 → 变体静默退化成基线、执行笔数完全相同却看似生效。闸门规则：**变体 vs 基线执行笔数相同 → 直接判"参数未生效"，阻断发布**。
3. **验证**：用已知"静默退化"案例（`keyline_excl` 事件）回填，确认闸门能拦截并告警。

**落地设计**

### V5｜组合级回撤熔断（P1，需新模块）

**现状**：Qi Analisy 有严格单笔纪律（仓位≤2%、截盈放亏、阶梯加码），但**无组合层最大回撤熔断**（lh2 的"组合回撤 >15% 减仓 / >25% 清仓"我们尚未有）。

**落地设计**
1. 新增组合权益监控模块：跟踪组合净值峰值，回撤 `>15%` 自动降总仓位至半仓；`>25%` 清仓观望。（阈值按用户评审结论初设，对齐 lh2 实证；后期可调，调整须经历史净值回放反推，见 §6 决策记录）
2. 与 `trade-philosophy-mapping` 盈亏归因闭环联动：熔断触发记录到理念映射，复盘是否"死扛"类亏损。
3. **验证**：用基线历史净值回放，确认熔断触发点与降仓逻辑正确，且不劣化 9/9 年全正属性。

### V6｜波动率分位数状态位（P1）

**现状**：Qi Analisy 已用 ATR 做汇流与止损，但未用**波动率分位数状态**（lh5：90% 分位以上物极必反、10% 分位以下最危险；lh4：历史波动率只能量长度不能量面积）。

**落地设计**
1. 在 ATR 体系加状态位：`ATR_perc = percentile(ATR_roll, 250日)`，>90% → 降仓/观望（防急转），<10% → 警戒（防暴风雨前）；EWMA 加权更灵敏（lh5:71）。
2. 属离场/风控类，与入场正交，预期可移植（同 V1 路径 B 逻辑）。
3. **验证**：配对归因——固定基线成交，分桶"高波动分位居仓 vs 低波动分位居仓"，看降仓是否降低回撤而不牺牲趋势收益。过三重判据采纳。（按 D5 一律融入 `fusion_signal.py` 引擎 ATR 体系，不另立宿主模块。）

## 4. 验收标准（"可以落地"的定义）

一项被判定"可以落地"并固化，须同时满足：
1. 通过 §0.3 的净值集中度体检（或明确记录"样本不支持过滤器优化"的上限结论）；
2. 过滤器/改动通过**配对归因三重判据**（参数平台 / 跨体系同向 / 横截面分半）；
3. 通过六项走前检验（分半双正、逐年≥60%、走前 OOS 正、参数宽平台、成本余量足、双重显著）；
4. 通过两道硬闸门（价格取负对称、随机入场对照）；
5. 代码改动遵循"开关 + 默认值等于旧行为 + 双向等价性验证"；
6. 结论写入冻结文档（参考 backtest-merge §六-10 五层结构 + 十项逻辑一致性审计）。

任一不过 → 记录拒绝理由，不固化。

## 5. 风险提示

- **所有 A 股结论在期货上须重测**：lh5 的"胜率 +8pct、回撤减半"是 A 股回测，期货仅机制同构，幅度未知。
- **过滤器类改动极易被污染**：严禁用 naive A/B 链路净利对比下结论（backtest-merge §六-8 实测同一效应在不同体系 +45万/+13万/−20.9万，方向都反）。必须配对归因。
- **量价过滤作为入场门禁预期可能负**（与入场不正交），应优先验证路径 B（离场预警）；若路径 A 负，属预期内，不视为方法失败。
- **换周期/加指标非单变量实验**：任何改动须锁定"同品种 + 同窗口 + 同成本"对照。

### 7.2 统一部署原则（D5）
用户决策（2026-09-28 14:15）：V1–V6 **全部作为 `qhyc` 预测系统的一部分在 Docker 内实现，不作宿主独立拆分、不另立独立回测/简报模块**。具体落点：

| 编号 | 原"宿主侧"方案 | D5 后落点（Docker 引擎内） |
|---|---|---|
| V1 量价 | 独立 `volume_filter.py` + 简报观察 | 直接进 `fusion_signal.py` 信号/风控层（路径 B 为引擎内背离预警态） |
| V2 前视 | 宿主回测脚本断言 | 引擎数据准备守卫，内置 qhyc 校验路径 |
| V3 五关 | 宿主回测流水线闸门 | 引擎发布校验内置（不独立存在） |
| V4 数据自检 | 宿主日更脚本函数 | 进 `qhyc-scheduler` 每日 17:30 流程 |
| V5 组合熔断 | 组合权益监控模块 | 进 `fusion_signal.py` 组合权益监控 |
| V6 波动率分位 | ATR 扩展 + 简报 | 进 `fusion_signal.py` 引擎 ATR 体系 |

**验证手段统一**：配对归因 / 六项走前检验 / 真源回放 → 复用引擎内置"真源回放"能力（Qi Analisy SKILL：50 品种 / 9 年真源回放、10 项锚点偏差全 0），**在 Docker 内对引擎跑回放 + 配对归因**，不依赖外部独立回测链路（呼应 backtest-merge"严禁 naive A/B 链路净利对比"）。

### 7.3 强制运维规则（来自 data-layer / brief-pipeline 避雷项）
- 改 `qhyc` 引擎/采集器代码 → **必须 `docker restart qhyc-api qhyc-scheduler`**（只读挂载不热重载，改了不重启则 17:30 调度仍写旧口径）。
- 策略逻辑改动 → **引擎 `fusion_signal.py` 与 Qi Analisy skill 两处同步改 + `diff` 校验一致**（单一真源铁律）。
- `qhyc-pipeline` 改脚本 → 重启该容器生效（只读挂载 + 启动快照）。
- 容器内无 `ps` → 查进程用 `/proc`；长任务用 `docker exec -d` 而非宿主机 `nohup &`（Windows 会话会清理）。
- PG 长回填压崩（Windows Docker WAL EINTR）→ V4 注入测试须多所串行，避免拖垮 TimescaleDB。

### 7.4 对 M0/M1/M2 的影响（已同步 §6.2）
- **M0**：验证环境直接锚定 Docker `qhyc` 引擎——用引擎真源回放跑基线集中度体检，确认 `volume`/`oi` 在引擎数据路径可用；不搭独立宿主骨架。
