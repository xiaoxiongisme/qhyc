V5X 策略系统：自我学习与进化设计

版本 2026-10-22 ｜ 基于现有三源对拍主干（step46 回测 == fusion_v5x_engine 生产 == 云端规格冻结表）

0. 设计原则（先定调）

这不是上深度学习，而是把我们已经手动做过的「扫描 → 对照 → 重锁 → 对拍」闭环自动化，并加上护栏。 当前系统的 edge 来自规则与参数，不在于"学出一个模型"。所以"进化" = ①在已知有效处（波动体制）做在线自适应；②周期性用样本外窗口重扫参数；③用硬护栏防止重扫把 bug 当 edge。任何"学到的东西"都必须先过 step46 == 引擎 逐笔偏差 0 这道关，否则不准落地。

组件角色进化时的用途

已验证的关键事实（来自本项目研究）：可预测性集中在"波动体制"维度——HMM(K=3) 三态波动体制（高/中/低波）在 holdout 的 log₂/bar 1.6–1.8，大幅优于六位 K 线形态链 2.2。这意味着"在线体制学习"是收益最高的进化方向，且风险远低于改 alpha。

2. 三层自进化

A在线体制学习（最低风险、最早做）

  • 把固定门控换成体制感知。当前 ADX≥15 是写死的阈值；改为在线估计每个品种当日所处的波动体制（高/中/低波三态，用已实现波动率 + 区间幅度 + ADX 分布做轻量 HMM/贝叶斯更新）。
  • 体制驱动两件事：①门控开关（高波态自动触发 P2 高波日禁开仓，低波态放宽）；②仓位缩放（高波态降仓、低波态加仓），不碰方向 alpha。
  • 为什么安全：它只调"风险预算分配"，不改入场逻辑；且体制变量是样本外真实有效的维度，不是新挖的因子。

B滚动重扫 + Governor 闸门（周期触发）

  • 调度：用自动化（recurring）每 1–3 个月触发一次，窗口 train = t-3y, holdout = t-1y, validate = t 的 walk-forward。
  • 流程：step73 网格 → step74 挑 reco → 候选参数喂给 Governor 闸门。
  • 闸门不通过 = 原样保留当前冻结参数 + 写告警日志。通过才写回三源。

C漂移监控（实时/准实时）

  • 滚动 20/60 日窗口，比较实盘净值/回撤/PF 与回测预期。指标：live MAR < 0.6×回测 MAR，或体制分布偏移 > 阈值。
  • 漂移触发即唤醒 B 层重扫（不必等周期）。

3. Governor 四道硬护栏（来自本项目的血泪教训）

护栏拦截过的历史事故实现
① self_check 逐笔 PASS空头吊灯误用 SL_ATR（bug 假象，旧 SL3/TR2 净利被人为抬高 30%+）、NaN-ATR 僵尸仓fusion_v5x_engine.self_check() 对比 trades46_V5X.csv，任一笔偏离 >0 即 FAIL
② OOS MAR↑ 且三分区同号样本内 IC/净利好看、样本外衰减；单点"优化"只是噪声holdout + validate 两段 MAR 同向上升，且不低于当前值
③ 无"全同结果"指纹价格序列全 NaN → 多个参数变体逐位相同（数据退化指纹）重扫前断言每品种价格非全 NaN；同一输入的多个变体不得逐位相同
④ 无前视因子用了决策时点后的 bar / 前瞻标签用未来价重扫数据契约锁定"决策时点可用字段"，CI 检查

护栏 ① 是主干中的主干。本次（2026-10-22）正是靠它揪出空头吊灯 bug：没有逐笔对拍，SL 调到 3.0 的"更好表现"会被误当成真实 edge 锁死。自进化系统必须把对拍做成不可绕过的关卡，而不是事后校验。

4. 版本治理与知识沉淀

  • 冻结参数表带版本号（V5X.1 → V5X.2 …），每次重锁在 fusion_v5x_spec.html 写勘误段，记录变更前后值与通过/未通过的护栏。
  • 策略变体登记册：分支/合并可追溯。新门控（如把 M5 幅度门换成方向过滤）须作为独立变体先跑 holdout，不得直接覆盖基线。
  • 教训库自动化：把项目记忆里的 19+ 条量化纪律转成 relock_checklist，重锁前逐项打勾，新事故追加新条目。

5. 绝不能做的事（风险边界）

  1. 不要让系统自动 overwrite 生产参数。Governor 默认 --dry-run，只产出"建议 + 护栏报告"，人工确认后才写三源。
  2. 不要在单一样本内做"无限重扫"。重扫必须 walk-forward，且护栏 ②③④ 缺一不可。
  3. 不要碰 alpha 的"自动搜索新因子"。新因子进入必须经过完整 OOS + 多网格 + 多品种交叉，禁止自进化系统自行引入未审计因子。
  4. 不要把在线体制学习误当成预测。它只分配风险预算、不预测方向，避免引入前视。

7. 开放问题（已定夺的部分）

  • 落地确认方式：已定——默认 dry-run 出报告；落地需 --apply --confirm 双层确认，且 4 关全过才写三源。绝不自动 overwrite 生产参数。
  • 体制标注数据来源：已定双轨——离线用 bar_60m_ba 标定分位阈值（v5x_regime.calibrate_to_csv），上线后用 OnlineRegime 轻量实时分类；体制注入引擎默认关闭（REGIME_P2_AUTO/REGIME_POS_SCALE=False），保证基线对拍不变。
  • 重扫窗口粒度：待定（1 月 vs 1 季）——由未来月度巡检的 drift 频率反推。

9. 迭代二已实现（2026-10-22 晚）：受控落地分支 apply_to_sources

迭代一仅做到 PROPOSED dry-run，源字面量改写留作人工 commit。本迭代把 v5x_governor.apply_to_sources() 补全为真实但受控的落地执行分支：

环节实现
备份落地前先备份四件产物：step46_prod_bt.py / fusion_v5x_engine.py / trades46_V5X.csv / results_step46.json（.bak_apply_{ts}_*）
精确改写对 step46 三行全局量 + 引擎 6 个 V5XConfig 字段做 re.sub 数值替换，仅改数值字面、保留注释尾；每条规则必须命中恰好 1 次，否则视为结构漂移 → 中止回滚
无变化不落盘用 newline='' 保留原始换行符；文本未变则跳过写盘，避免污染 git diff
回测再生改写后重跑 step46 V5X 再生 trades46_V5X.csv / results_step46.json（与引擎新参数一致）
终极护栏再跑引擎 self_check()：逐笔对拍必须 PASS，否则全量回滚备份并抛错——保证三源恒对齐
非重锁短路候选 == 当前冻结值时直接 ALREADY-CURRENT，不写规格勘误、不 bump 版本、不污染变更日志

验证：① 候选=当前（no-op）跑 apply_to_sources → 9 条替换各命中 1 次、两源文件字节零漂移、self_check PASS、备份清理；② 全链 --apply --confirm + 候选=当前 → 命中 ALREADY-CURRENT 短路，规格/版本未被污染（变更日志仍停 V5X.1）。

本设计直接复用了本项目已验证的工程主干（三源逐笔对拍）与 19+ 条量化纪律。核心命题：让系统"学"，但永远不让它绕开对拍这道关。
